B-04-W 레코드를 QA할 때 아래 3종은 **매 배치 전건 실측**한다. 2026-09-02 테스트 배치 11건에서 전부 재발했다.

**① `008` 말미 공백 2칸(38-39) 유실 — 11/11건 재발**
- 증상: 워커가 40자로 만들어도 텍스트 파일에 기록되면 38자가 된다.
- 검증: 손으로 옮긴 문자열이 아니라 **파일에 기록된 줄**을 재야 한다.
  `awk '/^008/{print length(substr($0,8))}' <파일>` → 40이어야 한다.
- 근본 해결: `#` 공백 치환 + 파일 머리 범례(FN-04). 2026-09-02 산출물에는 치환이 적용되지 않았다.

**② `260 $a` 발행지 추정 기재 — 4/11건**
- 증상: 워커가 메모에 "발행지 저신뢰 추정"이라 적고도 `$a서울`을 그대로 쓴다. 실제로 틀린 경우가 있었다
  (다산북스·북21은 모두 **파주**인데 서울로 기재). 이때 `008/15-17`도 함께 틀린다.
- 검증: 발행처 소재지를 웹검색으로 확인한다. 파주출판단지 입주 출판사(창비·열린책들·다산북스·북이십일/아울북)를
  서울로 적었는지 특히 본다. 미확인이면 `[발행지불명]` + `needs_info`가 정답이고, 추정 기재는 QA 실패다.

**③ `300 $c` 크기 임의값 — 1/11건**
- 검증: `book_catalog.book_size`(예: `128*188`)의 **세로 mm를 올림해 cm**로 환산해 대조한다.
  128*188 → 19 cm. 21 cm로 적혀 있으면 실패.

**Why:** 세 항목 모두 개별 레코드만 보면 그럴듯해서 눈으로는 통과한다. 배치 전건을 기계적으로 실측해야만 잡힌다.

**How to apply:** QA 시작 시 위 세 쿼리/스크립트를 먼저 돌려 실패 목록을 만든 뒤 나머지 체크리스트로 들어간다.
