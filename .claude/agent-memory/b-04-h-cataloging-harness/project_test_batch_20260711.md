2026-07-11, 사서가 가상 테스트 도서 2건(TEST-B04H-피자를 좋아하는 로봇 이야기 / TEST-B04H-현대 조직관리론 입문)으로 B-04-H 전체 파이프라인(FN-02 B-04-W 순차 호출 → FN-03 QA → FN-03.5 DB 반영)을 처음 실행. FN-04(배치 출력파일)는 이번엔 생략 요청받음.

**결과:** 2건 모두 1차 QA 통과, 재작업 0건. DB 반영 성공(EM0197351/EM0197352, ctrl_no 7281716/7281717, call_no "813.8 김19ㅍ" / "325.1 박45ㅎ", room 어린이실(신간도서)/종합실(신간도서), 둘 다 정리중).

**중요 — 테스트 행은 검증 후 삭제됨(2026-07-11):** 위 두 레코드는 main 세션이 실제 INSERT 여부를 SQL로 직접 재확인한 뒤 `delete from public.books where title like 'TEST-B04H-%'`로 삭제했다. `EM0197351`/`EM0197352`와 `ctrl_no 7281716`/`7281717`은 **더 이상 DB에 존재하지 않으며 다시 사용 가능한 번호**다 — 다음 실제 배치의 FN-03.5 채번 시 `public.books`에서 현재 MAX(reg_no)/MAX(ctrl_no)를 다시 조회하면 자동으로 이 번호부터 이어진다(하드코딩된 "다음 번호"로 이 값들을 가정하지 말 것).

**발견된 이슈 — B-04-W 세션 간 제목 처리 불일치:**
같은 "TEST-B04H-" 접두가 붙은 제목을 두 번 순차로 B-04-W에 전달했는데, 1번째 호출은 접두를 그대로 245에 남겼고 2번째 호출은 접두를 "하네스 추적용 식별자"로 판단해 스스로 제거하고 500 주기에 명기하는 방식으로 처리함. 즉 B-04-W는 제목 전처리(접두/코드 판단)에 대해 호출마다 다른 판단을 내릴 수 있음.
**Why:** B-04-W가 각 호출을 독립적으로 판단하기 때문— 표준 규칙이 없으면 서지사항 전사 원칙(ISBD)을 자체 해석해 임의로 편집할 수 있음을 확인.
**How to apply:** 향후 실제 배치에서 제목에 비표준 접두/코드가 섞여 들어올 가능성이 있으면(예: 스캔 라벨 오류, 시스템 코드 오염 등), B-04-W 호출 시 "제목은 전달된 문자열 그대로 245에 기술하고 임의로 편집하지 말 것"을 명시적으로 지시하거나, 반대로 편집이 필요하면 명시적으로 지시할 것 — 일관성을 B-04-W의 자체 판단에 맡기지 말 것. DB `title` 컬럼에는 항상 사서가 입력한 원문(FN-01 등록값)을 사용하고, 245 KORMARC 표제와는 별개로 취급.

**세션 도달 이슈:** 워커가 결과를 SendMessage로 하네스에 직접 전달하려 했으나 "이름으로 하네스에 도달 불가"로 실패하고 상위(main)로 전달됨. 워커→하네스 직접 SendMessage 회신 경로가 현재 인프라상 불안정할 수 있음 — 향후 배치에서도 동일 현상 발생 가능성 있으니, 결과 미수신 시 상위 경유 전달 여부를 확인할 것.
