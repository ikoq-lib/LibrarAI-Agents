2026-09-02, 사서가 입고 확정 도서 6행 배치(batch_20260902.md)로 B-04-H 전체 파이프라인을 재검증. 이번 배치는 **의도적으로 결함 있는 입력**(ISBN 중복 1건, 저자 누락 1건, 대상 자료실 미기재 1건)을 포함해 예외 처리(FN-06) 커버리지를 시험함. 장서 DB `public.books`에는 실제 INSERT를 실행하지 않고(SELECT만), would-be INSERT문만 배치 출력 파일(`outputs/20260902_b04h_batch_test/20260902_자료조직_batch001.txt`)에 기록했다.

**결과 요약:** 접수 6건 → 등록 제외 1건(저자 누락, #6) + 중복 제외 1건(#4, #1과 ISBN 동일) → 실작업 4건(#1,#2,#3,#5) → QA 전건 1차 통과(재작업 0건), 단 #2는 발행지·대상자료실 정보 부족으로 DB 반영 보류. reg_no EM0197351~354, ctrl_no 7281716~719 신규 채번(직전 테스트 배치가 EM0197351/352·7281716/717을 쓰고 삭제한 뒤라 MAX(reg_no)=EM0197350에서 정상 이어짐 — [[project_test_batch_20260711]] 참고).

**이번 배치에서 정의에 없어 하네스가 스스로 판단한 지점 (핵심 발견):**

1. **저자 누락 도서를 WebSearch로 보완할지 vs 문언대로 등록 제외할지** — FN-01은 "임의 추정 금지"만 명시하고 결측 필드의 외부 보완 시도 허용 여부는 무규정. 실존 도서라 WebSearch로 저자를 알아낼 수 있었을 가능성이 있었지만, **문언을 엄격 해석해 등록 제외 + 사서 보완 요청**을 선택함. 정의 개정 시 "결측 필수항목을 하네스가 자체 조사로 채워도 되는지"를 명확히 할 필요.
2. **배치 내 ISBN 중복이 "입력 실수"인지 "진짜 복본(2부 입고)"인지 하네스가 자동 판정할 근거가 없음** — FN-06은 "중복 입력"이라고만 표현. 실제로 2부 입고일 수도 있는데 그 경우 049 $l 반복+$c2(복본기호)가 필요함. **1건만 처리하고 진짜 복본 여부는 사서 확인 사항으로 넘기는 쪽을 선택**(자동으로 복본 처리하지 않음).
3. **대상 자료실 미기재 시 "워커 호출 자체를 보류"할지 "카탈로징은 진행하되 DB반영만 보류"할지** — FN-01 문구는 대상 자료실이 "DB 반영 시 room 값 결정에만 필요"한 것처럼 읽히나, 실제로는 KORMARC 008/22·049 $f도 연동됨. **카탈로징은 진행 + DB반영만 보류**를 선택. 워커가 서지적 근거(동일 저자 선례·판형)로 잠정값을 제시했는데, 이를 "확정"이 아닌 "권고값(사서 확정 전)"으로 하향 표시해 배치 출력물에 별도 라벨링함 — 이 잠정값 처리 방식 자체가 정의에 없는 재량.
4. **FN-05 보고 4분류(완료/재작업통과/QA실패/정보부족)에 들어맞지 않는 "핵심 판단은 통과했으나 부속 필드 1~2개만 미확정"인 중간 상태** — #2가 해당. **"완료(조건부)"라는 제5의 상태를 임의로 만들어 보고**함. 정의에 이 중간 상태에 대한 규정이 필요해 보임.
5. **reg_no/ctrl_no/대상자료실을 워커 호출 시 사전 전달할지, 워커가 임시값을 쓰고 하네스가 사후 치환할지** — FN-03.5는 채번 절차만 규정하고 전달 방식은 무규정. **하네스가 Supabase SELECT로 사전 계산해 위임 프롬프트에 명시 전달**하는 방식을 채택(001/049 $l을 워커가 바로 정확히 채우도록). 대상 자료실은 원본 목록 값을 그대로 전달하되 미기재 건은 "미기재"임을 명시하고 워커의 통상적 판단에 맡김. 복본기호($c)는 이번엔 부여 대상 없음.
6. **워커가 전체 레코드 대신 "요약"만 반환한 사건(Job3 1차 호출)** — 위임 프롬프트에 "정해진 Output Format으로 반환"이라고만 지시했더니 워커가 자체 판단으로 축약 요약을 먼저 제시해 필드 단위 QA가 불가능했음. **SendMessage로 같은 agentId에 재요청**(요약 금지, LDR/008 문자 단위 포함 전체 원문 요구)해 해결. **Job5부터는 위임 프롬프트에 처음부터 "요약 없이 전체 레코드를, LDR·008을 문자 단위로 정확히 반환"을 명시**해 재발 방지. → 정의(b-04-h-cataloging-harness.md) 개정 시 "B-04-W 호출 시 반드시 전체 Output Format 원문을 요구하고 요약을 허용하지 않는다"를 FN-02에 명문화할 필요.
7. **LDR(24자)·008(40자, 위치별 고정값)의 "문자 단위 정확성"을 하네스가 무엇으로 검증할지 방법론이 정의에 없음** — Bash+node로 문자열을 파일에 써서 `.length`/`.slice()`로 실측하는 방법을 스스로 도입. **주의(재발 방지용 교훈): 워커 응답의 008 문자열을 손으로 다시 타이핑해 옮기다가 말미 공백 2칸을 누락해 길이가 38로 잘못 나온 적이 있음(오탐 직전)** — 반드시 워커 응답 원문을 그대로(수동 재입력 없이) 파일에 써서 대조할 것.
8. **저자기호/청구기호가 표준 리재철 산출식과 다르게 "기존 소장 선례"를 재사용할 때 QA 통과로 볼지 여부** — 워커 정의(b-04-w) 자체엔 "같은 저자·같은 총서면 기존 기호를 따른다"는 예외 규정이 있지만, 하네스 QA 체크리스트 문구("리재철 규칙 구조를 따르는가")만 보면 예외 적용 여부가 애매함. **워커가 제시한 선례를 하네스가 Supabase로 직접 재조회해 실재를 검증한 뒤 통과 처리**하는 방식을 채택(Job1의 "던295"=기존 EM 레코드 511.186 던295딜 확인, Job3의 "우239창"=EM52629 확인). 하네스가 이 재검증을 생략했다면 위험했을 지점.
9. **FN-01 예시 room 값("종합실(신간도서)"/"어린이실(신간도서)")이 실제 DB 관행과 일치하는지 정의만으론 알 수 없었음** — SELECT로 실측한 결과 이 값들은 `material_status='정리중'`일 때만 쓰는 임시 room이고, 추후 '이용가능' 전환 시 '종합자료실'/'어린이자료실'로 바뀌는 2단계 구조였음(정의가 맞았음을 확인). **검증 없이 그냥 믿고 썼다면 위험했을 부분 — 향후에도 정의에 적힌 고정값·상수는 실행 전 DB로 재확인할 것.**
10. **vol(권차) 컬럼 = "다권본 분책" vs "총서 내 권호"의 구분이 정의에 없음** — Job2(그림책 총서 118권)·Job3(재화 시리즈 8권 가능성) 둘 다 "vol을 다권본(한 저작이 여러 물리적 권으로 나뉜 경우)"으로 좁게 해석해 NULL로 두고, 총서 권호는 490/830/049 $v(KORMARC)에만 반영. 이 구분 기준도 하네스가 임의로 정한 것.
