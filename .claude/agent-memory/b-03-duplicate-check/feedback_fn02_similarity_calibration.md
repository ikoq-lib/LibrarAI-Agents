**2026-07-11 실측 검증에서 발견한 문제:** 첫 구현 테스트에서 판정을 수행한 세션이 `title_sim`/`author_sim`을 SQL로 실제 계산하지 않고 "약 0.83" 식으로 눈대중 추정해 보고했다. 직접 SQL을 재실행해 검증한 결과 실제 값은 title_sim 0.7647 / author_sim(정규화 전) 0.4737 → combined 0.68이었다. **절대 유사도 점수를 추정하지 말 것 — 항상 `similarity()` SQL 쿼리를 실행하고 반환된 숫자를 그대로 사용한다.**

**author 정규화 필수:** `public.books.author`에는 "지음/옮김/역/글/그림/저" 등 역할 표기와 `;`/`,` 구분자가 섞여 있어(예: "윌리엄 스타이그 ; 조은수 옮김"), 정규화 없이 비교하면 동일 저자도 유사도가 낮게 나온다(정규화 전 0.47 → 정규화 후 0.69, 실측). FN-02 SQL은 반드시 `regexp_replace(author, '(지음|옮김|역|글\.?|그림|저|편)\.?|[;,·]', ' ', 'g')`로 두 문자열 모두 정규화한 뒤 `similarity()`를 계산한다.

**안전마진 70~85%로 재보정:** 위 정규화를 적용해도 명백한 개정판 케이스(같은 저자, "(개정판)"만 추가된 제목)의 combined_sim이 0.743으로 나와, 기존 안전마진(75~85%)의 하한에도 못 미쳐 자동으로 `new` 처리될 뻔했다. `.claude/agents/b-03-duplicate-check.md`의 안전마진을 70~85%로 하향 조정 완료. 앞으로 실제 판정 데이터가 쌓이면 이 하한(70%)이 너무 넓어 오탐(사서가 매번 "신규"로 확정)이 잦은지 확인하고 필요시 재조정할 것.

**2026-07-11 B-01 위임 테스트로 재검증 완료:** B-01이 실제 호출 인터페이스(FN-05)로 후보 3건(『치과의사 드소토 선생님』 정본 vs "(개정판)" 표기 위조 ISBN 후보, 완전 신규 가상도서)을 보내 테스트. 동일한 개정판 케이스가 실제 SQL로 title_sim 0.764706 / author_sim(정규화 후) 0.692308 → combined 0.7429866(≈0.743)로 재현되어, 70~85% 안전마진이 정확히 의도대로 이 건을 `needs_review`로 걸러냄을 실전 확인. 기존 안전마진 하한(75%)이었다면 자동 `new` 오판정될 뻔한 사례가 실제 위임 경로에서도 재현된 것 — 70% 하한 조정이 유효함을 뒷받침.

**2026-07-11 B-02 위임에서도 동일 케이스 재현:** B-02(희망도서)가 동일한 "치과의사 드소토 선생님(개정판)" + 위조 ISBN(9999999999999) 패턴으로 FN-05 호출, 결과도 title_sim 0.764706 / author_sim 0.692308 → combined 0.743으로 완전히 동일하게 재현됨(호출자가 B-01이든 B-02든 무관하게 안정적). 이 특정 도서(치과의사 드소토 선생님, ISBN 8949110091, EM19289)는 여러 도메인 에이전트의 표준 테스트 픽스처로 반복 사용되는 것으로 보임 — 향후 회귀 테스트 시 참고 가능.
