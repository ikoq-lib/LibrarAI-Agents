**문서 버전:** 1.0
**작성일:** 2026-07-04
**소속 도메인:** D2 이용자
**에이전트 ID:** C-02
**에이전트 유형:** Leaf Agent
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3

---

## 1. 개요

### 1.1 목적

C-02 추천 에이전트는 이용자가 키오스크(음성+터치 입력)에서 도서 추천을 요청하면, 대출 통계·소장 자료 정보를 기반으로 개인화 또는 비개인화 추천 목록을 제공하는 리프 에이전트다. C-01 FAQ 에이전트가 개인화 추천 질문을 받으면 C-02로 라우팅한다.

### 1.2 배경

실시간 OPAC·대출이력 API 연동이 없는 현재 환경(CLAUDE.md Pending Issues 참조)에서는 이용자를 실시간으로 식별하거나 그 자리에서 개인 대출이력을 조회할 수 없다. 따라서 C-02는 두 가지 추천 모드를 병행한다.

| 모드 | 조건 | 추천 방식 |
|------|------|---------|
| 비개인화 추천 | 회원 식별 불가 또는 비회원 | 인기 대출 통계·신착 자료·주제 큐레이션 기반 |
| 개인화 추천 | 이용자가 회원번호를 직접 제시하거나 최근 대출 이력을 언급 | 해당 이용자의 대출 이력 KDC·주제 분포 기반 유사 자료 추천 |

대출 통계 데이터는 사서가 엑셀 파일로 업로드하는 연구용 방식(xlsx.js 처리, CLAUDE.md 기술스택 참조)을 사용하며, 실LMS 연동 시 자동 수집으로 대체 가능하도록 설계한다.

### 1.3 다른 에이전트와의 구분

| 에이전트 | 추천/큐레이션 성격 |
|---------|----------------|
| **C-02 (이 문서)** | 이용자 개인 요청에 대한 즉석 도서 추천 (키오스크 상호작용) |
| D-02 행사기획 | 월별 행사용 북큐레이션 (어린이/성인 각 5~8권, 사전 기획) |
| D-01 동아리 | 독서동아리 회차별 도서 선정 제안 (모임 진행 목적) |
| B05 균형 | 장서 전체의 KDC 분류 균형 분석 (수서 방향 제언, 개별 이용자 대상 아님) |

C-02는 이용자 개인의 즉석 질의에 응답하는 유일한 에이전트이며, 나머지는 모두 사서가 사전에 기획하거나 장서 전체를 분석하는 성격이다.

### 1.4 범위

- **포함:** 비개인화 인기·신착 도서 추천, 개인화 대출이력 기반 추천, 주제·키워드 기반 추천, 연령대별(어린이/청소년/성인) 필터링, 추천 사유 설명, 대출 통계 데이터 업로드 관리
- **제외:** 실시간 재고·대출 가능 여부 확인(OPAC 미연동), 실제 예약·대출 처리, 특정 행사용 사전 기획 북큐레이션(D-02 담당), 독서동아리 회차 도서 선정(D-01 담당), 장서 전체 KDC 균형 분석(B05 담당)

## 4. 기능 요구사항

### FN-01 비개인화 인기·신착 도서 추천

회원 식별이 안 되거나 별도 조건 없이 추천을 요청하는 경우, 전체 대출 통계 기반 인기 도서와 신착 도서를 추천한다.

**추천 기준:**
- 최근 3개월 대출 횟수 상위 도서 (자료실별로 분리: 종합/어린이/다문화)
- 최근 입수된 신착 도서 (입수일 기준 최신순)
- 특정 계절·시기 트렌드 반영 가능 (예: 여름방학 시즌 어린이 인기 도서)

**출력 형식 예시:**
```
[요즘 많이 읽는 책 — 종합자료실]
1. 『○○○』 저자명 — 최근 3개월 대출 32회
2. 『○○○』 저자명 — 최근 3개월 대출 27회
...
```

---

### FN-02 개인화 추천 (대출이력 기반)

이용자가 회원번호를 제시하거나 최근 읽은 책을 언급하면, 해당 정보를 기반으로 유사 자료를 추천한다.

**처리 흐름:**
1. 이용자 식별 정보(회원번호) 또는 최근 대출·열람 도서 정보 수집
2. 대출 이력의 KDC 분류·주제 분포 분석
3. 가장 빈도가 높은 1~2개 분류·주제와 연관된 미대출 자료 추천

**Config 없이 이용자를 식별할 수 없는 경우:** FN-01 비개인화 추천으로 대체하고, 그 이유를 이용자에게 안내한다.

---

### FN-03 주제·키워드 기반 추천

이용자가 자연어로 주제를 요청하면("힐링되는 소설 추천해줘", "환경 관련 책 있어?") 키워드·주제 매칭으로 소장 자료 중 추천 목록을 구성한다.

**처리 흐름:**
1. 요청에서 주제·장르·분위기 키워드 추출
2. 소장 자료(또는 대출 통계 데이터에 포함된 서지 정보) 중 매칭되는 자료 검색
3. 매칭 자료가 부족할 경우 상위 카테고리로 범위를 넓혀 재검색

---

### FN-04 연령대별 추천 필터링

이용자가 있는 자료실(어린이자료실/다문화자료실/종합자료실 등) 또는 명시한 대상 연령에 맞춰 추천 목록을 필터링한다.

**필터 기준:** 어린이 자료실 이용자에게는 성인 도서를 추천하지 않으며, 반대의 경우도 마찬가지로 자료실 이용 대상 규정(예: 종합자료실은 중학생 이상)을 따른다.

---

### FN-05 추천 사유 설명

각 추천 도서마다 추천 근거를 간단히 덧붙인다.

**출력 예시:**
```
『○○○』 — 최근 대출하신 『△△△』와 같은 사회과학(KDC 300번대) 분야이며,
비슷한 독자들이 많이 찾는 책이에요.
```

---

### FN-06 소장 여부 확인 및 위치 안내 연계

추천 도서의 소장 여부를 확인하고, 위치 정보가 필요하면 이용자에게 C-01(위치 안내 기능)로 이어서 물어보도록 안내한다.

**소장 여부 미확인 시:** "소장 여부 확인이 필요합니다. 자료실에서 검색용 PC로 확인해보세요."로 안내한다 (실시간 OPAC 미연동).

---

### FN-07 대출 통계 데이터 업로드 관리

사서가 정기적으로 대출 통계 엑셀 파일을 업로드하면 xlsx.js로 파싱하여 추천 로직에 반영한다.

**업로드 데이터 항목 (예상):** 도서명, ISBN, KDC 분류, 대출 횟수, 최근 대출일, 자료실 구분

**갱신 주기:** 사서 업로드 시점 기준 (권장: 월 1회 이상)

---

## 5. 데이터 흐름

```
[사서 — 정기]
사서 → C-02: 대출 통계 엑셀 업로드
C-02: xlsx.js 파싱 → 통계 캐시 갱신

[이용자 요청 시]
이용자 → C-02: 추천 요청 (일반 요청 / 회원번호·최근 대출 언급 / 주제 언급)

  → 식별 정보 있음 (FN-02): 대출 이력 분석 → 개인화 추천
  → 주제 언급 (FN-03): 키워드 매칭 추천
  → 식별 정보 없음 (FN-01): 인기·신착 추천

C-02: 연령대 필터링 (FN-04) → 추천 사유 부가 (FN-05) → 이용자에게 응답
필요 시 → C-01 위치 안내로 이어서 안내 (FN-06)
```

## 6. MCP 도구 연동

| 도구 | 용도 |
|------|------|
| MCP Filesystem | 대출 통계 엑셀 파일 로드 |
| MCP SQLite | 대출 통계 캐시, 추천 이력 저장 |
| xlsx.js (CDN 동적 로드) | 엑셀 파싱 |

외부 API 연동 없음. LMS 대출이력 API 미연동 (연구용: 사서 엑셀 업로드 방식).

## 7. Human-in-the-loop 정책

| 단계 | 사서 개입 여부 | 내용 |
|------|--------------|------|
| 추천 요청 응답 | 불필요 | 자동 생성 |
| 대출 통계 업로드 | **필수** | 사서가 직접 엑셀 파일 제공 |
| 추천 정책(가중치·필터 기준) 조정 | **필수** | 사서 승인 후 Config 반영 |
| 소장 여부 최종 확인 | 불필요(단, 미확인 시 자료실 방문 안내) | 자동 안내 |

## 8. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 이용자 식별 불가 | 비개인화 추천(FN-01)으로 대체, 사유 안내 |
| 대출 통계 데이터 없음/오래됨 | 마지막 업로드 시점 안내 후 신착 도서 위주로 대체 추천 |
| 주제 매칭 자료 없음 | 상위 카테고리로 확대 검색 후 안내, 그래도 없으면 사서 문의 권고 |
| 자료실 이용 대상과 맞지 않는 추천 요청 | 해당 자료실 이용 대상 안내 후 적합한 자료실로 재추천 |
| 엑셀 파싱 오류 | 실패 항목 목록화 후 사서에게 재업로드 요청 |

---

## 9. 비기능 요구사항

- 키오스크 상호작용 특성상 응답은 지연 없이 즉시 제공되어야 한다.
- 추천 목록은 3~5권 내외로 간결하게 제시한다.
- 대출 통계 데이터는 연도 단위로 보존하며 삭제하지 않는다.
- 에이전트 응답 언어: 한국어

## 11. 향후 확장 고려사항

- LMS 대출이력 API 정식 연동 시 실시간 개인화 추천으로 전환 검토
- 실시간 OPAC 연동 시 FN-06 소장 여부·대출 가능 여부 즉시 확인 기능 확장
- 추천 결과에 대한 이용자 피드백("마음에 들어요"/"별로예요") 수집 후 추천 정확도 개선 루프 검토
- C-01 위치 안내와의 연계를 넘어, 추천 도서의 서가 위치까지 함께 안내하는 기능 검토
