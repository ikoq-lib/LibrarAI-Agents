# PRD — D-01 독서동아리 에이전트 (Reading Club Agent)

**문서 버전:** 1.0
**작성일:** 2026-07-07
**소속 도메인:** D3 독서문화
**에이전트 ID:** D-01
**에이전트 유형:** Leaf Agent
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3
**기존 구현:** `.claude/agents/d-01-reading-club.md`(서브에이전트 스펙), `LibrarAI.html`(웹앱 "독서동아리" 탭) — 본 PRD는 두 구현체의 기능을 사후 정리한 설계 문서다.

---

> **표기 안내:** 이 문서의 `FN-01`, `FN-02`... 는 D-01 에이전트 내부 기능(Function) 번호다. 기존 서브에이전트 스펙(`.claude/agents/d-01-reading-club.md`)은 동일 기능을 `F-01`~`F-08`로 표기하고 있었으나, 이는 PRD가 아니라 스펙 파일 소속 번호라 별개로 유지한다. 본문에 등장하는 `A-01`·`A-03`·`D-03`·`DM-03`·`F-01`·`F-04`는 모두 실제 에이전트 ID 참조다.

---

## 1. 개요

### 1.1 목적

D-01 독서동아리 에이전트는 공공도서관 독서동아리의 전 생애주기 — 정보 등록, 모집 공고, 참여자(기관) 관리, 강사 섭외 연계, 회차별 도서 선정, 운영일지 작성, 연간 실적 보고 — 를 지원하는 에이전트다. 도서관 자체 운영(`in_house`)과 외부 기관 방문형(`outreach`) 두 유형을 모두 다루며, 문서 생성이 필요한 모든 산출물은 A-01 공문서 에이전트를 통해 hwpx로 생성한다.

### 1.2 배경

독서동아리는 매 회차 반복되는 행정 업무(공고문, 명단 관리, 운영일지)가 많고, outreach 유형은 강사 섭외까지 별도로 필요해 사서의 업무 부담이 크다. D-01은 이 반복 업무를 자동화하되, 공고 게시·참여자 선정·강사 섭외 트랙 전환 등 대외적으로 영향을 미치는 결정은 모두 사서 승인을 거치도록 한다.

> **D-01 동아리 vs D-02 행사기획 역할 구분**
> D-02는 1일~수일 내 완결되는 단발성 행사를 기획하고, D-01은 회차가 반복되는 동아리(정기 모임)를 운영 지원한다.

> **D-01 동아리 vs E-01~E-05 평생학습 역할 구분**
> 평생학습(E 도메인)은 강사 공개 채용을 거치는 정규 강좌를 다루고, D-01은 독서 토론 중심의 동아리를 다룬다. outreach 유형의 강사가 필요한 경우에도 D-01은 D-03(개별 섭외)을 호출하며, E-02(공개 공모)를 사용하지 않는다.

### 1.3 기존 구현과의 관계

- `LibrarAI.html`의 "독서동아리" 탭 시스템 프롬프트가 F-01~F-07 기능으로 이미 서비스 중이다.
- `.claude/agents/d-01-reading-club.md` 서브에이전트 스펙이 F-01~F-08(F-08 SNS·소식지 연계 포함)로 더 상세히 정의되어 있다.
- 본 PRD는 두 구현체를 기준으로 기능을 FN-01~FN-08로 재정리한 것이며, 신규 기능을 추가하지 않는다. 향후 기능 변경 시 이 문서와 스펙 파일을 함께 갱신한다.

## 2. 업무 범위 (Scope)

### 포함 (In Scope)
- 동아리 정보 등록·연간 회차 일정 자동 생성
- 모집 공고문 초안 생성 (in_house/outreach 유형별 항목 분기)
- 참여자(또는 협력 기관) 명단 관리 및 선정 결과 통보문 초안
- outreach 유형 강사 섭외 요건을 D-03에 전달, 공개 모집 실패 시 개별 섭외 전환 절차 지원
- 회차별 도서 후보 제안(3순위)
- 회차별 운영일지 초안 생성
- 연간 운영 실적 데이터 집계 및 DM-03 전달
- C-03·F-01·F-04에 동아리 현황 데이터 제공

### 제외 (Out of Scope)
- 모집 공고 실제 게시, 참여자 최종 선정, 도서 최종 확정 (사서 고유 권한)
- 강사 실제 발굴·섭외 문자 작성 (D-03 담당, D-01은 요건 전달만)
- 강사비 지급 처리 및 예산 편성 (A-03 담당)
- 도서 신규 구입 (B-01 수서 에이전트 담당, D-01은 미소장 안내만)
- 결과보고서 자체 작성·결재 (DM-03 담당, D-01은 실적 데이터 제공까지만)

## 3. 운영 유형 분류

모든 기능은 `type` 파라미터를 기준으로 분기한다.

| 유형 코드 | 설명 | 강사 필요 |
|----------|------|----------|
| `in_house` | 도서관 내 자체 운영 | 선택 |
| `outreach` | 외부 기관 방문 파견형 | 필수 |

- `type` 미지정 시 기본값 `in_house`를 적용하고 사서에게 확인을 요청한다.
- 동아리명·일정·협력 기관 등 기관 고유 정보는 Config 주입값을 사용하며 PRD·프롬프트에 하드코딩하지 않는다.

## 4. 업무 흐름 (Workflow)

```
[트리거] 사서의 동아리 등록/운영 요청, 또는 DM-03·C-03·F-01·F-04의 데이터 조회 요청

STEP 1 — 동아리 정보 등록 (FN-01)
  → 동아리명·유형·대상·연도·총 회차·주기·정원 확인
  → clubs 테이블 저장 + sessions 테이블 회차 일정 자동 생성

STEP 2 — 모집 공고문 초안 (FN-02) [A-01 호출]
  → 유형별 포함 항목 반영 hwpx 초안 생성
  → 사서 검토·수정 후 게시 [Human-in-the-loop]

STEP 3 — 참여자(기관) 명단 관리 (FN-03)
  → 신청 접수 → members 테이블 저장
  → 사서 최종 선정 [Human-in-the-loop] → 선정 결과 통보문 초안

STEP 4 — 강사 섭외 연계 (FN-04) [outreach 전용, requires_instructor=true]
  → D-03에 요건 전달 → 공개 모집
  → 신청 0명 시: A-01 보고 공문 초안 → 사서 승인 대기 [Human-in-the-loop] → 개별 섭외 전환 요청

STEP 5 — 회차별 도서 선정 제안 (FN-05)
  → 대상·주제 기반 3순위 후보 제시 → 사서 최종 확정 [Human-in-the-loop]
  → 미소장 도서는 B-01 연계 가능 여부 안내

STEP 6 — 회차별 운영일지 초안 (FN-06) [A-01 호출]
  → 사서 입력(회차·일자·도서·출석·활동) → hwpx 초안 생성
  → 사서 검토·결재 후 sessions 테이블 갱신

STEP 7 — 연간 운영 현황 보고 (FN-07) [DM-03 연계, 자동]
  → 동아리 종료 또는 DM-03 요청 시 실적 데이터 표준 형식 전달

STEP 8 — 소식 데이터 제공 (FN-08) [C-03·F-01·F-04 연계, 자동]
  → 동아리명·활동 요약·모집 현황 등 요청 시 즉시 응답
```

## 5. 기능 요구사항

### FN-01 독서동아리 정보 등록 및 관리

사서 입력을 MCP SQLite `clubs`·`sessions` 테이블에 저장한다.

**`clubs` 테이블:** `club_id`(자동), `club_name`, `type`, `target_audience`, `year`, `session_count`, `session_frequency`, `max_members`, `requires_instructor`, `partner_institution`(outreach 전용), `status`(`planned`/`recruiting`/`active`/`completed`)

**`sessions` 테이블:** `session_id`(자동), `club_id`, `session_no`, `scheduled_date`, `actual_date`, `book_title`, `activity_summary`, `attendance`, `status`(`scheduled`/`completed`/`cancelled`)

시작일과 운영 주기를 기반으로 회차별 예정일을 자동 계산한다. 방학·공휴일 등 예외 일정은 사서 확인 후 반영한다.

---

### FN-02 모집 공고문 초안 생성 (A-01 호출)

동아리 유형에 맞는 모집 공고문 hwpx 초안을 A-01에 요청한다.

| 유형 | 포함 항목 |
|------|---------|
| `in_house` | 동아리명, 운영 목적, 대상, 정원, 운영 기간·횟수·장소, 신청 방법, 문의처 |
| `outreach` | 사업명, 대상 기관 유형, 선정 기준, 신청 방법, 운영 조건, 문의처(특정 기관명 미명시, "운영 여건 및 수요를 사전 검토하여 선정" 표현 사용) |

> ⚠️ **Human-in-the-loop:** 초안 생성 후 사서 검토·수정을 거쳐야 게시한다. 에이전트가 직접 게시하지 않는다.

---

### FN-03 참여자(기관) 명단 관리

모집 완료 후 참여자/협력 기관 정보를 `members` 테이블에 저장한다.

**`members` 테이블:** `member_id`(자동), `club_id`, `name`(in_house: 참여자명 / outreach: 기관명), `contact`, `status`(`applied`/`selected`/`waitlisted`/`rejected`), `joined_date`

선정 결과 통보문 초안을 생성하고, 사서 최종 확정 후 발송한다.

> ⚠️ **Human-in-the-loop:** 참여자(기관) 선정은 사서가 최종 확정한다.

---

### FN-04 강사 섭외 연계 (outreach 전용)

`requires_instructor: true` 동아리에 대해 D-03 강사섭외 에이전트에 요건을 전달한다.

```json
{
  "requester_agent": "D-01",
  "club_id": "[club_id]",
  "club_name": "[동아리명]",
  "target_audience": "[대상]",
  "session_count": [회차수],
  "session_dates": ["[날짜1]", "[날짜2]", "..."],
  "instructor_requirements": "독서 지도 경력 1년 이상",
  "instructor_fee_per_session": [회당 강사비],
  "recruitment_method": "public"
}
```

**공개 모집 실패 → 개별 섭외 전환 절차:**
1. 공개 모집 마감 후 D-03으로부터 신청 인원 0명 수신 확인
2. A-01 호출 → 보고 공문 초안 자동 생성 (모집 기간·정원·신청 인원 0명·향후 계획 포함, "공개 모집 미달에 따라 적격자를 개별 섭외하여 운영할 예정임" 표현 사용)
3. **사서 승인 대기** — 에이전트가 자동으로 트랙을 전환하지 않는다.
4. 승인 확인 후 D-03에 개별 섭외 트랙 전환 요청

운영일 임박 시점에도 강사가 미확정이면 즉시 사서에게 촉구 알림을 발송한다.

> ⚠️ **Human-in-the-loop:** 개별 섭외 트랙 전환 전 사서 승인이 필수다.

---

### FN-05 회차별 도서 선정 제안

동아리 유형·대상·주제에 맞는 도서 후보를 회차당 3순위로 제안한다.

**제안 기준:** 대상 연령·독서 수준 적합성, 회차 간 주제 연속성/다양성, 토론·활동 연계 가능성, 소장 여부(소장 도서 우선)

**출력 형식:**
```
[n회차 도서 후보]
주제: [주제]
1순위: 『[도서명]』 [저자] | 소장 여부: ○/×/미확인
   → [선정 이유 및 토론 활용 방안]
2순위: 『[도서명]』 [저자] | 소장 여부: ○/×/미확인
3순위: 『[도서명]』 [저자] | 소장 여부: ○/×/미확인
```

미소장 도서 발견 시 B-01 수서 에이전트 연계 가능 여부를 안내한다. 소장 여부 확인 불가 시 "소장 여부 미확인"으로 표기하고 사서 확인을 요청한다.

> ⚠️ **Human-in-the-loop:** 도서 최종 선정은 사서가 확정한다.

---

### FN-06 회차별 운영일지 초안 생성 (A-01 호출)

**사서 입력 항목:** 회차 번호, 실제 진행일, 선정 도서, 출석 인원, 활동 내용 요약, 특이사항

**운영일지 포함 항목:**

| 항목 | 내용 |
|------|------|
| 사업명 | 동아리명 |
| 회차 | n회차 |
| 일시·장소 | 실제 진행 일시 및 장소 |
| 참여 인원 | 출석 인원 / 총 정원 |
| 선정 도서 | 도서명·저자 |
| 활동 내용 | 진행 순서 및 주요 내용 |
| 특이사항 | 민원·건의·개선 필요 사항 |
| 결재란 | 담당/팀장/과장 (기관 설정 따름) |

생성 후 `sessions` 테이블의 해당 회차 레코드를 갱신한다.

> ⚠️ **Human-in-the-loop:** 사서 검토·수정 후 결재 상신한다.

---

### FN-07 연간 운영 현황 보고 (DM-03 연계)

동아리 운영 종료 후 또는 DM-03 요청 시 다음 형식으로 실적 데이터를 전달한다.

```json
{
  "agent_id": "D-01",
  "club_id": "[club_id]",
  "club_name": "[동아리명]",
  "year": [연도],
  "total_sessions_planned": [계획 회차],
  "total_sessions_conducted": [실시 회차],
  "total_participants": [총 참여자 수],
  "avg_attendance_rate": [평균 출석률],
  "books_discussed": ["[도서1]", "[도서2]", "..."],
  "notable_outcomes": "[주요 성과 및 특이사항]"
}
```

사서 개입 없이 자동 실행된다. (DM-03·C-03 PRD에서는 이 표준 형식을 "D-01 FN-07 형식"으로 인용한다.)

---

### FN-08 SNS·소식지 소식 데이터 제공 (F-01·F-04 연계)

F-01 SNS 에이전트 또는 F-04 소식지 에이전트 요청 시 다음 항목을 제공한다: 동아리명, 최근 회차 활동 요약, 선정 도서, 다음 회차 예정일·주제, 모집 중 여부.

사서 개입 없이 자동 응답한다. (C-03 PRD에서는 이 인터페이스를 "D-01 FN-08 인터페이스"로 인용한다.)

---

## 6. 비기능 요구사항

| 항목 | 기준 |
|------|------|
| Human-in-the-loop | 공고 게시, 참여자 선정, 개별 섭외 전환, 도서 최종 선정, 운영일지 결재는 모두 사서 승인 필수 |
| 범용 설계 | 동아리명·일정·협력 기관 등은 Config로 주입. PRD·프롬프트 본문에 특정 기관 하드코딩 금지 |
| 자동 처리 허용 범위 | 동아리 정보 등록(즉시 저장), DM-03 실적 데이터 전달(FN-07), F-01·F-04 소식 데이터 제공(FN-08) |
| 공문서 규칙 준수 | A-01 호출 시 날짜(`2026. 1. 6.`)·시간(24시각제)·금액(숫자+한글 병기)·항목기호·낫표 등 `CLAUDE.md` 공문서 규칙 명시 |
| 외부 API 연동 | 없음. 필요 상황 발생 시 사서에게 알리고 대안 제시 |

## 9. 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 공개 모집 신청자 0명 | 보고 공문 초안 자동 생성 → 사서 승인 대기 → 개별 섭외 전환 |
| 회차 취소 발생 | `sessions.status: cancelled` 기록, 보강 일정은 사서 판단 |
| 도서 소장 여부 미확인 | "소장 여부 미확인" 표기 후 사서 확인 요청 |
| `type` 값 미입력 | 기본값 `in_house` 적용 후 사서에게 확인 요청 |
| outreach 강사 미확정 + 운영일 임박 | 사서에게 강사 확정 촉구 알림 발송 |
| 정보 부족으로 작업 불가 | 필요한 정보 목록을 명시하고 사서에게 입력 요청 |

## 10. 수용 기준 (Acceptance Criteria)

- **AC1**: 동아리 등록 시 시작일·주기 기반으로 전체 회차 예정일이 자동 생성된다.
- **AC2**: in_house/outreach 유형에 따라 모집 공고문 포함 항목이 다르게 구성된다.
- **AC3**: outreach 유형에서 공개 모집 신청 0명 확인 시, 사서 승인 없이는 개별 섭외 트랙으로 전환되지 않는다.
- **AC4**: 도서 제안은 항상 3순위 형식과 소장 여부 표기를 포함한다.
- **AC5**: 운영일지 생성 후 해당 회차의 `sessions` 레코드가 갱신된다.
- **AC6**: 동아리 종료 시 또는 DM-03 요청 시 FN-07 표준 형식으로 실적 데이터가 자동 전달된다.
- **AC7**: C-03·F-01·F-04 요청에 사서 개입 없이 FN-08 형식으로 응답한다.

## 11. 미결 사항 (Open Questions)

1. **방학·공휴일 예외 일정 처리 규칙**: 회차 자동 계산 시 건너뛸 날짜를 사서가 매번 지정할지, 기관 Config에 연간 휴관일을 사전 등록할지 결정 필요.
2. **강사비 잔액 확인 시점**: outreach 섭외 요건을 D-03에 전달하기 전에 A-03 잔액 조회를 필수 선행 단계로 둘지, D-03 내부에서 처리할지 정리 필요.
3. **members 테이블과 B-03 복본조사 연계 여부**: 참여자가 신청한 도서 추천 요청이 있을 경우 B-03과의 연계 필요성 검토.
