# 수서(收書) 에이전트 PRD
**Product Requirements Document · Leaf Agent #01**

- 버전: v0.1 초안
- 계층: Leaf Agent
- 도메인: 자료개발
- 우선순위: 높음

---

## 1. 에이전트 정의

공공도서관의 자료 선정·주문·수령·등록 업무를 지원하는 단일 목적(single-purpose) leaf agent.
도서관 외부 데이터(알라딘 API, 국립중앙도서관 서지 데이터)와 내부 데이터(기존 장서 DB, 이용자 대출 통계)를 조합해 선정 초안을 자동 생성하고, 사서의 최종 검토·결재를 지원한다.

| 항목 | 내용 |
|---|---|
| 상위 에이전트 | 자료개발 도메인 에이전트 (Domain Agent) |
| 호출 방식 | 도메인 에이전트로부터 태스크 수신 / 사서 직접 호출 |
| 출력 소비자 | 도서관 장서 관리 시스템, 도메인 에이전트, 담당 사서 |
| 개발 방법론 | 바이브 코딩 + 하네스 엔지니어링 |

---

## 2. 배경 및 문제 정의

### 현재 문제
신간 목록 수기 검토, 중복 확인, 예산 배분 계산이 분절·수작업으로 처리됨. 선정 근거 문서화 미흡.

### 목표 상태
정형화된 선정 기준과 외부 API를 활용해 초안을 자동 생성, 사서는 검토·승인에만 집중.

---

## 3. 업무 범위 (Scope)

### 포함 (In Scope)
1. 신간 후보 목록 수집 및 필터링 (알라딘 신간 API, 주제별 베스트셀러)
2. 장서 중복 여부 자동 확인 (ISBN 대조, KORMARC 레코드 조회)
3. 선정 기준 점수화 및 우선순위 정렬 (이용자 요청, 대출 통계, 출판 연도, KDC 균형)
4. 예산 범위 내 자동 배분 초안 산출
5. 선정 도서 목록 엑셀/보고서 초안 자동 생성 및 결재 패키지 구성

### 제외 (Out of Scope)
- 최종 선정 결정 (사서 고유 권한)
- 발주 송신
- 납품 검수
- KORMARC 레코드 생성 (목록 에이전트 담당)
- 폐기 처분 판단

---

## 4. 업무 흐름 (Workflow)

```
트리거 수신 (도메인 에이전트 / 사서)
  → 신간 후보 수집 (알라딘 API)
  → 중복 확인 (장서 DB)
  → 점수화·정렬 (선정 기준 적용)
  → 예산 배분 초안 (KDC별 균형)
  → 보고서 생성 (Excel / 공문 초안)
  → 사서 검토·승인 [Human-in-the-loop]
```

---

## 5. 기능 요구사항

### F-01 · 신간 후보 자동 수집
알라딘 API를 통해 주제별(KDC 대분류) 신간 목록을 주기적으로 수집한다.
- 수집 주기: 주 1회 (기본값, 도메인 에이전트가 파라미터로 변경 가능)
- 필수 수집 필드: ISBN, 제목, 저자, 출판사, 정가, 출판일, 분류 기호
- 도구: `GET /aladin/api`, KDC 필터, SQLite 저장

### F-02 · 중복 및 장서 균형 확인
- 기존 장서 DB와 ISBN 대조를 통해 중복 자료를 자동 제외
- KDC 대분류별 현재 장서 수와 권장 비율 비교 → 부족 분야에 가중치 부여
- 이용자 희망도서 요청 목록과 교차 확인 → 해당 자료 우선순위 상향
- 도구: ISBN 중복검사, KDC 균형 분석, 희망도서 매핑

### F-03 · 선정 기준 점수화
각 후보 자료에 대해 아래 항목을 가중 합산하여 선정 점수 산출:
- ① 이용자 수요: 희망도서 신청 여부, 유사 도서 대출 실적
- ② 사회적 관심도: 베스트셀러 순위
- ③ 장서 균형: KDC 분야 결핍 지수
- ④ 출판 시의성: 출판일로부터 경과 개월 수 역산

가중치는 도메인 에이전트가 조정 가능해야 함.

### F-04 · 예산 배분 초안
- 분기별 자료구입비 예산을 입력값으로 수신
- 선정 점수 순 정렬 후 예산 한도 내 최대 다양성(KDC 분류 다변화) 확보
- 단일 출판사 편중(30% 초과) 자동 감지 및 경고 출력

### F-05 · 결과 문서 자동 생성
- Excel(.xlsx): 선정 순위, ISBN, 서지 정보, 정가, 수량, 선정 근거(점수 항목별 상세)
- 공문 초안(.docx): 경남교육청 공문 양식 기준 개조식 본문 자동 작성

## 6. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 응답 시간 | 후보 100건 처리 시 30초 이내 |
| Human-in-the-loop | 사서 1인 최종 승인 필수 |
| 데이터 보안 | 개발·테스트 시 더미 DB 사용, 실 이용자 데이터 미사용 |
| 에러 처리 | API 호출 실패 시 재시도 3회 후 도메인 에이전트에 오류 보고 |

## 7. 도구 및 MCP 연동

| 도구 / MCP 서버 | 용도 |
|---|---|
| Aladin API | 신간 목록 및 서지 정보 수집 |
| NLK 서지 API (국립중앙도서관) | 서지 정보 보완 및 검증 |
| MCP: Filesystem | 출력 파일(.xlsx, .docx) 저장 |
| MCP: SQLite | 장서 DB 및 중간 처리 데이터 저장 |
| MCP: Google Sheets | 사서와의 협업 검토용 공유 시트 |
| MCP: Fetch | 외부 API 호출 경유 |

> 모든 외부 API 호출은 MCP Fetch 서버를 경유한다.
> 장서 DB는 SQLite(개발) → 실 운영 시스템(운영) 순으로 단계적 교체.

---

## 8. 수용 기준 (Acceptance Criteria)

- **AC1**: 알라딘 API에서 신간 50건 수집 후, 중복 제외·점수화·Excel 생성을 30초 이내 완료한다.
- **AC2**: 희망도서 요청 목록에 포함된 자료가 최종 선정 초안 상위 20%에 반드시 포함된다.
- **AC3**: 예산 초과 자료가 최종 목록에 포함되지 않는다.
- **AC4**: 사서 승인 없이 외부 시스템(발주 시스템 등)으로 데이터가 전송되지 않는다.

---

## 9. 미결 사항 (Open Questions)

1. 알라딘 API 키 발급 및 사용 정책 확인 필요 (교육기관 비영리 무료 여부)
2. 기존 장서 DB 포맷 확인 (MARC XML / CSV 등) — SQLite 변환 작업 선행 필요
3. KDC 분야별 권장 비율 기준 결정 (도서관 자체 기준 vs. 공공도서관 통계 벤치마크)
4. 하네스 엔지니어링 적용 범위 — 점수 모델 유닛 테스트 우선 설계 여부
