# PRD — E-03 모집 에이전트 (Student Recruitment Agent)

**문서 버전:** 1.0  
**작성일:** 2026-06-29  
**소속 도메인:** D4 평생학습  
**에이전트 ID:** E-03  
**에이전트 유형:** Leaf Agent  
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3

---

## 1. 개요

### 1.1 목적

E-03 모집 에이전트는 E-02 강사공모 에이전트로부터 확정 강사·프로그램 정보를 인계받아, 수강생 모집 공고·홍보·접수·결과 보고까지의 전 과정을 담당하는 리프 에이전트다. 모집 완료 후 수강생 명단을 E-04 운영일지 에이전트에 인계한다.

### 1.2 배경

평생학습 수강생 모집은 홍보물 제작(채널별 3종), 공식 기안문 작성, 수강 신청서·명단 서식 관리, 모집 결과 보고 등 반복적인 문서 작업이 집중되는 단계다. E-03은 이 과정을 자동화하되, 실제 접수 처리와 최종 판단은 사서가 직접 수행하는 human-in-the-loop 구조로 설계한다.

### 1.3 범위

- **포함:** 홍보 문안 생성 (채널별 3종), 수강생 모집 기안문 초안, 수강 신청서·명단 서식 생성, 수강생 모집 결과 보고 공문 초안, E-04 수강생 명단 인계
- **제외:** 강사 공모 (E-02 담당), 홍보물 완성본(인쇄물·SNS) 직접 생성 (F-01 담당), 실제 수강 접수 처리 (사서 직접 처리), 강좌 운영 관리 (E-04 담당)

## 4. 기능 요구사항

### FN-01 홍보 문안 생성 및 F-01 홍보물 작성 위임

E-02 인계 수신 후 프로그램별 핵심 정보를 F-01 홍보물 에이전트에 전달해 인쇄물·SNS 홍보물 작성을 위임하고, 텍스트 전용 채널(현수막)은 E-03이 직접 문안을 작성한다.

**채널별 생성 기준:**

| 채널 | 형식 | 내용 범위 | F-01 위임 |
|------|------|---------|---------|
| 홈페이지·인쇄물 | A4/A3 세로형 | 전체 정보 (프로그램명·대상·기간·요일·시간·장소·정원·신청방법·문의처) | ✅ |
| SNS 인스타그램 | 1:1 정방형 이미지 + 캡션 | 핵심 정보 중심 축약, 중요도 낮은 항목 생략 가능 | ✅ |
| 현수막 | 텍스트 초안 | 핵심 정보만 (프로그램명·기간·신청방법) | ❌ (텍스트만 제공) |

**F-01 위임 시 전달 항목:**
```json
{
  "requester_agent": "E-03",
  "output_types": ["print_poster", "sns_instagram"],
  "event_name": "2026년 상반기 캘리그라피",
  "target_audience": "일반 성인",
  "period": "2026-03-07 ~ 2026-05-09",
  "venue": "○○도서관 강의실1",
  "session_info": "매주 토요일 10:00~12:00 (총 10회)",
  "capacity": 15,
  "application_method": "도서관 홈페이지 선착순 접수",
  "contact": "기관 Config 설정값",
  "fee": "무료",
  "tone": "친근하고 따뜻한"
}
```

**SNS 캡션 작성 원칙:**
- 첫 줄(훅): 이목을 끄는 1~2문장 (의문형·감탄형·공감형)
- 본문: 핵심 정보 간결하게, 이모지 자연스럽게 활용
- CTA: 신청 방법 및 링크 안내
- 해시태그: 기관 고정 태그 + 프로그램 관련 태그 5~10개

**현수막 텍스트 초안 예시:**
```
○○도서관 평생학습 프로그램 수강생 모집
[캘리그라피] 3.7(토) ~ 5.9(토) / 매주 토 10:00~12:00
선착순 15명 | 무료 | 홈페이지 접수
문의: 기관 Config 설정값
```

**Human-in-the-loop 필수:** 생성된 홍보 문안 및 이미지 초안 사서 검토 후 직접 게시.

### FN-02 수강생 모집 기안문 초안 (A-01 호출)

홍보물과 동시에 수강생 모집 공식 기안문 hwpx 초안을 생성한다. 복수 프로그램인 경우 하나의 기안문에 전체 프로그램을 표로 통합한다.

**기안문 포함 항목:**
- 모집 목적, 운영 개요 (전체 프로그램 표), 신청 방법, 문의처

**프로그램 통합 표 구성:**

| 프로그램명 | 대상 | 운영기간 | 요일 | 시간 | 회차 | 정원 | 수강료 |
|----------|------|---------|------|------|------|------|------|
| 캘리그라피 | 성인 | 3.7~5.9 | 토 | 10:00~12:00 | 10 | 15 | 무료 |
| 북아트 | 어린이 | 3.8~5.10 | 토 | 10:00~12:00 | 10 | 12 | 무료 |

**Human-in-the-loop 필수:** 사서 검토 후 결재 상신.

### FN-03 수강 신청서 및 명단 관리 서식 생성

수강 신청서(이용자 작성용)와 수강생 명단 관리 서식(사서 관리용)을 생성한다.

**수강 신청서 포함 항목:**
- 신청 프로그램명, 성명, 연락처, 생년월일, 이메일 (선택), 개인정보 수집·이용 동의

**수강생 명단 관리 서식 (Excel 구조):**

| 컬럼 | 내용 |
|------|------|
| 번호 | 자동 부여 |
| 성명 | |
| 연락처 | |
| 생년월일 | |
| 신청일 | |
| 접수 상태 | 정원 내 / 대기 |
| 비고 | |

**대기자 관리:** 정원 초과 신청자는 자동으로 대기 순번을 부여하고, 취소 발생 시 대기 순번대로 안내 대상을 표시한다.

### FN-04 수강생 모집 결과 보고 공문 초안 (A-01 호출)

접수 마감 후 사서가 접수 현황을 입력하면 모집 결과 보고 공문 초안을 생성한다.

**사서 입력 항목:**
- 프로그램별 정원·접수 인원·대기 인원

**공문 포함 항목:**
- 모집 기간, 프로그램별 정원·접수 현황 표, 특이사항, 향후 계획

**정원 충족 시:**
- 향후 계획: "계획대로 운영 예정임"
- FN-05 E-04 인계 진행

**미달 시 (접수 인원 < 정원):**
- 향후 계획: "추가 모집을 실시하거나 운영 규모를 조정할 예정임"
- 사서에게 아래 선택지 제시:
  1. 추가 모집: 모집 기간 연장 후 FN-01 홍보 재실행
  2. 운영 규모 조정: 정원 하향 조정 후 운영 (에이전트가 수강생 명단 업데이트)
  3. 폐강: 사서가 별도 처리 (에이전트 범위 외)

**Human-in-the-loop 필수:** 미달 시 사서가 선택지 중 하나를 선택 후 진행.

```
[E-02 인계 수신]
E-02 → E-03: 확정 강사·프로그램 정보 수신

[홍보 및 모집 공고]
E-03: 채널별 홍보 문안 생성
E-03 → F-01: 인쇄물·SNS 홍보물 작성 위임
E-03 → A-01: 수강생 모집 기안문 hwpx 초안 생성
E-03: 수강 신청서·명단 서식 생성
사서: 홍보물 검토·게시, 기안문 결재

[접수 기간]
사서: 수강 신청 접수 처리 (직접 수행)
사서 → E-03: 접수 현황 입력 (접수 마감 후)

[모집 결과]
E-03 → A-01: 모집 결과 보고 공문 초안 생성
  → 정원 충족: FN-05 E-04 인계
  → 미달: 선택지 제시 → 사서 판단
      → 추가 모집: FN-01 재실행
      → 운영 규모 조정: 명단 업데이트 → FN-05 E-04 인계
      → 폐강: 에이전트 범위 외
```

## 8. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 모집 미달 | 결과 보고 공문 초안 생성 + 추가 모집·규모 조정·폐강 선택지 제시. 임의 처리 금지 |
| 정원 초과 신청 | 대기 순번 자동 부여, 사서에게 대기자 명단 제공 |
| 동일 이용자 중복 신청 | 중복 감지 후 사서에게 확인 요청 |
| F-01 응답 실패 | 실패 안내 후 E-03이 보유한 홍보 문안 텍스트만 사서에게 제공 |
| 추가 모집 후에도 미달 | 추가 미달 결과 보고 초안 생성 후 사서 판단 재위임 |
| 폐강 결정 시 | 이미 접수한 수강생 연락처 목록 제공 (개별 연락 사서 직접 처리) |

## 9. 비기능 요구사항

- 복수 프로그램의 홍보 문안은 채널별로 일괄 생성하되, 프로그램마다 개별 내용이 포함되도록 한다.
- 수강생 명단 서식은 openpyxl 기반 Excel 파일로 생성한다.
- 기관별 고유 정보(문의처·신청 채널·강의실명 등)는 Config로 주입한다.
- SQLite 데이터는 연도 단위로 보존하며 삭제하지 않는다.
- 에이전트 응답 언어: 한국어

## 11. 향후 확장 고려사항

- 수강생 SMS·이메일 자동 안내 기능 추가 검토 (접수 확인, 개강 안내 등)
- 이용자 홈페이지 접수 시스템 연동 시 실시간 접수 현황 자동 수신 검토
- 대기자 자동 순번 전환 알림 기능 추가 검토
- E-01 수강 데이터(모집 충족률)와 연동하여 다음 시즌 기획에 자동 반영 검토
