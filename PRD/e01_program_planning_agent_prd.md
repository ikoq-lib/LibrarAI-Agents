# PRD — E-01 강좌기획 에이전트 (Lifelong Learning Program Planning Agent)

**문서 버전:** 1.0  
**작성일:** 2026-06-28  
**소속 도메인:** D4 평생학습  
**에이전트 ID:** E-01  
**에이전트 유형:** Leaf Agent  
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3

---

## 1. 개요

### 1.1 목적

E-01 강좌기획 에이전트는 공공도서관 평생학습 프로그램의 기획 단계를 전담하는 범용 리프 에이전트다. 사서의 기획 요청을 받아 사전 질의로 기획 방향을 확정하고, 직전 1년간 수강 데이터를 분석하여 데이터 기반 프로그램 후보를 추천한다. 사서 확인 후 세부계획서 hwpx 초안을 생성하여 E-02 강사섭외 에이전트에 인계한다.

### 1.2 배경

평생학습 프로그램 기획은 수요 파악 없이 진행하면 모집 미달·낮은 출석률로 이어지는 경우가 많다. E-01은 기획 시작 전 대상·주제 선호를 사전 질의로 확인하고, 과거 수강 데이터에서 성과가 높았던 주제를 우선 추천함으로써 기획의 수요 적합성을 높인다.

### 1.3 D-01과의 설계 원칙 공유

D-01 독서동아리 에이전트와 동일하게, 기관별 고유 운영 정보(예산, 강의실, 시즌 구조 등)는 PRD 본문에 하드코딩하지 않고 배포 시 Config로 주입한다.

### 1.4 범위

- **포함:** 사전 질의 수행, 수강 데이터 분석, 프로그램 후보 추천, 사서 확정 후 세부계획서 hwpx 초안 생성, E-02 강사섭외 에이전트 인계
- **제외:** 강사 섭외 실행 (E-02 담당), 수강생 모집 (E-03 담당), 강좌 운영 중 관리 (E-04 담당), 결과보고 (DM-04 담당), 예산 집행 (A-03 담당)

## 5. 기능 요구사항

### FN-01 사전 질의 수행

사서가 기획 요청을 하면 세부계획서 작성 전에 아래 세 가지 질의를 순서대로 수행한다. 모든 질의에 대한 사서의 응답을 확인한 후에만 FN-02(수강 데이터 분석)로 진행한다.

**질의 1 — 대상**
```
이번 시즌 프로그램의 대상을 선택해주세요. (복수 선택 가능)

① 유아 (7세 미만)
② 어린이 (초등학생)
③ 청소년 (중·고등학생)
④ 일반 성인
⑤ 시니어 (65세 이상)
```

**질의 2 — 대상별 프로그램 개수**
```
각 대상별로 몇 개의 프로그램을 운영할 예정인가요?
(예: 어린이 2개, 일반 성인 3개)
```

**질의 3 — 대상별 선호 주제**
```
각 대상별로 선호하거나 기획하고 싶은 주제가 있으면 알려주세요.
없으면 '없음' 또는 '데이터 기반으로 추천해줘'라고 입력해주세요.
(예: 어린이 — 독서·공예, 일반 성인 — 없음)
```

**Human-in-the-loop 필수:** 세 질의 모두 사서 응답 확인 후 다음 단계 진행. 에이전트가 임의로 값을 가정하지 않는다.

---

### FN-02 수강 데이터 분석

사전 질의 응답을 바탕으로 SQLite `course_history` 테이블에서 직전 1년간 수강 데이터를 조회하고 분석한다.

**분석 지표:**

| 지표명 | 산식 | 설명 |
|--------|------|------|
| 모집 충족률 | 접수 인원 / 모집 정원 × 100 | 수요 반응도 |
| 출석률 | 평균 출석 인원 / 접수 인원 × 100 | 지속 참여도 |
| 수료율 | 수료 인원 / 접수 인원 × 100 | 완료도 |
| 종합 점수 | (모집 충족률 × 0.4) + (출석률 × 0.4) + (수료율 × 0.2) | 강좌 성과 종합 지수 |

**분석 출력 예시:**
```
[직전 1년 수강 데이터 분석 — 일반 성인 대상]

순위 | 주제        | 모집충족률 | 출석률 | 수료율 | 종합점수
1    | 캘리그라피  | 120%       | 91%    | 88%    | 98.8
2    | 수채화 기초 | 100%       | 85%    | 82%    | 93.4
3    | 요가·필라테스| 95%       | 78%    | 75%    | 86.8
4    | 스마트폰 활용| 80%       | 72%    | 68%    | 76.4

※ 모집충족률 100% 초과는 대기자 발생 강좌를 의미합니다.
※ 데이터가 없는 주제는 신규 기획으로 분류됩니다.
```

**데이터 없는 경우:** 해당 대상의 이전 운영 이력이 없으면 "신규 기획 — 데이터 없음"으로 표시하고 공공도서관 트렌드 기반 추천으로 전환한다.

### FN-03 프로그램 후보 추천

FN-01 사전 질의 응답과 FN-02 분석 결과를 결합하여 대상별 프로그램 후보를 추천한다.

**추천 우선순위:**

```
1순위: 사서가 선호 주제를 명시한 경우
       → 해당 주제를 최우선 배치, 수강 데이터로 세부 방향 보완

2순위: 사서가 '데이터 기반 추천' 요청 시
       → 종합 점수 상위 주제 우선 추천
       → 동일 주제 연속 3시즌 이상 운영 시 주의 표시 ("신선도 저하 위험")

3순위: 데이터 없는 신규 주제 필요 시
       → 공공도서관 트렌드 + 대상 특성 기반 신규 제안
       → "(신규)" 레이블 표시
```

**후보 목록 출력 형식:**

```
[2026년 상반기 프로그램 후보 — 사서 확정 요청]

■ 일반 성인 (3개 필요)

1. 캘리그라피 ★데이터 추천★
   · 근거: 직전 1년 종합점수 1위 (98.8점), 모집충족률 120%
   · 제안 운영: 10회, 주 1회, 회당 2시간

2. 수채화 기초 ★데이터 추천★
   · 근거: 직전 1년 종합점수 2위 (93.4점)
   · 제안 운영: 8회, 주 1회, 회당 2시간

3. 북바인딩 (신규)
   · 근거: 공공도서관 트렌드 — 손공예 계열 인기 상승 중
   · 제안 운영: 8회, 주 1회, 회당 2시간

■ 어린이 (2개 필요)

1. 독서·북아트 ★사서 지정★
   · 운영일: 토요일 지정
   · 제안 운영: 8회, 주 1회, 회당 2시간

2. 과학 실험 교실 ★데이터 추천★
   · 근거: 직전 1년 어린이 대상 종합점수 1위 (91.2점)
   · 운영일: 토요일 지정
   · 제안 운영: 8회, 주 1회, 회당 2시간

※ 위 목록을 확인하신 후 수정·확정 의견을 주세요.
   확정 후 세부계획서 작성을 진행합니다.
```

**Human-in-the-loop 필수:** 후보 목록은 사서 확인 후 확정. 사서가 일부를 교체하거나 수정할 수 있으며, 에이전트가 최종 확정 없이 세부계획서 작성을 시작하지 않는다.

### FN-04 예산 잔액 확인 (A-03 호출)

세부계획서 작성 전 A-03 예산 에이전트에 해당 시즌 강사비·운영물품비 잔액을 조회하여 예산 초과 여부를 확인한다.

**예산 초과(부족) 시:** A-03이 예산 부족으로 응답하면, 먼저 A-03의 FN-07 절차(사업항목 간 예산 유용, Bottom-Up — 같은 단위과제카드 내 인접 사업항목의 잔액을 가까운 단계부터 찾아 대체 재원으로 쓸지 확인하는 절차, A-03 PRD FN-07/스펙 FN-08 참고)를 통해 대체 재원 사용 여부를 사서에게 확인한다.
- 사서가 대체 재원 사용에 동의하면 그 재원으로 세부계획서 작성을 계속 진행한다.
- 사서가 거절하면 **세부계획서 작성을 중단한다.** 임의로 프로그램 수·회차 수 조정 단계로 넘어가지 않는다.
- 같은 단위과제카드 내에 대체 재원이 전혀 없다고 A-03이 응답한 경우에만, 초과 금액과 함께 사서에게 알리고 프로그램 수·회차 수 조정 의견을 제시하는 기존 절차로 진행한다. 이 경우에도 사서 승인 없이 예산 초과 계획서를 작성하지 않는다.

### FN-05 세부계획서 hwpx 초안 생성 (A-01 호출)

사서 확정 및 예산 확인 완료 후 A-01 공문서 에이전트를 호출하여 세부계획서 hwpx 초안을 생성한다.

**세부계획서 구성 (공공도서관 기안문 첨부 표준):**

| 항목 | 형식 | 내용 |
|------|------|------|
| 1. 운영 목적 | 개조식 | 프로그램별 목적, 지역 수요 배경 |
| 2. 운영 개요 | 개조식 | 전체 기간·대상·프로그램 수·총 정원·운영 장소·소요 예산 |
| 3. 세부 내역 | 표 | 순번·프로그램명·대상·운영기간·요일·시간·회차·정원·강의실·비고, 하단 합계 행 |
| 4. 소요 예산 | 표 | 예산과목(기관명/평생학습/강사비) 명시, 프로그램별 강사비 표, 하단 합계 행, 표 아래 운영물품비 별도 명시 |
| 5. 기대 효과 | 개조식 | 대상별 기대 효과, 도서관 기여 효과 |

**강의실 자동 배정 원칙:**
- Config의 `audience_rules.children_preferred_day` 설정 값 우선 적용
- 정원 규모에 따라 수용 가능한 강의실 자동 매칭
- 동일 시간대 중복 배정 방지

**A-01 호출 입력 구조:**
```json
{
  "requester_agent": "E-01",
  "template_id": "TPL-002",
  "season": "상반기",
  "programs": [
    {
      "name": "캘리그라피",
      "target": "일반 성인",
      "period": "2026-03-07 ~ 2026-05-09",
      "day": "토요일",
      "time": "10:00~12:00",
      "sessions": 10,
      "capacity": 15,
      "room": "강의실1",
      "instructor_fee_per_session": 100000,
      "total_instructor_fee": 1000000
    }
  ],
  "total_instructor_fee": 5000000,
  "operation_cost": 300000
}
```

### FN-07 수강 데이터 누적 저장

매 시즌 종료 후 DM-04 평생학습 도메인 에이전트로부터 수강 실적 데이터를 수신하여 SQLite `course_history` 테이블에 저장한다. 이 데이터가 다음 시즌 FN-02 분석의 입력값이 된다.

**`course_history` 테이블 저장 항목:**

| 필드 | 설명 |
|------|------|
| `course_id` | 자동 부여 ID |
| `season` | 시즌명 (상반기·여름방학 등) |
| `year` | 운영 연도 |
| `program_name` | 프로그램명 |
| `subject_tag` | 주제 태그 (예: 캘리그라피·요리·독서) |
| `target_audience` | 대상 |
| `capacity` | 모집 정원 |
| `applicants` | 접수 인원 |
| `avg_attendance` | 평균 출석 인원 |
| `completions` | 수료 인원 |
| `recruitment_rate` | 모집 충족률 (%) |
| `attendance_rate` | 출석률 (%) |
| `completion_rate` | 수료율 (%) |
| `composite_score` | 종합 점수 |

## 6. 데이터 흐름

```
[시즌 기획 시작]
사서 → E-01: 시즌 지정 (예: "상반기 기획 시작해줘")

E-01 → 사서: 사전 질의 3종 순차 수행
사서 → E-01: 대상·개수·선호 주제 응답

E-01 → SQLite: 직전 1년 course_history 조회
E-01: 대상별 종합 점수 분석
E-01 → 사서: 프로그램 후보 목록 제시
사서 → E-01: 후보 확정 (수정 포함)

E-01 → A-03: 시즌 예산 잔액 조회
A-03 → E-01: 잔액 응답
  → 예산 초과 시: 사서에게 조정 의견 제시 → 사서 승인

E-01 → A-01: 세부계획서 hwpx 초안 생성 요청
A-01 → E-01: hwpx 파일 경로 반환
E-01 → 사서: 초안 전달

사서: hwpx 검토·수정·결재 상신

[세부계획서 승인 후]
E-01 → E-02: 확정 프로그램 정보 전달

[시즌 종료 후]
DM-04 → E-01: 수강 실적 데이터 전달
E-01 → SQLite: course_history 저장
```

## 9. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 직전 1년 수강 데이터 없음 | "데이터 없음" 명시 후 트렌드 기반 추천으로 전환 |
| 동일 주제 3시즌 이상 연속 운영 | 후보 제시 시 "신선도 저하 위험" 주의 표시 |
| 예산 초과(부족) 계획 | A-03 FN-07 대체 재원(같은 단위과제카드 내 Bottom-Up) 확인 우선 → 사서 거절 시 세부계획서 작성 중단, 대체 재원 없을 때만 초과 금액·조정 의견 제시 → 사서 승인 없이 진행 불가 |
| 사전 질의 응답 불완전 | 누락 항목 재질의, 임의 가정 금지 |
| 강의실 중복 배정 발생 | 자동 대안 강의실 제안, 해결 불가 시 사서 판단 요청 |
| Config 미입력 항목 | 해당 파라미터 입력 요청, 기본값 사용 시 명시 |

## 10. 비기능 요구사항

- 수강 데이터 분석은 직전 1년(최근 4개 시즌) 기준으로 수행한다.
- 종합 점수 가중치(모집충족률 40% / 출석률 40% / 수료율 20%)는 Config에서 조정 가능하도록 설계한다.
- 기관별 고유 운영 정보는 Config로만 주입하며 PRD 본문에 하드코딩하지 않는다.
- SQLite 데이터는 연도 단위로 보존하며 삭제하지 않는다.
- 에이전트 응답 언어: 한국어
