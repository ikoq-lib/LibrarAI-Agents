## 1. 개요

### 1.1 목적

최상위 오케스트레이터는 인간 최고관리자(관장)와 6개 도메인(D0~D5) 사이의 유일한 접점이다. 최고관리자로부터 지시를 받아 해당 도메인 에이전트(DM-01~DM-05, D0는 A-01·A-03·A-04에 직접)에 분배하고, 각 도메인의 계획서·실적 데이터를 취합해 월간 또는 특별 행사 단위의 통합 계획서·결과보고서를 작성해 최고관리자에게 보고한다.

### 1.2 배경 — 도메인 에이전트(DM) 계층 도입에 따른 위치 재정의

2026-07-07 도메인 에이전트 계층(DM-01~DM-05) 도입 이전에는 최상위 오케스트레이터가 32개 리프 에이전트 각각을 상대해야 했다. 이제는 D1~D5 도메인이 각자의 DM을 통해 1차 취합되므로, 최상위 오케스트레이터는 **DM 5개 + D0 3개(A-01·A-03·A-04) — 총 8개 소스**만 상대한다. 단, 이 상대 방식은 두 갈래로 나뉜다.

- **정기 실적 통계(정량 지표):** A-02 최상위이관 에이전트가 8개 소스에서 표준 JSON을 수집·표준화해 최상위 오케스트레이터에 "완성 데이터 패키지"로 전달한다(`a02_top_level_relay_agent_prd.md` FN-04). 최상위 오케스트레이터는 이 패키지를 받아 통계 계산·보고서 작성만 담당하며, A-02를 거치지 않고 개별 소스에 직접 실적을 요청하지 않는다.
- **계획서·정책 지시·특별 행사 결과:** A-02의 범위 밖이다(A-02 PRD 1.3 범위: "정기 실적 데이터"에 한정). 최상위 오케스트레이터가 DM-01~DM-05와 **직접** 주고받는다 — 정책 지시 하향(FN-01), 계획서 취합(FN-02), 특별 행사 결과보고 취합(FN-04)이 여기 해당한다.

이 두 채널을 혼동하지 않는 것이 중요하다: "이번 달 통계 줘"는 A-02 경유, "이번 달 사업계획 짜줘"는 DM 직접 채널이다.

### 1.3 범위

- **포함:**
  - 최고관리자 지시 수신 및 도메인 에이전트(DM-01~DM-05, 필요 시 D0 직접)에 하향 분배(FN-01)
  - 월간/특별 행사 계획서 취합 요청 및 통합 계획서 작성(FN-02)
  - A-02 경유 정기(월간·반기·연간) 실적 통계 수신 및 통계보고서 작성(FN-03)
  - 특별 행사(수시) 결과보고서 취합 및 작성(FN-04)
  - 보고서 내 수치 시각화(차트) 생성(FN-05)
  - hwpx 문서 출력(A-01 호출, FN-06)
  - 이상 징후 강조(예산 초과, 정책 위반 등)를 실행 요약에 표기(FN-07)
- **제외:**
  - 도메인 내부 리프 실적 취합·1차 표준화(각 DM 담당)
  - 정기 실적 데이터의 개별 소스 수집·검증(A-02 담당)
  - 리프 간 직접 협업 호출의 중계(각 도메인 자체 처리)
  - 예산 잔액 조회·집행 기록·이상 집행 판정 자체(A-03 담당 — 최상위는 A-03/DM이 이미 판정한 결과를 보고서에 강조 표기만 함)
  - 실제 결재·대외 발송(최고관리자 고유 권한)

## 4. 기능 요구사항

### FN-01 최고관리자 지시 수신 및 하향 분배

인간 최고관리자로부터 정책·업무 지시를 수신해 대상 도메인 에이전트(DM-01~DM-05 중 하나 이상, 또는 D0 공통도구 자체를 겨냥한 지시는 A-01/A-03/A-04에 직접)에 분배한다.

**처리 절차:**
1. 지시 내용을 분석해 대상 DM(들)을 식별한다.
2. 여러 도메인에 걸친 지시는 각 DM이 이해할 수 있는 형태로 분해해 전달한다.
3. 지시가 모호하면 임의로 배분하지 않고 최고관리자(또는 대리하는 사서)에게 확인 질문한다.
4. 분배 완료 후 어느 DM에 어떤 내용을 전달했는지 최고관리자에게 확인 보고한다.

**분배 기준(예시):** 수서·복본·자료조직·장서 균형·점검 → DM-01 / 이용자 서비스 전반 → DM-02 / 독서동아리·행사·독서문화 강사공모·순회문고 → DM-03 / 평생학습 강좌 전반 → DM-04 / 홍보·협력기관·공모사업·소식지 → DM-05.

> ⚠️ 이 지시 분배는 도메인 내부 리프 간 협업 호출과 무관하다 — 각 DM이 자기 리프에게 어떻게 전달할지는 DM의 재량이다.

---

### FN-02 계획서 취합 및 통합 계획서 작성

월간 정기 주기 또는 특별 행사 준비 시, 관련 DM(들)에 계획 수립 여부를 조회하고 응답을 취합해 통합 계획서를 작성한다.

**트리거:**
- **정기(월간):** 매월 말 또는 사서·최고관리자 요청 시, 다음 달 계획을 5개 DM 전체에 조회한다.
- **특별 행사:** 사서·최고관리자가 특정 행사/사업명을 지정해 요청 시, 관련 DM(들)에만 조회한다.

**계획 조회 요청 (최상위 → 각 DM):**
```json
{
  "requester_agent": "chief-coordinator",
  "request_type": "plan_request",
  "scope": "monthly",
  "target_period": "2026-08"
}
```
(특별 행사인 경우 `"scope": "event"`, `"event_name": "[행사명]"` 추가)

**계획 응답 (DM → 최상위):**
```json
{
  "agent_id": "DM-03",
  "agent_name": "독서문화 도메인 에이전트",
  "scope": "monthly",
  "period": "2026-08",
  "has_plan": true,
  "plan_summary": "8월 독서문화 행사 3건(북토크 1, 체험형 2), 독서동아리 정기 모임 2건 예정",
  "source_leaf": ["D-02", "D-01"],
  "status": "complete"
}
```
계획이 없는 도메인(예: 해당 월 특별 계획이 없는 DM-01)은 `"has_plan": false, "status": "unavailable"`로 응답하며, 이는 오류가 아니다.

> **역할 경계(중요):** 각 DM이 자기 도메인의 `plan_summary`를 이미 작성해 응답한다 — 최상위 오케스트레이터는 이 내용을 처음부터 새로 쓰지 않는다. 최상위의 역할은 5개 도메인 응답을 **편집(compile & edit)** 해 하나의 통합 계획서로 묶는 것이다(F-04 소식지 에이전트가 여러 소스의 하이라이트를 하나의 발행물로 편집하는 방식과 동일한 패턴). 도메인 전문성이 필요한 서술(무엇을, 왜)은 DM 책임이고, 문서 전체의 구조·요약·예산 개요·확인 필요 항목 취합은 최상위 책임이다.

**통합 계획서 구성:** ①표지 ②요약(각 DM의 `plan_summary`에서 핵심만 3~5줄로 발췌 — 최상위가 새로 작성하지 않음) ③도메인별 계획 상세(DM-01~05 순서로 각 `plan_summary` 원문 배치, 계획 없는 도메인은 "해당 없음" 표기) ④예산 소요 개요(A-03 경유 데이터 반영 시) ⑤최고관리자 확인·승인 필요 항목

> ⚠️ **Human-in-the-loop 필수:** 초안 생성 후 최고관리자 검토·확정 전까지는 확정 계획으로 간주하지 않는다.

### FN-03 정기 실적 통계 수신 및 통계보고서 작성 (A-02 경유)

A-02로부터 월간·반기·연간 완성 데이터 패키지(`a02_top_level_relay_agent_prd.md` FN-04 구조)를 수신해 통계보고서를 작성한다. 최상위 오케스트레이터는 개별 DM·D0 소스에 직접 실적을 요청하지 않는다 — 이 흐름은 전적으로 A-02가 대행한다.

**수신 데이터 활용:** `domains.D0`(A01·A03·A04 개별 응답), `domains.D1~D5`(각 DM-01~05의 1차 취합 응답)를 도메인별 섹션과 통합 수치 분석(차트)에 반영한다.

**수집 미완료 상태로 요청받은 경우:** A-02가 반환한 현재까지의 부분 데이터임을 보고서에 명시하고, 완료 후 갱신본을 재생성한다.

### FN-04 특별 행사 결과보고서 취합 및 작성 (수시)

정기 월간 주기와 무관하게, 특정 행사·사업이 종료된 직후 사서·최고관리자 요청으로 해당 행사만의 결과보고서를 생성한다.

**결과 조회 요청 (최상위 → 관련 DM):**
```json
{
  "requester_agent": "chief-coordinator",
  "request_type": "event_result_request",
  "event_name": "[행사/사업명]",
  "target_period": "[행사 기간]"
}
```
DM은 자신의 월간 실적 취합 로직(각 DM PRD의 "리프 실적 데이터 수신·검증" 기능)을 해당 행사 범위로 좁혀 응답한다. 여러 도메인에 걸친 행사(예: 독서문화 행사 + 홍보 연계)는 관련 DM 모두에 요청 후 하나의 보고서로 통합한다.

> **역할 경계:** FN-02와 동일한 원칙 — DM이 자기 도메인의 행사 실적 서술을 작성하고, 최상위는 여러 DM의 응답을 편집·통합해 하나의 보고서로 구성한다.

**구성:** ①행사 개요(기간·대상·목적) ②운영 실적(도메인별, 각 DM 응답 원문 기반) ③예산 집행 현황(해당 시) ④성과 및 개선사항 ⑤차기 유사 행사 제언

> ⚠️ **Human-in-the-loop 필수:** 초안 생성 후 최고관리자 검토·결재 전까지는 미확정.

---

### FN-05 수치 시각화(차트) 생성

FN-03·FN-04에서 확보한 정량 데이터를 막대·선·원형 차트(텍스트/ASCII 또는 렌더링용 구조화 데이터)로 표현한다. 축·단위는 반드시 한글로 표기하고, 차트 옆에 원본 수치 표를 함께 제시한다.

**우선 차트 유형:** 예산 집행 현황(막대), 월별 추이(선), KDC·분야별 분포(원형).

---

### FN-06 hwpx 문서 출력 (A-01 호출)

FN-02(계획서)·FN-03(통계보고서)·FN-04(특별 행사 결과보고서)의 확정 전 초안을 A-01 공문서 에이전트를 호출해 hwpx로 생성한다. 문서 종류에 따라 목적문 종결(운영 계획: "~하고자 합니다", 결과보고: "~보고합니다")을 구분한다(CLAUDE.md 공문서 작성 규칙 준수).

---

### FN-07 이상 징후 강조

DM·A-03이 이미 판정·보고한 이상 징후(예산 잔액 부족, 정책 위반, 목표 미달)를 재계산하지 않고, 수신된 데이터의 플래그·notes를 그대로 실행 요약(Executive Summary) 상단에 ⚠️ 표기로 강조한다.

최상위 → A-01: 통합 계획서 hwpx 초안 생성

## 8. 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 일부 DM 계획/결과 미응답 | 재요청 1회 후 미응답 항목은 "확인 중"으로 표기, 최고관리자에게 안내 |
| 특정 도메인 해당 기간 계획 없음 | `unavailable` 처리, 보고서에 "해당 없음" 표기(오류 아님) |
| A-02 데이터 수집이 아직 진행 중 | 현재까지의 부분 데이터로 초안 생성 후 "잠정치" 표기, 완료 시 갱신 |
| 지시 대상 도메인이 불명확 | 임의 배분하지 않고 확인 질문 |
| 여러 도메인에 걸친 특별 행사 결과 취합 시 도메인 간 수치 중복(예: 동일 참여자 이중 집계) | 원본 데이터 그대로 표기하고 최고관리자에게 중복 가능성 안내(임의 보정 금지) |

## 9. 비기능 요구사항

- 계획서·결과보고서·통계보고서 모두 A-01을 통해 hwpx 형식으로만 출력한다(CLAUDE.md 문서 출력 규칙).
- 통계보고서의 정량 데이터는 A-02가 표준화한 값을 그대로 사용하며, 별도로 재계산하지 않는다.
- 이상 징후 강조는 하위 에이전트가 이미 판정한 결과만 인용하며, 최상위가 새로운 판정 기준을 임의로 적용하지 않는다.
- SQLite 이력 데이터는 연도 단위로 보존하며 삭제하지 않는다.
- 모든 응답은 한국어로 작성한다.

## 11. 미결 사항 (Open Questions)

1. ~~DM 측 계획 응답 인터페이스 부재~~ — **해결됨(2026-07-07):** DM-01~DM-05 PRD·스펙 전체에 FN-02(계획서 초안 생성 및 최상위 전달)를 대칭 추가했다. 각 DM이 자기 리프의 계획을 취합·편집해 `plan_summary`로 응답하며, 최상위는 이를 다시 편집·통합만 한다(DM이 계획을 직접 초안 작성 → 최상위는 편집자 역할 — F-04 소식지의 다중 소스 편집 패턴과 동일). 각 DM PRD의 기능 번호가 한 칸씩 뒤로 밀렸으므로(예: DM-01 "리프 실적 데이터 수신"은 FN-02→FN-03), 참조 시 각 DM PRD 최신본을 확인할 것.
2. **월간 계획서의 실질 대상 도메인:** D1(장서)·D2(이용자)는 D3(행사기획)·D4(시즌 기획)·D5(공모사업)만큼 "월간 계획" 개념이 뚜렷하지 않다 — 실제로 각 DM PRD FN-02는 이 경우 대부분 `unavailable` 응답을 기본값으로 설계했다. 매월 5개 DM 전체에 조회를 보낼지, 계획 성격이 뚜렷한 도메인에만 선별적으로 보낼지는 운영 데이터 축적 후 재검토.
3. **여러 도메인에 걸친 특별 행사의 최종 확정 주체:** 행사 하나에 여러 DM이 관련될 때, 통합 보고서의 최종 편집 책임(도메인 간 서술 비중, 우선순위)을 최상위가 임의로 정할지 최고관리자 지침을 별도로 받을지 확정 필요.
4. **주간 업무계획서 여부:** 구 설계(A-02 이관 이전)에는 "월간·주간 업무계획서"라는 표현이 있었으나, 본 PRD는 월간·특별 행사 단위로만 정의했다. 주간 단위 계획서가 실제로 필요한지 사서 확인 필요.
