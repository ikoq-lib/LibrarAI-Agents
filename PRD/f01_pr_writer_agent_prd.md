# PRD — F-01 홍보물 작성 에이전트 (PR Writer Agent)

**문서 버전:** 1.0
**작성일:** 2026-07-07
**소속 도메인:** D5 홍보협력
**에이전트 ID:** F-01
**에이전트 유형:** Leaf Agent
**기존 구현:** `.claude/agents/f-01-pr-writer.md`(서브에이전트 스펙), `LibrarAI.html`(웹앱 "홍보물 작성" 탭), `PRD/PRD_홍보_담당.md`(초기 기술 메모) — 본 PRD는 세 자료를 근거로 사후 정리한 설계 문서다.

> **표기 안내:** 이 문서의 `FN-01`, `FN-02`... 는 F-01 에이전트 내부 기능(Function) 번호다. 다른 에이전트를 인용할 때(`D-02`·`D-03`·`E-01` 등)는 실제 에이전트 참조다.
>
> **D-04 PRD와의 관계(2026-07-07 폐지 확정):** `PRD/d04_promotional_materials_agent_prd.md`는 D3 독서문화 도메인 소속 "D-04 홍보물" 에이전트가 OpenRouter 이미지 생성 모델을 호출하고, F-01은 그 중 SNS 이미지 생성만 D-04에 위임하는 구조로 먼저 설계되었다. 그러나 실제 구현(`f-01-pr-writer.md`, `LibrarAI.html`)은 F-01 **단일 에이전트가 보도자료·인쇄물·SNS 3종을 모두 직접 생성**하며, 이미지 생성 API를 호출하지 않고 "이미지 요소 지시문"(디자인 가이드 텍스트)으로 대체한다. **D-04는 별도 에이전트로 구현하지 않기로 확정(폐지)했다** — F-01이 그 기능을 완전히 흡수했다고 판단했으며, 구 C-02(위치)를 C-01로 통합 폐지했던 것과 동일한 유형의 구조 정리다. 이에 따라 D3 독서문화 도메인은 6개 → 5개로, 전체 리프 에이전트는 32개 → 31개로 정정됐다. 본 PRD가 F-01의 유일한 정식 설계 문서이며, D-04 PRD는 폐지된 최초 설계안으로만 보존된다.

## 1. 개요

### 1.1 목적

F-01 홍보물 작성 에이전트는 도서관의 각종 행사·프로그램에 대해 보도자료, 홈페이지·인쇄물, SNS(인스타그램) 3종 홍보물 초안을 hwpx 형식으로 생성하는 에이전트다. 기획업무팀 기획담당(D-02 행사기획, D-03 강사섭외, E-01 강좌기획 등)이 확정한 행사 정보를 받아 매체별 지침에 맞춰 홍보물을 작성한다.

### 1.2 배경

도서관 행사 하나당 성격이 다른 세 매체(공식 텍스트, 인쇄용 시각물, SNS용 소셜 콘텐츠)에 맞춰 각각 다르게 홍보물을 제작해야 했고, 사서가 매체별로 반복 작성하는 부담이 컸다. F-01은 동일한 행사 정보를 입력받아 세 매체 지침에 맞게 동시에 초안을 생성하되, 실제 게시·발송은 항상 사서가 담당한다.

### 1.3 산출물 유형

| 유형 | 성격 | 형식 | 주요 내용 |
|------|------|------|----------|
| 보도자료 | 공식·언론 배포용 | hwpx 텍스트 | 제목·부제, 리드 문단(5W1H), 행사 취지·기간·내용, 관계자 코멘트, 문의처 |
| 홈페이지·인쇄물 | 공식·시각 | hwpx (A4/A3) | 이미지 요소 지시문(텍스트로 대체) + 헤드라인, 운영기간·내용·장소·신청방법·문의처, 레이아웃 가이드 |
| SNS(인스타그램) | 소셜 | hwpx (1:1) | 이미지 요소 지시문(인쇄물과 톤 통일, 정보 축약) + 인스타그래머블 캡션, 해시태그 |

세 유형 모두 실제 이미지 파일을 생성하지 않으며, "이미지 요소 지시문"이라는 상세 디자인 가이드 텍스트로 대체한다(1.1의 D-04 PRD 관계 설명 참조).

### 1.4 범위

- **포함:** 매체별 홍보물 초안 생성(보도자료·인쇄물·SNS), 특정 매체만 요청 시 해당 매체만 생성, hwpx 변환(`hwpx-autofill-conversion` 스킬), 담당자 표기 통일
- **제외:** 홍보물 실제 게시·배포·발송(사서 담당), SNS 게시글 실제 업로드, 이미지 파일 실제 생성(현재 미구현 — 9절 참조), 소식지 제작(F-04 담당), 영상 홍보물 제작

## 3. 기능 요구사항

### FN-01 정보 수집 및 매체 선택 확인

사용자(사서 또는 호출 에이전트)로부터 행사 정보를 받아 필수 항목(행사명, 기간, 장소, 대상, 내용, 신청 방법)이 모두 있는지 확인한다. 누락된 핵심 정보는 작업 전 반드시 질문한다.

특정 매체만 요청된 경우 해당 매체만 작성하고, 별도 지정이 없으면 3종 모두 작성한다.

---

### FN-02 보도자료 생성

- 배포 날짜(작성 당일 기준), 행사 성격에 맞는 제목·부제, 리드 문단(5W1H), 본문(취지·기간·주요 내용·대상·장소·신청 방법), 관계자(사서 또는 관장) 코멘트(직접 인용), 문의처(미제공 시 `[전화번호]` 플레이스홀더)
- 격식체·3인칭 보도 문체로 작성
- hwpx 형식으로 출력

---

### FN-03 홈페이지·인쇄물 생성

- 규격: A4 또는 A3(미지정 시 행사 규모에 따라 적절히 선택)
- 이미지 요소 지시문: 행사 성격에 어울리는 배경 이미지·색상 테마·그래픽 요소를 구체적으로 묘사하는 디자인 가이드 텍스트(실제 이미지 생성 불가 시 대체)
- 헤드라인, 핵심 정보 텍스트(운영 기간, 행사 내용 요약, 장소, 대상, 신청 방법, 문의처), 시각적 레이아웃 가이드(텍스트 배치 순서·강조 요소)
- hwpx 형식으로 출력

---

### FN-04 SNS(인스타그램) 생성

- 규격: 1:1 정방형
- 이미지 카드: 인쇄물과 디자인 톤 통일, 핵심 정보만 선별, 시각적으로 간결한 구성 가이드
- 캡션 텍스트: 인스타그래머블한 문체(친근·감각적, 이모지 적절히 사용), 스토리텔링형 소개, 핵심 정보 재강조(날짜·신청 방법), 해시태그(행사명·도서관명·관련 키워드, `#공공도서관 #도서관행사` 등 포함)
- hwpx 형식으로 출력

---

### FN-05 문서 출력 및 검토·수정

- 모든 홍보물은 hwpx 파일 형식으로 출력하며, `hwpx-autofill-conversion` 스킬로 변환한다.
- 문서 내 담당자 표기는 **기획업무팀 기획담당**으로 통일한다.
- 사용자 피드백을 반영해 수정본을 제공한다.

---

## 4. 작성 원칙

- **정확성**: 제공된 정보를 정확히 반영하며 날짜·장소·비용 등을 임의로 창작하지 않는다.
- **일관성**: 동일 행사의 매체별 홍보물은 정보와 톤이 일관되어야 한다.
- **적합성**: 행사 성격(어린이/성인 대상, 문화/교육행사 등)에 맞는 어조·디자인 방향을 제안한다.
- **플레이스홀더**: 알 수 없는 정보(전화번호, 도서관 주소 등)는 `[정보]` 형식으로 명확히 표시한다.
- 기관 기본 정보(도서관명, 주소, 전화, 홈페이지, 인스타그램 계정)는 Config로 주입하며, 미제공 시 플레이스홀더를 사용한다.

## 6. 도구 및 연동

| 도구 / 에이전트 | 사용 시점 |
|----------------|---------|
| `hwpx-autofill-conversion` 스킬 | 홍보물 3종 hwpx 변환 |
| D-02 행사기획 에이전트 | 행사 정보 전달 후 홍보물 요청 |
| D-03 강사섭외 에이전트 | 강사 확정 정보 전달 후 홍보물 요청 |
| E-01 강좌기획 에이전트 | 강좌 정보 전달 후 홍보물 요청 |

외부 이미지 생성 API 연동 없음(9절 참조). 필요 정보가 부족하면 임의로 추정하지 않고 사용자에게 질문한다.

## 7. 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 핵심 정보(행사명·기간·장소·대상·내용·신청방법) 누락 | 작업 시작 전 필요한 항목을 구체적으로 질문 |
| 특정 매체만 요청 | 해당 매체만 생성, 나머지는 생성하지 않음 |
| 연락처 등 기관 정보 미제공 | `[정보]` 형식 플레이스홀더 사용, 임의 생성 금지 |
| 이미지 실제 생성 요청 | 현재 이미지 생성 기능 없음을 안내하고, 이미지 요소 지시문(디자인 가이드 텍스트)으로 대체 제공 |

## 8. 수용 기준 (Acceptance Criteria)

- **AC1**: 3종 모두 요청 시 보도자료·인쇄물·SNS 홍보물이 모두 hwpx로 생성된다.
- **AC2**: 특정 매체만 요청하면 해당 매체만 생성된다.
- **AC3**: 필수 정보가 누락된 상태에서는 홍보물을 생성하지 않고 누락 항목을 먼저 질문한다.
- **AC4**: 동일 행사에 대해 생성된 매체별 홍보물의 행사명·기간·장소 등 핵심 정보가 서로 일치한다.
- **AC5**: 담당자 표기가 모든 산출물에서 "기획업무팀 기획담당"으로 통일된다.

---

## 9. 미결 사항 (Open Questions)

1. **이미지 실제 생성 도입 여부**: D-04 PRD(폐지됨, 역사적 기록)가 설계했던 OpenRouter 이미지 생성 모델 연동을 F-01에 직접 도입할지, 아니면 현재처럼 디자인 가이드 텍스트로 유지하고 사서가 Canva 등 별도 툴에서 완성할지 결정 필요(도입 시에도 별도 D-04 에이전트를 되살리지 않고 F-01 내부 기능으로 추가하는 방향으로 검토 — D-04는 결번 처리됨).
2. **SNS 실제 게시 연동**: 현재 캡션·이미지 지시문 초안까지만 생성하며, 인스타그램 실제 게시는 전적으로 사서가 수행한다. 추후 게시 자동화(예약 게시 등) 필요성은 운영 후 재검토한다.
