**문서 버전:** 1.0  
**작성일:** 2026-05-11  
**소속 도메인:** D0 행정  
**에이전트 ID:** A-01  
**에이전트 유형:** Leaf Agent (공통 도구 에이전트)  
**참조 아키텍처:** 창녕도서관 사서 AI 에이전트 시스템 v3

## 1. 개요

### 1.1 목적

A-01 공문서 초안 작성 에이전트는 창녕도서관 전 업무 도메인에서 발생하는 공문서(기안문) 초안을 hwpx 형식으로 생성하는 공통 도구 에이전트다. 각 도메인 에이전트가 공문 작성이 필요한 시점에 A-01을 호출하여 초안을 받아가는 구조로, 경상남도교육청 공문서 양식 규정과 공공기관 기안문 작성 기준을 일원화하여 관리한다.

### 1.2 배경

창녕도서관은 수서, 프로그램 운영, 독서동아리, 순회문고, 강사 섭외 등 거의 모든 업무에서 기안문 작성이 필요하다. 기안문은 경상남도교육청 표준 양식을 준수해야 하며, 형식 오류 시 반려 처리된다. 현재는 사서가 직접 한글(HWP) 프로그램에서 기존 문서를 복사·수정하는 방식으로 처리하나, 반복 작업이 많고 양식 일관성 유지가 어렵다.

A-01은 이 반복 과정을 자동화하고, 공문 양식 지식을 단일 에이전트에 집중시켜 향후 양식 변경 시 A-01만 수정하면 전 도메인에 일괄 반영되도록 한다.

### 1.3 운영 방식

A-01은 독립적으로 사서 요청을 직접 받을 수도 있고, 타 도메인 에이전트(D-02 행사기획, E-01 강좌기획 등)가 내부적으로 호출하는 방식으로도 작동한다. 생성된 hwpx 파일은 MCP Filesystem을 통해 지정 경로에 저장되며, 사서가 USB로 복사하여 업무 PC의 한글 프로그램에서 검토·결재 처리한다.

### 1.4 범위

- **포함:** 기안문 hwpx 초안 생성, 공문 양식 템플릿 관리, 도메인 에이전트 호출 대응
- **제외:** 결재 처리, 공문 발송, 접수·처리 이력 관리 (별도 행정 시스템 담당), 첨부 문서 본문 작성 (각 도메인 에이전트 담당)

### FN-01 공문 유형별 템플릿 관리

### FN-02 기안문 구조 생성

경상남도교육청 기안문 표준 구조에 따라 본문을 구성한다.

**기안문 표준 구조:**

```
수신: 내부결재
(경유)
제목: ○○○

1. 관련: [관련 공문 번호 및 날짜]
2. [추진 배경 또는 목적] (개조식)
3. [세부 내용 또는 결과] (개조식, 표 포함 가능)
   가. 항목1: ...
   나. 항목2: ...
4. 향후 계획 (해당 시)

붙임: ○○○ 1부. 끝.
```

**개조식 작성 원칙:**
- 명사형 또는 동사 명사화로 종결 ("~임", "~함", "~예정임")
- 불필요한 수식어 제거, 사실 위주 기술
- 수치는 아라비아 숫자 사용, 단위 명시

### FN-03 hwpx 파일 생성 (hwpx-autofill-conversion 스킬 기반)

**핵심 원칙:** hwpx는 플레이스홀더 치환 방식이 아니라, **검증된 샘플 파일을 원본 그대로 복사한 뒤 `Contents/section0.xml`만 새로 생성하여 교체**하는 방식으로 만든다. 처음부터 XML을 작성하거나 샘플 내 다른 파일(header.xml, container.xml, settings.xml 등)을 임의로 수정하면 namespace·설정 불일치로 한글에서 "파일이 손상되었습니다" 오류가 발생하므로 금지한다.

**처리 흐름:**

1. 해당 공문 유형(`템플릿ID`)에 연결된 hwpx 샘플 파일 경로를 MCP Filesystem에서 확인 (미공급 시 스킬 기본 샘플로 폴백)
2. FN-02 기안문 구조와 사서 또는 호출 에이전트가 전달한 내용을 바탕으로 `section0.xml`에 들어갈 문단(paragraph) 목록 구성 (제목·본문 항목·붙임·결재선 순)
3. Python 스크립트를 별도 `.py` 파일로 작성하여 `zipfile`로 샘플 hwpx를 열고 `Contents/section0.xml`만 새 XML로 교체, 나머지 파일은 원본 그대로 복사
   - namespace는 반드시 `2011` 연도 사용 (`2012` 사용 시 파일 손상)
   - 첫 문단(`id="1"`)은 `hp:secPr` 페이지 설정 고정 블록 유지, 본문 문단은 `id=2`부터 순차 증가
   - 텍스트 내 `<`, `>`, `&` 등 XML 특수문자는 `xml.sax.saxutils.escape()`로 이스케이프
4. `py -3 script.py`로 스크립트를 실행하여 hwpx 파일 생성 (한글 경로 인코딩 문제 방지를 위해 인라인 `-c` 실행 금지)
5. 완성 파일을 `/outputs/` 경로에 저장

**파일명 규칙:**
```
[날짜]_[공문유형]_[대상또는제목요약].hwpx
예: 20260511_강사선정결과보고_2026상반기평생학습.hwpx
```

**Human-in-the-loop 필수:** 생성된 hwpx 초안은 사서가 한글 프로그램에서 반드시 검토·수정 후 결재 상신한다. 에이전트는 초안만 제공하며 결재 처리를 대행하지 않는다.

### FN-04 기안문 불필요 공문 식별 및 안내

일부 공문은 기안문 없이 별도 문서만 작성하거나 구두 처리가 적절한 경우가 있다. 에이전트는 요청 내용을 분석하여 기안문이 불필요한 경우 사서에게 안내한다.

**기안문 불필요 유형 (확정 사례):**

| 유형 | 처리 방식 |
|------|----------|
| 강사 섭외 문자 | 문자·이메일 초안 직접 생성 (기안문 없음) |
| 범죄경력조회 요청 | 관련 기관 지정 양식 사용 (기안문 없음) |
| 이용자 안내 문자 | 문자 초안 직접 생성 (기안문 없음) |

### FN-05 도메인 에이전트 호출 인터페이스

```json

  "template_id": "TPL-004",

    {
      "heading": "모집 개요",
      "items": [
        "모집 기간: 2026. 3. 13.(금) ~ 3. 19.(목)",

        "신청 인원: 0명"

    },

      ]
    }
  ],
  "attachments": ["2026년 상반기 평생학습 강사 모집 공고문 1부"]
}
```

**출력:** 생성된 hwpx 파일 경로 반환

## 9. 비기능 요구사항

- hwpx 파일은 한글 2020 이상에서 정상 열람 가능해야 한다.
- 파일명에 날짜·유형·요약을 포함하여 사서가 파일 목록에서 즉시 식별할 수 있어야 한다.
- 생성 파일은 `/outputs/official_docs/YYYY/MM/` 경로 구조로 연월별 정리 저장한다.
- 에이전트 응답 언어: 한국어

---

## 10. 템플릿 추가·수정 절차

공문 양식이 변경되거나 신규 유형이 필요한 경우:

1. 사서가 한글에서 정상 열람 가능한 검증된 hwpx 샘플 파일을 `/templates/official_docs/[템플릿ID]_[문서명].hwpx`에 배치
2. 별도의 플레이스홀더 표시는 불필요 — `section0.xml`은 매 요청마다 FN-03 절차에 따라 새로 생성되어 교체되므로, 샘플 파일은 나머지 구조(header.xml, container.xml, settings.xml 등)의 원본으로만 사용된다
3. FN-01 템플릿 목록에 새 항목 등록 (에이전트 설정 파일 수정)
4. 이후 해당 유형 요청 시 자동 적용, 등록 전까지는 스킬 기본 샘플로 폴백
