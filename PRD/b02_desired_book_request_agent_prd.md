## 1. 개요

### 1.1 목적

B-02 희망도서 에이전트는 이용자가 신청한 희망도서를 매주 접수·검토하여 구입 적합 여부를 1차 판정하고, 구입 대상 목록을 B-01 수서 에이전트에 전달하는 리프 에이전트다. 이용자와 수서 업무 사이의 연결 고리 역할을 담당한다.

### 1.2 서비스 개요 (창녕도서관 기준)

| 항목 | 내용 |
|------|------|
| 신청 채널 | 도서관 홈페이지 (실운영) / Excel 직접 입력 (연구용) |
| 신청 한도 | 1인 월 3권까지 |
| 시리즈물 한도 | 월 3권 이내 |
| 작업 주기 | 매주 — 월~일 신청 건을 화요일에 선정/반려 결정 후 최대한 빠르게 구입 |

### 1.3 입력 채널 (연구용 vs 실운영)

| 구분 | 연구용 (현재) | 실운영 (전환 시) |
|------|-------------|----------------|
| 입력 방식 | 사서가 Excel에 직접 입력 | 도서관 홈페이지 폼 자동 수집 |
| 데이터 형태 | xlsx 파일 (지정 경로) | DB 또는 API 엔드포인트 |
| 에이전트 처리 로직 | 동일 | 동일 |
| 전환 시 변경 범위 | 입력 레이어만 교체 | 처리·출력 로직 유지 |

### 1.4 범위

- **포함:** 희망도서 신청 접수·목록화, 서지 정보 자동 보완, 반려 기준 1차 자동 판정, B-01에 주간 구입 대상 목록 전달, 처리 결과 이용자 안내 문구 생성, 월간 신청 현황 보고
- **제외:** 실제 구입 결정 (B-01·사서 담당), 구입 후 입고·정리 (B-04 담당), 이용자 계정 관리, 홈페이지 폼 직접 연동 (실운영 전환 시 구현)

## 5. 기능 요구사항

### FN-01 신청 접수 및 목록화

사서가 지정 경로의 Excel 파일을 에이전트에 전달하면 미처리 신규 행을 식별하여 SQLite `wish_requests` 테이블에 저장한다.

**`wish_requests` 테이블 저장 항목:**

| 필드 | 설명 |
|------|------|
| `request_id` | 자동 부여 ID |
| `week_key` | 신청 주차 (예: `2026-W20`) |
| `request_date` | 신청일 |
| `requester_name` | 신청자명 |
| `requester_contact` | 연락처 |
| `book_title` | 서명 |
| `author` | 저자 |
| `isbn` | ISBN |
| `publisher` | 출판사 |
| `reason` | 신청 사유 |
| `status` | 처리 상태 (`pending` / `approved` / `rejected` / `unverified`) |
| `reject_reason` | 반려 사유 코드 |
| `created_at` | 접수 일시 |

### FN-02 서지 정보 자동 보완 (네이버 책 검색 API + SEOJI, 2026-07-09 소스 교체)

ISBN 또는 서명을 기반으로 네이버 책 검색 API(1차)와 SEOJI(2차 검증)를 호출하여 서지 정보를 보완한다.

**처리 흐름:**

1. ISBN 있음 → 네이버 책 검색 API에 ISBN 쿼리 → 서명·저자·출판사·정가·출판일 조회 (KDC는 제공되지 않음, 아래 참고)
2. ISBN 없음 → 서명으로 네이버 책 검색 API 쿼리 → 1순위 결과 자동 매칭
3. 네이버 결과 없음/모호 → SEOJI로 2차 조회 시도
4. 매칭 실패 → `status: unverified` 플래그, 사서에게 수동 확인 요청
5. 보완된 서지 정보로 `wish_requests` 레코드 업데이트

**소스 전환에 따른 제약:**
- 네이버 책 검색 API에는 알라딘의 `stockStatus`(재고/절판)·`categoryName`/`mallType`(외국도서·전자책·DVD 구분)·KDC 분류 기호에 대응하는 필드가 없다. 이 필드들에 의존하던 FN-03 R-03·R-04·R-05·R-08 판정 방식은 아래와 같이 조정한다.
- 가격 정보(price/discount)가 모두 없는 응답은 "절판 의심"으로만 플래그하고 자동 반려하지 않는다.

### FN-03 반려 기준 1차 자동 판정

네이버 책 검색 API(및 SEOJI 보완) 응답과 기존 장서 DB 조회 결과를 바탕으로 아래 반려 기준을 순서대로 적용한다. 첫 번째 해당 조건에서 즉시 반려 처리하며 사유를 기록한다.

**반려 기준 (창녕도서관 확정 기준):**

| 순번 | 반려 사유 | 판정 방법 | 사유 코드 |
|------|----------|----------|----------|
| R-01 | 기소장·구입·정리 중인 자료 | **B-03 복본 에이전트 호출**(ISBN 완전일치 또는 제목+저자 유사도 판정, `PRD/b03_duplicate_check_agent_prd.md` FN-05 인터페이스) | `ALREADY_OWNED` |
| R-02 | 자격증 학습서·수험서·문제집 | 제목·KDC 키워드 패턴 매칭 | `STUDY_BOOK` |
| R-03 | 품절·절판 도서 | **(2026-07-09 변경)** 네이버 책 검색 API에 재고 상태 필드 없음 — price/discount 필드 모두 누락 시 "절판 의심"으로만 플래그, 자동 반려 대신 `MANUAL_REVIEW`로 사서 확인 요청 | `OUT_OF_PRINT`→`MANUAL_REVIEW`로 강등 |
| R-04 | 서양서·E-book·DVD·잡지 | **(2026-07-09 변경)** 네이버 책 검색 API에 카테고리/포맷 구분 필드 없음 — 제목·설명(description) 텍스트 키워드 패턴("전자책", "eBook" 등)으로 느슨하게 추정하되 확신도가 낮으면 `MANUAL_REVIEW` | `INELIGIBLE_FORMAT`→불확실 시 `MANUAL_REVIEW` |
| R-05 | 출판 후 5년 초과 자료 | 네이버 책 검색 API `pubdate` 기준 계산 (필드명만 변경, 로직 동일) | `TOO_OLD` |
| R-06 | 만화·무협·판타지·로맨스 (학습·우량 만화 제외) | KDC + 제목 키워드 패턴 | `ENTERTAINMENT` |
| R-07 | 문제풀이집·색칠공부·교구 포함 자료 | 제목 키워드 패턴 | `INAPPROPRIATE_FORM` |
| R-08 | 정가 5만원 이상 고가 전문 도서 | 네이버 책 검색 API `price` ≥ 50,000 (필드명만 변경, 로직 동일) | `HIGH_PRICE` |
| R-09 | 수량 많은 전집·시리즈 | 제목 패턴 + 시리즈물 월 3권 초과 여부 | `SERIES_LIMIT` |
| R-10 | 기타 장서기준 미부합 | 사서 수동 판단 필요 플래그 | `MANUAL_REVIEW` |
| R-11 (2026-07-09 신규) | 개인적 성향의 종교 관련 도서 | 제목·설명(description) 키워드 패턴(종교 경전·전도서 등) — 자동 확신도 낮으므로 `MANUAL_REVIEW` 권장 | `RELIGIOUS` |
| R-12 (2026-07-09 신규) | 스프링 제본 도서·소책자 등 일반 규격 외 자료 | 네이버/SEOJI 응답에 판형·제본 형태 필드 없음 — 자동판정 불가, `MANUAL_REVIEW` | `NONSTANDARD_FORMAT` |

**R-11·R-12 출처:** 자료개발 도메인의 실물 「2026년 자료 확충 계획」 문서(붙임, A-01 `ATT-006`)의 "희망도서 반려기준" 조항에서 확인한 기준으로, 기존 B-02 PRD의 R-01~R-10에는 누락되어 있었다. 두 항목 모두 서지 API로 자동 판정할 근거 필드가 없어 처음부터 `MANUAL_REVIEW`로 설계한다(R-03·R-04처럼 강등이 아니라 애초에 수동 확인 전제).

**자동 판정 불가 항목 처리:**
R-06(학습·우량 만화 예외), R-10(기타)은 에이전트가 `MANUAL_REVIEW` 플래그와 함께 사서에게 최종 판단을 요청한다. B-03이 `needs_review`(상세조사 필요)로 응답한 R-01 건도 동일하게 `MANUAL_REVIEW`로 분류하고 사서 확인 전까지 반려·승인을 확정하지 않는다. **(2026-07-09 추가)** R-03(절판 의심)·R-04(포맷 확신도 낮음) 건도 네이버 책 검색 API의 필드 한계로 자동 확정이 불가한 경우 동일하게 `MANUAL_REVIEW`로 분류한다 — 이 변경으로 사서의 수동 확인 대상 건수가 이전(알라딘 기준)보다 늘어날 수 있음을 감안한다.

**Human-in-the-loop 필수:** 자동 판정 결과는 사서 확인 후 확정된다. 에이전트는 판정 초안을 제공하며, 사서 승인 없이 B-01에 목록을 전달하지 않는다.

### FN-04 신청 한도 검증

동일 신청자의 당월 신청 이력을 조회하여 한도 초과 여부를 확인한다.

| 검증 항목 | 기준 | 처리 |
|----------|------|------|
| 1인 월 신청 한도 | 월 3권 초과 | 초과 건 반려 (사유: `MONTHLY_LIMIT`) |
| 시리즈물 월 신청 한도 | 시리즈물 월 3권 초과 | 초과 건 반려 (사유: `SERIES_LIMIT`) |
| 동일 도서 중복 신청 | 당월 동일 ISBN 기신청 | 기존 신청 건에 신청자 추가, 신청 수 합산 |

### FN-05 주간 처리 결과 보고 및 B-01 전달 (매주 화요일)

월~일 접수 건을 화요일에 일괄 검토하여 처리 결과를 확정하고 B-01에 구입 대상 목록을 전달한다.

**화요일 처리 흐름:**

```
1. 직전 주(월~일) 신청 건 취합
2. 자동 판정 결과 사서 확인 요청
3. MANUAL_REVIEW 항목 사서 최종 판단
4. 사서 승인 후 구입 대상 목록 확정
5. B-01 수서 에이전트에 목록 전달
6. 이용자 안내 문구 생성 (사서가 홈페이지·전화로 전달)
7. 주간 처리 현황 요약 보고
```

**B-01 전달 항목:**

| 필드 | 설명 |
|------|------|
| `book_title` | 서명 |
| `author` | 저자 |
| `isbn` | ISBN |
| `publisher` | 출판사 |
| `price` | 정가 |
| `kdc` | KDC 분류번호 |
| `request_count` | 해당 도서 신청자 수 (복수 신청 시 합산) |
| `reason_summary` | 신청 사유 요약 |

**주간 처리 현황 요약 보고 예시:**
```
[희망도서 주간 처리 현황 — 2026년 20주차 (5.4~5.10)]

총 신청: 12건
 · 구입 대상: 7건 → B-01 전달 완료
 · 소장/구입 중 (R-01): 2건
 · 절판 (R-03): 1건
 · 출판 5년 초과 (R-05): 1건
 · 수동 검토 필요: 1건 (사서 최종 판단 필요)

신청 한도 초과: 0건
이용자 안내 문구 생성: 4건 (반려 건)
```

### FN-06 이용자 안내 문구 생성

반려 건에 대해 사서가 이용자에게 전달할 안내 문구 초안을 생성한다. 사서가 직접 발송하며 에이전트는 초안만 제공한다.

**반려 안내 문구 예시 (절판):**
```
[창녕도서관 희망도서 신청 결과 안내]
안녕하세요, 홍길동 님.
신청하신 도서 『○○○』은 현재 절판 상태로 구입이 어렵습니다.
희망도서 신청에 감사드리며, 다른 도서로 다시 신청해 주시기 바랍니다.
창녕도서관 ☎ 055-532-9501
```

**반려 안내 문구 예시 (소장 중):**
```
[창녕도서관 희망도서 신청 결과 안내]
안녕하세요, 홍길동 님.
신청하신 도서 『○○○』은 이미 창녕도서관에 소장되어 있습니다.
홈페이지에서 소장 위치와 대출 가능 여부를 확인하실 수 있습니다.
창녕도서관 ☎ 055-532-9501
```

```

이용자 신청 → Excel 입력 (사서) → B-02: 접수·서지보완·자동판정

[매주 화요일]
B-02 → 사서: 자동판정 결과 + MANUAL_REVIEW 건 확인 요청

B-02 → B-01: 구입 대상 목록 전달
B-02 → 사서: 이용자 안내 문구 초안 생성
사서: 이용자에게 직접 통보

[매월 말]
B-02 → 사서: 월간 신청 현황 보고
```

## 7. MCP 도구 연동

| 도구 | 용도 |
|------|------|
| MCP Filesystem | Excel 신청 파일 읽기, 처리 결과 xlsx 출력 |
| MCP SQLite | 신청 이력·처리 결과·월간 한도 관리 |
| 네이버 책 검색 API | 서지 정보 1차 보완 — 정가·출판일 확인 (절판 여부는 가격 정보 누락으로만 약하게 추정) |
| NLK 서지정보유통지원시스템(SEOJI) | 네이버 검색 실패/모호 시 2차 검증 |
| B-03 복본 에이전트 | R-01(기소장·구입·정리 중) 판정 요청 및 결과 수신 |

## 8. Human-in-the-loop 정책

| 단계 | 사서 개입 여부 | 내용 |
|------|--------------|------|
| 신청 접수·서지 보완 | 불필요 | 자동 처리 |
| 자동 판정 (R-01~R-09) | **필수** | 판정 초안 확인·승인 |
| 수동 검토 항목 (R-06 예외·R-10) | **필수** | 사서 직접 판단 |
| B-01 목록 전달 | **필수** | 사서 승인 후 전달 |
| 이용자 안내 문구 발송 | **필수** | 사서가 직접 발송 |
| 월간 현황 보고 | 불필요 | 사서 요청 즉시 응답 |

## 9. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 네이버 책 검색 결과 다수 (서명 모호) | 상위 3건 후보 제시, 사서가 선택 |
| 네이버 책 검색 API 호출 실패 | SEOJI로 재조회 → 그래도 실패 시 재시도 3회 후 `unverified` 플래그, 사서에게 수동 확인 요청 |
| B-03 응답 없음/오류 | R-01 판정 보류, `MANUAL_REVIEW` 플래그로 사서 위임 |
| Excel 파일 형식 오류 | 오류 위치 특정 후 사서에게 수정 요청 |
| 신청자 연락처 없음 | 안내 문구 생성하되 전달 방법은 사서 판단 |
| 화요일 사서 부재 | 처리 보류, 익일 사서 복귀 시 처리 |
