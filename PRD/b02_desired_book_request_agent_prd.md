**문서 버전:** 1.0  
**작성일:** 2026-05-11  
**소속 도메인:** D1 장서  
**에이전트 ID:** B-02  
**에이전트 유형:** Leaf Agent  
**참조 아키텍처:** 창녕도서관 사서 AI 에이전트 시스템 v3

---

## 1. 개요

### 1.1 목적

B-02 희망도서 에이전트는 이용자가 신청한 희망도서를 매주 접수·검토하여 구입 적합 여부를 1차 판정하고, 구입 대상 목록을 B-01 수서 에이전트에 전달하는 리프 에이전트다. 이용자와 수서 업무 사이의 연결 고리 역할을 담당한다.

### 1.2 서비스 개요 (창녕도서관 기준)

| 항목 | 내용 |
|------|------|
| 신청 채널 | 도서관 홈페이지 (실운영) / Excel 직접 입력 (연구용) |
| 신청 한도 | 1인 월 3권까지 |
| 시리즈물 한도 | 월 3권 이내 |
| 작업 주기 | 매주 — 월~일 신청 건을 화요일에 선정/반려 결정 후 최대한 빠르게 구입 |

### 1.3 입력 채널 (연구용 vs 실운영)

| 구분 | 연구용 (현재) | 실운영 (전환 시) |
|------|-------------|----------------|
| 입력 방식 | 사서가 Excel에 직접 입력 | 도서관 홈페이지 폼 자동 수집 |
| 데이터 형태 | xlsx 파일 (지정 경로) | DB 또는 API 엔드포인트 |
| 에이전트 처리 로직 | 동일 | 동일 |
| 전환 시 변경 범위 | 입력 레이어만 교체 | 처리·출력 로직 유지 |

### 1.4 범위

- **포함:** 희망도서 신청 접수·목록화, 서지 정보 자동 보완, 반려 기준 1차 자동 판정, B-01에 주간 구입 대상 목록 전달, 처리 결과 이용자 안내 문구 생성, 월간 신청 현황 보고
- **제외:** 실제 구입 결정 (B-01·사서 담당), 구입 후 입고·정리 (B-04 담당), 이용자 계정 관리, 홈페이지 폼 직접 연동 (실운영 전환 시 구현)

## 5. 기능 요구사항

### F-01 신청 접수 및 목록화

사서가 지정 경로의 Excel 파일을 에이전트에 전달하면 미처리 신규 행을 식별하여 SQLite `wish_requests` 테이블에 저장한다.

**`wish_requests` 테이블 저장 항목:**

| 필드 | 설명 |
|------|------|
| `request_id` | 자동 부여 ID |
| `week_key` | 신청 주차 (예: `2026-W20`) |
| `request_date` | 신청일 |
| `requester_name` | 신청자명 |
| `requester_contact` | 연락처 |
| `book_title` | 서명 |
| `author` | 저자 |
| `isbn` | ISBN |
| `publisher` | 출판사 |
| `reason` | 신청 사유 |
| `status` | 처리 상태 (`pending` / `approved` / `rejected` / `unverified`) |
| `reject_reason` | 반려 사유 코드 |
| `created_at` | 접수 일시 |

---

### F-02 서지 정보 자동 보완 (Aladin API)

ISBN 또는 서명을 기반으로 Aladin API를 호출하여 서지 정보를 보완한다.

**처리 흐름:**

1. ISBN 있음 → Aladin ItemLookUp API로 서명·저자·출판사·정가·출판일·KDC 조회
2. ISBN 없음 → 서명으로 ItemSearch → 1순위 결과 자동 매칭
3. 매칭 실패 → `status: unverified` 플래그, 사서에게 수동 확인 요청
4. 보완된 서지 정보로 `wish_requests` 레코드 업데이트

**`aladin_book_lookup.py` 스킬과 동일한 API 연동 방식 적용 (urllib 기반, SSL verify=False 기관망 환경 대응)**

---

### F-03 반려 기준 1차 자동 판정

Aladin API 응답 및 기존 장서 DB 조회 결과를 바탕으로 아래 반려 기준을 순서대로 적용한다. 첫 번째 해당 조건에서 즉시 반려 처리하며 사유를 기록한다.

**반려 기준 (창녕도서관 확정 기준):**

| 순번 | 반려 사유 | 판정 방법 | 사유 코드 |
|------|----------|----------|----------|
| R-01 | 기소장·구입·정리 중인 자료 | 장서 DB ISBN 조회 | `ALREADY_OWNED` |
| R-02 | 자격증 학습서·수험서·문제집 | 제목·KDC 키워드 패턴 매칭 | `STUDY_BOOK` |
| R-03 | 품절·절판 도서 | Aladin API `stockStatus` 확인 | `OUT_OF_PRINT` |
| R-04 | 서양서·E-book·DVD·잡지 | Aladin `categoryName` / `mallType` 확인 | `INELIGIBLE_FORMAT` |
| R-05 | 출판 후 5년 초과 자료 | Aladin `pubDate` 기준 계산 | `TOO_OLD` |
| R-06 | 만화·무협·판타지·로맨스 (학습·우량 만화 제외) | KDC + 제목 키워드 패턴 | `ENTERTAINMENT` |
| R-07 | 문제풀이집·색칠공부·교구 포함 자료 | 제목 키워드 패턴 | `INAPPROPRIATE_FORM` |
| R-08 | 정가 5만원 이상 고가 전문 도서 | Aladin `priceStandard` ≥ 50,000 | `HIGH_PRICE` |
| R-09 | 수량 많은 전집·시리즈 | 제목 패턴 + 시리즈물 월 3권 초과 여부 | `SERIES_LIMIT` |
| R-10 | 기타 장서기준 미부합 | 사서 수동 판단 필요 플래그 | `MANUAL_REVIEW` |

**자동 판정 불가 항목 처리:**
R-06(학습·우량 만화 예외), R-10(기타)은 에이전트가 `MANUAL_REVIEW` 플래그와 함께 사서에게 최종 판단을 요청한다.

**Human-in-the-loop 필수:** 자동 판정 결과는 사서 확인 후 확정된다. 에이전트는 판정 초안을 제공하며, 사서 승인 없이 B-01에 목록을 전달하지 않는다.

---

### F-04 신청 한도 검증

동일 신청자의 당월 신청 이력을 조회하여 한도 초과 여부를 확인한다.

| 검증 항목 | 기준 | 처리 |
|----------|------|------|
| 1인 월 신청 한도 | 월 3권 초과 | 초과 건 반려 (사유: `MONTHLY_LIMIT`) |
| 시리즈물 월 신청 한도 | 시리즈물 월 3권 초과 | 초과 건 반려 (사유: `SERIES_LIMIT`) |
| 동일 도서 중복 신청 | 당월 동일 ISBN 기신청 | 기존 신청 건에 신청자 추가, 신청 수 합산 |

---

### F-05 주간 처리 결과 보고 및 B-01 전달 (매주 화요일)

월~일 접수 건을 화요일에 일괄 검토하여 처리 결과를 확정하고 B-01에 구입 대상 목록을 전달한다.

**화요일 처리 흐름:**

```
1. 직전 주(월~일) 신청 건 취합
2. 자동 판정 결과 사서 확인 요청
3. MANUAL_REVIEW 항목 사서 최종 판단
4. 사서 승인 후 구입 대상 목록 확정
5. B-01 수서 에이전트에 목록 전달
6. 이용자 안내 문구 생성 (사서가 홈페이지·전화로 전달)
7. 주간 처리 현황 요약 보고
```

**B-01 전달 항목:**

| 필드 | 설명 |
|------|------|
| `book_title` | 서명 |
| `author` | 저자 |
| `isbn` | ISBN |
| `publisher` | 출판사 |
| `price` | 정가 |
| `kdc` | KDC 분류번호 |
| `request_count` | 해당 도서 신청자 수 (복수 신청 시 합산) |
| `reason_summary` | 신청 사유 요약 |

**주간 처리 현황 요약 보고 예시:**
```
[희망도서 주간 처리 현황 — 2026년 20주차 (5.4~5.10)]

총 신청: 12건
 · 구입 대상: 7건 → B-01 전달 완료
 · 소장/구입 중 (R-01): 2건
 · 절판 (R-03): 1건
 · 출판 5년 초과 (R-05): 1건
 · 수동 검토 필요: 1건 (사서 최종 판단 필요)

신청 한도 초과: 0건
이용자 안내 문구 생성: 4건 (반려 건)
```

### F-06 이용자 안내 문구 생성

반려 건에 대해 사서가 이용자에게 전달할 안내 문구 초안을 생성한다. 사서가 직접 발송하며 에이전트는 초안만 제공한다.

**반려 안내 문구 예시 (절판):**
```
[창녕도서관 희망도서 신청 결과 안내]
안녕하세요, 홍길동 님.
신청하신 도서 『○○○』은 현재 절판 상태로 구입이 어렵습니다.
희망도서 신청에 감사드리며, 다른 도서로 다시 신청해 주시기 바랍니다.
창녕도서관 ☎ 055-532-9501
```

**반려 안내 문구 예시 (소장 중):**
```
[창녕도서관 희망도서 신청 결과 안내]
안녕하세요, 홍길동 님.
신청하신 도서 『○○○』은 이미 창녕도서관에 소장되어 있습니다.
홈페이지에서 소장 위치와 대출 가능 여부를 확인하실 수 있습니다.
창녕도서관 ☎ 055-532-9501
```

### F-07 월간 신청 현황 보고

매월 말 또는 사서 요청 시 해당 월 전체 희망도서 신청 현황을 요약 보고한다.

**보고 항목:** 총 신청 건수, 구입 확정 건수, 반려 사유별 건수, 신청 한도 초과 건수, 신청자 수, 가장 많이 신청된 도서

## 9. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| Aladin 검색 결과 다수 (서명 모호) | 상위 3건 후보 제시, 사서가 선택 |
| Aladin API 호출 실패 | 재시도 3회 후 `unverified` 플래그, 사서에게 수동 확인 요청 |
| 장서 DB 미확정 | R-01 소장 확인 생략, `MANUAL_REVIEW` 플래그로 사서 위임 |
| Excel 파일 형식 오류 | 오류 위치 특정 후 사서에게 수정 요청 |
| 신청자 연락처 없음 | 안내 문구 생성하되 전달 방법은 사서 판단 |
| 화요일 사서 부재 | 처리 보류, 익일 사서 복귀 시 처리 |
