# PRD — DM-01 장서 도메인 에이전트 (Collection Domain Agent)

**문서 버전:** 1.0
**작성일:** 2026-07-07
**소속 도메인:** D1 장서 (총괄)
**에이전트 ID:** DM-01
**에이전트 유형:** 도메인 에이전트 (최상위 오케스트레이터와 D1 리프 에이전트 사이의 중간 관리 계층)
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3

---

> **표기 안내:** 이 문서의 `FN-01`, `FN-02`... 는 DM-01 내부 기능 번호다. `B-01`~`B-06`은 D1 장서 도메인의 리프 에이전트를 가리키는 실제 참조다.

---

## 1. 개요

### 1.1 목적

DM-01 장서 도메인 에이전트는 D1 장서 도메인(B-01 수서, B-02 희망도서, B-03 복본, B-04-H 자료조직 하네스, B-05 균형, B-06 점검)을 총괄하는 중간 관리 계층이다. 최상위 오케스트레이터로부터 장서 정책 지시를 받아 해당 리프에 분배하고, 각 리프의 월간 실적을 취합해 통합 결과보고서를 생성한 뒤 A-02의 표준 데이터 수집 요청에 응답한다.

### 1.2 리프-투-리프 직접 협업과의 관계 (중요)

**DM-01은 D1 리프 간 기존 직접 협업 호출에 개입하지 않는다.** B-01이 B-03(복본 판정)·B-05(균형 결핍지수)를 호출하는 것, B-02가 B-03을 호출하는 것, B-04-H가 B-04-W를 순차 호출하는 것은 지금처럼 리프끼리 직접 처리한다. DM-01이 관여하는 것은 오직 ①최상위 정책 지시의 하향 분배와 ②정기 실적 취합·보고뿐이다.

### 1.3 범위

- **포함:** 최상위 지시 수신·분배(FN-01), 계획서 초안 생성·전달(FN-02, 월간/주간/특별 공통), B-01·B-02·B-03·B-04-H·B-06 월간 실적 데이터 수신·검증(FN-03), A-03 자료구입비 예산 집행 현황 조회(FN-04), 월간 통합 결과보고서 hwpx 초안 생성(FN-05), A-02 표준 데이터 수집 응답(FN-06), 연간 누계 보고(FN-07)
- **제외:** 각 리프의 개별 운영 업무, 리프 간 직접 협업 호출의 중계(B-01↔B-03/B-05, B-02↔B-03, B-04-H↔B-04-W 등), 결과보고서 실제 제출·결재(사서 담당), 예산 집행 결정(A-03 담당), 최고관리자에게 직접 확인·승인을 요청하는 것(단일 접점 원칙 위반 — 반드시 escalations로 chief-coordinator를 경유)

## 2. 시스템 내 위치

```
[chief-coordinator] ⇄ DM-01 ← 이 문서
                          │ 지시 분배, 계획 조회 요청     ↑ 월간 실적 수신, 계획 응답
                          ↓                  │
     [B-01 수서] [B-02 희망도서] [B-03 복본] [B-04-H 자료조직] [B-05 균형] [B-06 점검]
        (리프 간 직접 협업은 그대로 유지 — B-01↔B-03/B-05, B-02↔B-03, B-04-H↔B-04-W)

DM-01 → A-03: 자료구입비 예산 집행 현황 조회
DM-01 → A-01: 통합 결과보고서 hwpx 초안 생성 요청
DM-01 → A-02: 표준 데이터 수집 요청 응답 (A-02는 이제 B-01~B-06 개별이 아니라 DM-01에만 요청)
chief-coordinator → DM-01: 계획서 조회 요청(월간/특별) — DM-01은 초안만 취합해 전달, hwpx 생성은 chief-coordinator가 A-01 호출
```

## 3. 기능 요구사항

### FN-01 최상위 지시 수신 및 분배

chief-coordinator로부터 장서 정책 지시(예: "희망도서 신청 요건을 강화해라", "이번 분기 KDC 300번대 확충에 집중해라")를 수신해 대상 리프(B-01~B-06 중 하나 이상)에 전달한다. 모호하면 확인 질문 후 배분하며, 배분 결과를 상위에 보고한다.

---

### FN-02 계획서 초안 생성 및 최상위 전달 (월간/주간/특별 공통)

chief-coordinator의 월간·주간·특별 계획 조회 요청에 응답한다. **DM-01이 직접 새 계획을 만들어내는 것이 아니라, 각 리프가 이미 보유·확정한 계획을 취합해 도메인 수준 요약으로 편집한다.** `scope: "weekly"`인 경우 매주 발생하는 B-02 희망도서 처리 주기가 핵심 소스가 된다.

**요청 (chief-coordinator → DM-01):**
```json
{ "requester_agent": "chief-coordinator", "request_type": "plan_request", "scope": "monthly", "target_period": "2026-08" }
```
(`"scope": "weekly"`, `"target_period": "2026-W30"` 형식도 동일하게 처리)

**처리 절차:**
1. 대상 기간에 계획을 보유할 가능성이 있는 리프를 식별한다 — 주로 B-01(신간 후보 선정·예산 배정 진행 상황), B-06(정기 장서점검 일정, 해당 시즌에만).
2. 해당 리프에 보유 중인 계획 정보를 조회한다(리프가 새로 계획을 수립하도록 지시하는 것이 아니라 이미 있는 정보를 취합).
3. 리프 응답을 도메인 수준으로 편집·요약한다. 여러 리프의 계획이 상충하거나 중복되면 원본 그대로 병기하고 임의로 조정하지 않는다.
4. `plan_summary`로 chief-coordinator에 응답한다.

**응답 (DM-01 → chief-coordinator):**
```json
{
  "agent_id": "DM-01",
  "agent_name": "장서 도메인 에이전트",
  "scope": "monthly",
  "period": "2026-08",
  "has_plan": true,
  "plan_summary": "8월 수서: 신간 후보 50건 선정 진행 중(B-01), 예산 700만원 배정 예정. 정기 장서점검 없음.",
  "source_leaf": ["B-01"],
  "status": "complete",
  "escalations": [
    { "item": "B-03 상세조사 필요 2건(유사도 83%) — 복본/신규 최종 판단 필요", "urgency": "normal", "source_leaf": "B-03" }
  ]
}
```

**계획이 없는 월(수서는 상시 운영이라 "특별 계획"이 없는 달이 흔함):** `"has_plan": false, "status": "unavailable"`로 응답한다 — 오류가 아니다.

**`escalations`(선택 필드):** 리프 단계 판단 필요 사안을 담는다. DM-01은 사서/최고관리자에게 직접 확인을 요청하지 않는다 — `urgency: "normal"`은 다음 정기 계획서/보고서에 포함되고, `urgency: "urgent"`는 chief-coordinator에 즉시 신호를 보내 수시 미니 노트 발행을 요청한다.

> DM-01은 이 계획 초안에 대해 hwpx 문서를 직접 생성하지 않는다 — chief-coordinator가 5개 도메인 응답을 통합 계획서 한 편으로 편집할 때 A-01을 호출한다.

### FN-03 D1 리프 에이전트 실적 데이터 수신 및 검증

매월 초 각 리프에 해당 월 실적 데이터를 요청한다.

**공통 요청 구조 (DM-01 → 각 리프):**
```json
{ "requester_agent": "DM-01", "request_type": "monthly_result", "target_period": "2026-06" }
```

**소스별 필수 응답 항목:**

| 소스 | 필수 항목 |
|------|---------|
| B-01 수서 | 신간 후보 수집 건수, 최종 선정 건수, 집행 예정 금액 |
| B-02 희망도서 | 주간 신청 건수 누계, 구입 확정 건수, 반려 사유별 건수 |
| B-03 복본 | 복본 판정 건수, 상세조사 필요 건수, 추가구입 권고 건수 (기존 B-03 PRD FN-06 형식 그대로 수신, `requester_agent`만 `DM-01`로 변경) |
| B-04-H 자료조직 | 자료조직 완료 건수, QA 재작업 건수, QA 실패 건수 (기존 B-04-H PRD FN-05 형식 그대로 수신) |
| B-06 점검 | 점검 대상 장서 수, 결본 확정 건수, 폐기 심의 상정 건수(점검 시즌에만 해당, 평시 `unavailable`) |

B-05(균형)는 상시 실적이 아니라 온디맨드 조회 도구이므로 월간 실적 대상에서 제외하되, 사서 요청 시 최신 결핍지수 요약을 결과보고서에 참고 자료로 첨부할 수 있다.

**검증 실패 시:** 누락·형식 오류 항목을 목록화해 해당 리프에 1회 재요청한다. 재요청 후에도 미해소면 사서에게 직접 묻지 않고 `escalations`(`urgency: "normal"`)로 표시해 chief-coordinator 응답에 포함한다. 해당 월 활동 없음(`unavailable`)은 정상 처리한다.

### FN-04 예산 집행 현황 조회 (A-03 호출)

A-03에서 해당 월 자료구입비(도서구입비) 편성액·집행액·잔액·집행률을 조회한다.

---

### FN-05 월간 통합 결과보고서 초안 생성 (A-01 호출)

FN-03·FN-04 데이터를 통합해 hwpx 초안을 생성한다.

**결과보고서 구성:** ①운영 개요 ②수서 실적(표) ③희망도서 처리 현황(표) ④복본 판정 현황(표) ⑤자료조직 처리 현황(표) ⑥점검 현황(해당 시) ⑦예산 집행 현황(표) ⑧성과 및 개선사항(개조식, 예: 희망도서 반려율 급증 시 기준 재검토 제언)

> ⚠️ **Human-in-the-loop:** DM-01은 이 초안을 사서/최고관리자에게 직접 결재 요청하지 않는다 — chief-coordinator에게 전달하며, 최종 검토·확정은 chief-coordinator의 통합 보고서 채널을 통해서만 이루어진다.

## 4. Human-in-the-loop 정책

| 단계 | 인간 개입 여부 | 내용 |
|------|--------------|------|
| 상위 지시 분배(FN-01) | 불필요(모호할 때만 chief-coordinator에 확인 질문) | 자동 분배 |
| 계획서 취합·전달(FN-02, 월간/주간/특별) | 불필요 | 리프가 이미 확정한 계획을 편집만 함 |
| 리프 데이터 수신·검증(FN-03) | 불필요(DM-01은 인간에 직접 개입시키지 않음) | 자동 처리, 지속 실패 시 escalation으로 chief-coordinator에 전달 |
| 예산 조회(FN-04) | 불필요 | 자동 처리 |
| 결과보고서 초안 생성(FN-05) | 불필요 | 자동 생성 후 chief-coordinator에게 전달 |
| 결과보고서 최종 검토·확정 | **필수 — chief-coordinator 경유로만** | chief-coordinator의 통합 보고서를 통해 최고관리자가 확인 |
| A-02 응답(FN-06) | 불필요 | 요청 즉시 자동 응답 |
| 연간 누계 보고(FN-07) | 불필요 | 자동 생성 또는 chief-coordinator 요청 즉시 응답 |
| escalations 발신 | 해당 없음(DM-01이 인간에게 직접 접촉하지 않음) | 판단 필요 사안은 escalations로 chief-coordinator에만 전달 |

## 6. 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 일부 리프 데이터 필수 항목 누락 | 누락 항목 목록화 후 해당 리프 1회 재확인 요청, 지속 미해소 시 escalation으로 chief-coordinator에 전달 |
| 특정 리프 해당 월 활동 없음 | `unavailable` 처리, 보고서에 "해당 없음" 표기 |
| A-03 예산 데이터 조회 실패 | 예산 항목 공란 처리 후 escalation(`urgency: "normal"`)으로 chief-coordinator에 전달 |
| 상위 지시 대상 리프 불명확 | 임의 배분하지 않고 chief-coordinator에 명확화 질문 |

## 9. 미결 사항 (Open Questions)
