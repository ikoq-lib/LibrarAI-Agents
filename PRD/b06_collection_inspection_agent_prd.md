# PRD — B-06 점검 에이전트 (Collection Inspection Agent)

**문서 버전:** 1.0
**작성일:** 2026-07-07
**소속 도메인:** D1 장서
**에이전트 ID:** B-06
**에이전트 유형:** Leaf Agent

---

## 1. 개요

### 1.1 목적

B-06 점검 에이전트는 공공도서관의 정기 장서점검(정수조사) 업무를 지원한다. 점검 대상·기간 계획 수립, 바코드 스캔 결과와 소장 DB 대조를 통한 결본·훼손 판정, 폐기 심의 자료 목록 작성, 점검 결과 보고 공문 초안 생성까지를 다룬다. 실제 서가 스캔 작업과 폐기 최종 결정은 사서(및 폐기심의위원회)의 몫이다.

### 1.2 배경

공공도서관은 정기적으로 장서점검(정수조사)을 실시해 결본(분실 추정 자료)과 훼손 자료를 파악하고, 그 결과를 근거로 폐기 심의 자료를 마련해야 한다. 점검 대상 자료가 많을수록 스캔 결과와 소장 DB를 수작업으로 대조하는 데 상당한 시간이 소요된다. B-06은 이 대조·분류·문서화 과정을 자동화하되, 결본 최종 확정과 폐기 여부는 항상 사서·심의위원회가 결정하도록 한다.

> **B-06 점검 vs B-01 수서 역할 구분**
> B-01은 신규 도서를 들이는 업무를, B-06은 기존 소장 장서의 현황을 점검하고 폐기 후보를 가려내는 업무를 담당한다. 폐기로 결정된 자료의 공석을 채우는 신규 수서가 필요하면 사서가 별도로 B-01에 요청한다.

### 1.3 범위

- **포함:** 점검 계획(대상 자료실·기간) 수립, 바코드 스캔 결과 업로드·DB 대조, 결본/훼손/정상 분류, 폐기 후보 산정, 점검 결과 보고 공문 초안(A-01 호출), 폐기 심의 자료 목록 생성
- **제외:** 실제 서가 바코드 스캔 작업(사서 물리적 수행), 결본 최종 확정 및 폐기 여부 결정(사서·폐기심의위원회 고유 권한), 폐기 처분 실행(사서), 폐기로 발생한 공석 보충 수서(B-01 담당)

## 2. 업무 흐름 (Workflow)

```
[점검 시작]
사서 → B-06: 점검 계획 요청 (대상 자료실, 점검 기간)
B-06: inspection_batch 생성 (FN-01)

[스캔 진행 후]
사서 → B-06: 바코드 스캔 결과 업로드 (엑셀)
B-06: 소장 DB 대조 → 정상/미확인 분류 (FN-02)

[미확인 자료 처리]
B-06: 과거 점검 이력 조회 → 최초 미확인은 "재확인 대상"으로, 연속 미확인은 "결본(안)"으로 분류 (FN-03)
사서: 결본(안) 최종 확정 [Human-in-the-loop]

[훼손 자료 처리]
사서 → B-06: 훼손 확인 자료 목록 입력
B-06: 폐기 후보 등록 (FN-04)

[결과 정리]
B-06 → 사서: 폐기 심의 자료 목록 (FN-05)
B-06 → A-01: 점검 결과 보고 공문 초안 요청 (FN-06)
사서: 검토·결재 [Human-in-the-loop]
```

## 3. 기능 요구사항

### FN-01 점검 계획 수립

사서 요청에 따라 점검 대상과 기간을 확정하고 `inspection_batch`를 생성한다.

**확인 항목:** 점검 대상 자료실(전체 또는 일부), 점검 기간(시작일~종료일), 점검 사유(정기/특별)

기관별 점검 주기(예: 연 1회, 격년 등)는 Config로 주입하며 하드코딩하지 않는다.

---

### FN-02 스캔 결과 업로드·DB 대조

사서가 업로드한 바코드 스캔 결과 엑셀을 소장 DB와 대조한다.

**업로드 항목(예상):** 바코드/등록번호, 스캔 일시, 스캔 자료실

**대조 결과 분류:** `scanned`(스캔 확인됨, 정상) / `not_found`(이번 점검에서 미확인) / `not_in_db`(스캔되었으나 소장 DB에 없음 — 등록 오류 가능성, 사서 확인 요청)

엑셀 파싱 실패 행은 목록화하여 사서에게 재업로드를 요청한다.

---

### FN-03 결본(안) 판정

미확인(`not_found`) 자료를 과거 점검 이력과 비교해 분류한다.

**판정 규칙(Config로 기관별 조정 가능, 기본값 예시):**
- 이번 점검이 최초 미확인: `재확인 대상`으로 분류, 결본 확정하지 않음
- 직전 점검에서도 미확인(연속 2회 이상): `결본(안)`으로 분류해 사서 확인 요청
- 재확인 대상 기간 내 대출·반납 이력이 확인되면 자동으로 `정상`으로 복귀

> ⚠️ **Human-in-the-loop:** 결본 최종 확정은 사서가 결정한다. B-06은 결본(안) 후보만 제시한다.

---

### FN-04 훼손 자료 폐기 후보 산정

사서가 입력한 훼손 확인 자료를 `disposal_candidates`에 등록한다.

**폐기 후보 등록 사유 유형:** `lost`(결본 확정), `damaged`(훼손), `long_term_no_loan`(장기 미대출, 사서가 별도 판단 시)

각 후보에는 사유·근거(최종 대출일, 훼손 정도 등)를 함께 기록한다.

---

### FN-05 폐기 심의 자료 목록 생성

폐기 후보 전체를 심의위원회 제출용 형식으로 정리한다.

**출력 형식:**
```
[폐기 심의 대상 목록 — 점검 배치: 2026-XX]
| 등록번호 | 서명 | 저자 | 청구기호 | 폐기 사유 | 최종 대출일 |
|---------|------|------|---------|----------|-----------|
```

**(2026-07-09 신규) 심의 주체 확인:** 자료개발 도메인 실물 문서 학습 결과, 「경상남도교육청 창녕도서관 운영규정」 제2장 제2절 제16조의 **자료심의위원회**(B-01이 정기구입 심의를 위해 연동하는 그 위원회, `b01_acquisition_agent_prd.md` FN-06 참조)가 자료 폐기 심의도 함께 담당함을 확인했다. 즉 B-06의 "폐기심의위원회"는 별도 조직이 아니라 **B-01이 이미 연동 중인 자료심의위원회와 동일 조직**이다. B-06은 폐기 후보 목록을 이 위원회에 상정하기 위해 B-01에 위원회 개최를 요청(또는 B-01의 정기구입 심의와 동일 회차에 병합 상정)하는 방식으로 FN-05를 재설계할 필요가 있다 — 아래 9장 미결 사항 2번 갱신 참조.

**(2026-07-09 신규) 폐기 규모 참고 기준:** 실물 「자료 확충 계획」 문서(A-01 `ATT-006`)에 따르면 자료 폐기·제적 기준은 **총장서량의 7% 이내**로 관리된다. FN-05 목록 생성 시 이 상한 대비 현재 폐기 후보 비율을 함께 표시하면 사서 판단에 참고가 된다(자동 상한 적용은 아님 — 최종 판단은 사서·위원회).

> ⚠️ **Human-in-the-loop:** 폐기 여부의 최종 결정은 자료심의위원회·사서가 한다. B-06은 목록만 준비한다.

---

### FN-06 점검 결과 보고 공문 생성 (A-01 호출)

점검 종료 후 A-01 공문서 에이전트에 결과 보고 공문 초안을 요청한다.

**포함 항목:** 점검 기간, 점검 대상(자료실·장서 수), 정상/재확인 대상/결본(안)/폐기 후보 건수 및 비율, 향후 조치 계획(재확인 일정, 폐기 심의 상정 여부)

> ⚠️ **Human-in-the-loop:** 사서 검토·수정 후 결재 상신한다.

---

### FN-07 연간 점검 통계 제공 (A-02 연계)

A-02 최상위이관 에이전트의 표준 데이터 수집 요청 시 다음 형식으로 응답한다.

```json
{
  "agent_id": "B-06",
  "period": "2026",
  "metrics": [
    { "metric_name": "점검 대상 장서 수", "value": 0, "unit": "권" },
    { "metric_name": "결본 확정 건수", "value": 0, "unit": "건" },
    { "metric_name": "폐기 심의 상정 건수", "value": 0, "unit": "건" }
  ],
  "status": "complete"
}
```

사서 개입 없이 자동으로 응답한다.

## 7. 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 스캔 결과에 소장 DB에 없는 바코드 존재 | `not_in_db`로 분류, 등록 오류 가능성 안내 후 사서 확인 요청 |
| 최초 점검(과거 이력 없음) | 모든 미확인 자료를 `재확인 대상`으로만 분류, 결본(안) 판정 보류 |
| 재확인 기간 중 대출 이력 발견 | 자동으로 `정상` 복귀, 결본(안) 대상에서 제외 |
| 훼손 여부 판단 불가 | 사서 육안 확인을 요청하고, 확인 전까지 폐기 후보에 등록하지 않음 |

## 8. 수용 기준 (Acceptance Criteria)

- **AC1**: 스캔 결과 업로드 후 소장 DB와 대조하여 정상/미확인/미등록을 자동 분류한다.
- **AC2**: 연속 미확인 자료만 결본(안)으로 분류하고, 최초 미확인 자료는 재확인 대상으로 별도 관리한다.
- **AC3**: 사서 승인 없이는 어떤 자료도 최종 결본·폐기로 확정되지 않는다.
- **AC4**: 점검 종료 후 결본·폐기 후보 건수를 포함한 보고 공문 초안이 A-01을 통해 생성된다.
- **AC5**: A-02 요청 시 연간 점검 통계가 표준 형식으로 자동 응답된다.

## 9. 미결 사항 (Open Questions)

1. **결본 확정 판정 규칙의 기관별 기준**: "연속 2회 미확인 시 결본(안)" 기준이 기관 실무 관행과 일치하는지 확인 필요.
2. **(2026-07-09 갱신) 폐기심의위원회 운영 방식과의 연계**: 2026-07-09 실물 문서 학습으로 "폐기심의위원회"가 F-02 운영위원회가 아니라 **B-01의 자료심의위원회와 동일 조직**임이 확인되었다. 남은 미결 사항은 (a) B-06이 B-01을 직접 호출해 위원회 개최를 요청하는 인터페이스 설계, (b) 정기구입 심의와 폐기 심의를 같은 회차에 병합 상정할지 별도 회차로 분리할지 결정.
3. **장기 미대출 자료의 폐기 후보 편입 기준**: 몇 년 이상 미대출 시 폐기 후보로 자동 제안할지(현재는 사서 판단에만 의존), 기준 확정 시 FN-04에 자동화 규칙 추가 검토.
4. **(2026-07-09 신규) 폐기·제적 상한(총장서량 7%) 관리 주체**: 이 상한을 B-06이 관리할지(점검마다 누적 추적), 자료심의위원회 사무국(B-01 연동)이 관리할지 결정 필요 — 중복 관리로 인한 불일치 방지.
