# PRD — DM-03 독서문화 도메인 에이전트 (Reading Culture Domain Agent)

**문서 버전:** 1.0
**작성일:** 2026-07-07
**소속 도메인:** D3 독서문화 (총괄)
**에이전트 ID:** DM-03
**에이전트 유형:** 도메인 에이전트 (최상위 오케스트레이터와 D3 리프 에이전트 사이의 중간 관리 계층)
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3

---

> **표기 안내:** 이 문서의 `FN-01`, `FN-02`... 는 DM-03 내부 기능 번호다. `D-01`~`D-06`은 D3 독서문화 도메인의 리프 에이전트, `chief-coordinator`는 최상위 오케스트레이터를 가리키는 실제 에이전트 참조다.
>
> **D-05 폐지 통합:** 본 PRD의 FN-02~FN-06은 폐지된 `PRD/d05_result_report_agent_prd.md`(D-05 결과보고 에이전트)의 기능을 그대로 흡수·이관한 것이다. 세부 로직(검증 기준, 보고서 표 구성, 자동 생성 문구 조건 등)은 D-05 PRD와 동일하며, 여기에 FN-01(상위 지시 분배)이 신규로 추가되었다.

## 1. 개요

### 1.1 목적

DM-03 독서문화 도메인 에이전트는 D3 독서문화 도메인(D-01 동아리, D-02 행사기획, D-03 강사공모, D-06 순회문고)을 총괄하는 중간 관리 계층이다. 최상위 오케스트레이터(chief-coordinator)로부터 정책·기획 지시를 받아 해당 리프 에이전트에 분배하고, 각 리프의 운영 실적을 매월 취합해 통합 결과보고서를 생성한 뒤 A-02 최상위이관 에이전트의 표준 데이터 수집 요청에 응답한다.

### 1.2 배경

기존에는 D-05 결과보고 에이전트가 D3 리프 4개(D-01·D-02·D-03·D-06)의 월간 실적을 취합해 A-02에 응답하는 역할을 리프 에이전트 신분으로 수행했다. 최상위 오케스트레이터 산하에 도메인 에이전트 계층(DM-01~DM-05)을 도입하면서, 이 "실적 취합·보고" 역할이 도메인 에이전트의 기본 책무로 재정의되었다. D-05가 이미 정확히 이 역할을 하고 있었으므로, 별도 리프로 유지하지 않고 DM-03 안으로 완전히 흡수했다(D-05는 결번 처리).

### 1.3 리프-투-리프 직접 협업과의 관계 (중요)

**DM-03은 D3 리프 에이전트 간의 기존 직접 협업 호출에 개입하지 않는다.** 예를 들어 D-01이 D-03에 강사 요건을 전달하거나, D-01이 A-01을 호출해 hwpx 문서를 생성하는 것은 지금처럼 리프끼리 직접 처리한다. DM-03이 관여하는 것은 오직 다음 두 가지뿐이다:
- **하향(top-down):** 최상위의 정책/기획 지시를 받아 어느 리프가 처리할지 배분
- **상향(bottom-up):** 정기(월간·연간) 실적 취합과 보고서 생성

일상적인 리프 간 실무 협업은 도메인 에이전트를 거치지 않고 지금처럼 직접 이루어진다.

### 1.4 범위

- **포함:** 최상위 지시 수신·분배(FN-01), 계획서 초안 생성·전달(FN-02), D-01·D-02·D-03·D-06 월간 실적 데이터 수신·검증(FN-03), A-03 예산 집행 현황 조회(FN-04), 월간 통합 결과보고서 hwpx 초안 생성(FN-05), D-02 행사기획 피드백(FN-06), A-02 표준 데이터 수집 응답(FN-07), 연간 누계 보고(FN-08)
- **제외:** 각 리프 에이전트의 개별 운영 업무(D-01·D-02·D-03·D-06 담당), 리프 간 직접 협업 호출의 중계, 결과보고서 실제 제출·결재(사서 직접 처리), 예산 집행 결정(A-03 담당)

## 3. 기능 요구사항

### FN-01 최상위 지시 수신 및 분배

chief-coordinator로부터 D3 독서문화 관련 정책·기획 지시를 수신하여 해당 리프 에이전트에 전달한다.

**처리 절차:**
1. 지시 내용을 분석해 대상 리프(D-01~D-03, D-06 중 하나 이상)를 식별
2. 여러 리프에 걸친 지시는 각 리프가 이해할 수 있는 형태로 분해해 전달
3. 지시가 모호하면 chief-coordinator에 명확화 질문
4. 전달 완료 후 어느 리프에 어떤 내용을 전달했는지 chief-coordinator에 확인 보고

**예시:** "독서동아리 신청 방식을 온라인 우선으로 바꿔라" → D-01에 전달, 반영 여부 확인 후 상위 보고.

> ⚠️ 이 지시 분배는 실무 협업 호출(리프 간 직접 호출)과 무관하다 — DM-03은 리프가 서로를 부르는 것에는 관여하지 않는다.

---

### FN-02 계획서 초안 생성 및 최상위 전달

chief-coordinator의 월간·특별 계획 조회 요청에 응답한다. **DM-03이 직접 새 계획을 만들어내는 것이 아니라, 각 리프가 이미 보유·확정한 계획을 취합해 도메인 수준 요약으로 편집한다.** D3는 5개 도메인 중 계획 취합 대상이 가장 뚜렷하다 — D-02 행사기획이 이미 매월 사서 확정을 거친 "다음 달 행사 기획안"(주제·6개 행사 구성)을 보유하고 있기 때문이다.

**요청 (chief-coordinator → DM-03):**
```json
{ "requester_agent": "chief-coordinator", "request_type": "plan_request", "scope": "monthly", "target_period": "2026-08" }
```

**처리 절차:**
1. D-02에 해당 월 확정 행사 기획안을 조회한다(사서 확정본만 — 아직 후보 단계인 초안은 제외).
2. D-01에 해당 월 예정 동아리 회차·신규 모집 계획을, D-03에 진행 중인 강사공모 일정을, D-06에 해당 월 배치·회수 예정을 조회한다(각 도메인 보유 정보 그대로, 새로 계획을 세우도록 지시하지 않음).
3. 리프 응답을 도메인 수준으로 편집·요약한다. 여러 리프의 계획이 상충하거나 중복되면 원본 그대로 병기하고 임의로 조정하지 않는다.

**응답 (DM-03 → chief-coordinator):**
```json
{
  "agent_id": "DM-03",
  "agent_name": "독서문화 도메인 에이전트",
  "scope": "monthly",
  "period": "2026-08",
  "has_plan": true,
  "plan_summary": "8월 행사 6건 확정(어린이 북큐레이션 1·성인 북큐레이션 1·참여형 4), 독서동아리 정기 모임 2건, 강사공모 진행 중 1건(체험형 행사용).",
  "source_leaf": ["D-02", "D-01", "D-03"],
  "status": "complete"
}
```

해당 월에 D-02 확정 기획안이 아직 없으면(사서 확정 전 단계) `"has_plan": false, "status": "unavailable"`로 응답하며, 이는 오류가 아니다.

> DM-03은 이 계획 초안에 대해 hwpx 문서를 직접 생성하지 않는다 — chief-coordinator가 5개 도메인 응답을 통합 계획서 한 편으로 편집할 때 A-01을 호출한다.

### FN-03 D3 리프 에이전트 실적 데이터 수신 및 검증

매월 초 D-01·D-02·D-03·D-06에 해당 월 실적 데이터를 요청하고, 응답을 필수 항목 기준으로 검증한다. (D-05 PRD FN-01과 동일)

**공통 요청 구조 (DM-03 → 각 리프):**
```json
{ "requester_agent": "DM-03", "request_type": "monthly_result", "target_period": "2026-06" }
```

**소스별 필수 응답 항목:**

| 소스 | 필수 항목 |
|------|---------|
| D-01 동아리 | 동아리별 계획/실시 회차, 총 참여자 수, 평균 출석률 (D-01 PRD FN-07 표준 형식) |
| D-02 행사기획 | 행사별 명칭·유형·대상·정원·실참여 인원·모집충족률 |
| D-03 강사공모 | 섭외 시도 건수, 성사 건수, 성사율, 강사비 합계 |
| D-06 순회문고 | 당월 배치·회수 건수, 배치 도서 수, 이용 기관 수 (D-06 PRD FN-07) |

**검증 실패 시:** 누락·형식 오류 항목을 목록화해 사서에게 해당 리프 재확인 요청. `status: unavailable`(해당 월 활동 없음)은 정상 처리하며 보고서에 "해당 없음"으로 표기한다.

---

### FN-04 예산 집행 현황 조회 (A-03 호출)

A-03에서 해당 월 독서문화 관련 예산(동아리 운영비, 행사 재료비·강사비, 순회문고 운영비 등) 집행 현황을 조회한다. 항목별 편성액·집행액·잔액·집행률, 도메인간 유용 발생 건수·금액(해당 시)을 포함한다.

---

### FN-05 월간 통합 결과보고서 초안 생성 (A-01 호출)

FN-03·FN-04에서 취합한 데이터를 통합해 결과보고서 hwpx 초안을 생성한다. (D-05 PRD FN-03과 동일 구성)

**결과보고서 구성:** ①운영 개요 ②행사 운영 실적(표) ③독서동아리 운영 현황(표) ④강사공모 현황(표) ⑤순회문고 운영 현황(표) ⑥예산 집행 현황(표) ⑦성과 및 개선사항(개조식)

**성과·개선사항 자동 생성 기준(Config로 조정 가능):** 모집충족률 90%↑/60%↓, 강사공모 성사율 80%↑/50%↓, 동아리 평균 출석률 70%↓ 등 — 상세 기준·문구 템플릿은 D-05 PRD FN-03을 그대로 따른다.

> ⚠️ **Human-in-the-loop 필수:** 초안 생성 후 사서 검토·수정·결재 후 사용.

---

### FN-06 D-02 행사기획 피드백

결과보고서 사서 확정 후 행사별 실적 데이터를 D-02에 전달해 다음 달 기획에 참고하도록 한다(D-05 PRD FN-04와 동일 전달 형식). 전달은 보고서 확정 직후 자동 실행되며, D-02는 참고용으로만 활용한다.

---

### FN-07 A-02 표준 데이터 수집 응답

A-02 최상위이관 에이전트의 정기 데이터 수집 요청에 표준 구조로 응답한다.

```json
{
  "agent_id": "DM-03",
  "agent_name": "독서문화 도메인 에이전트",
  "period": "2026-06",
  "metrics": [
    { "metric_name": "행사 개최 건수", "value": 6, "unit": "건" },
    { "metric_name": "행사 총 참여자 수", "value": 92, "unit": "명" },
    { "metric_name": "동아리 평균 출석률", "value": 88.3, "unit": "%" },
    { "metric_name": "강사공모 성사율", "value": 75.0, "unit": "%" }
  ],
  "notes": "6월 통합 결과보고서 확정 완료",
  "status": "complete"
}
```

**중요 변경:** A-02는 이제 D-01~D-06에 개별적으로 요청하지 않고 DM-03 1곳에만 요청한다(`a02_top_level_relay_agent_prd.md` 갱신 반영).

---

### FN-08 연간 누계 보고 (연말 요청 시)

사서 요청 또는 12월 말 자동 트리거 시 연간 12개월 실적을 취합해 연간 결과 요약을 생성한다(D-05 PRD FN-06과 동일 구성: 월별 행사 현황, 연간 최고/개선 필요 행사 유형, 동아리·순회문고 연간 요약, 연간 예산 집행 요약, 차기 연도 기획 제언).

## 4. 데이터 흐름

```
[상위 지시 발생 시]
chief-coordinator → DM-03: 정책/기획 지시
DM-03 → 대상 리프: 지시 분배 (FN-01)
DM-03 → chief-coordinator: 분배 결과 확인 보고

[월말 또는 특별 행사 준비 시]
chief-coordinator → DM-03: 계획서 조회 요청 (FN-02)
DM-03 → D-01·D-02·D-03·D-06: 보유 계획 정보 조회
DM-03 → chief-coordinator: 계획 응답 (or unavailable)

[매월 초]
DM-03 → D-01·D-02·D-03·D-06: 전월 실적 데이터 요청 (FN-03)
DM-03 → A-03: 전월 예산 집행 현황 조회 (FN-04)
DM-03 → A-01: 통합 결과보고서 hwpx 초안 생성 요청 (FN-05)
DM-03 → 사서: 초안 전달 → 사서 검토·결재
DM-03 → D-02: 확정 후 실적 피드백 (FN-06)

[월간·연간 통계 수집 시]
A-02 → DM-03: 데이터 수집 요청
DM-03 → A-02: 표준 실적 데이터 응답 (FN-07)

[연말]
자동 트리거 또는 사서 요청 → DM-03: 연간 누계 보고 생성 (FN-08)
```

## 5. Human-in-the-loop 정책

| 단계 | 사서 개입 여부 | 내용 |
|------|--------------|------|
| 상위 지시 분배(FN-01) | 불필요(모호할 때만 확인 질문) | 자동 분배, 결과만 상위 보고 |

## 8. 비기능 요구사항

- 월간 결과보고서는 매월 익월 5영업일 이내 초안 생성을 목표로 한다.
- 자동 생성 기준값(모집충족률·성사율 등)은 Config에서 조정 가능하다.

- SQLite 데이터는 연도 단위로 보존하며 삭제하지 않는다.
- 응답 언어: 한국어
