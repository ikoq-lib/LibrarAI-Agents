# PRD — F-02 협력기관 에이전트 (Partner Relations Agent)

**문서 버전:** 1.0
**작성일:** 2026-07-04
**소속 도메인:** D5 홍보협력
**에이전트 ID:** F-02
**에이전트 유형:** Leaf Agent
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3

> **표기 안내:** 이 문서의 `FN-01`, `FN-02`... 는 에이전트 내부 기능(Function) 번호이며, 에이전트 ID인 F-01(SNS)·F-03(공모)·F-04(소식지)와는 무관하다. F 도메인은 에이전트 ID 접두어와 기능 번호 접두어가 같아 혼동될 수 있어 `FN-` 접두어로 구분한다. (F-03 PRD에서 도입한 규칙과 동일)

---

## 1. 개요

### 1.1 목적

F-02 협력기관 에이전트는 도서관의 대외 관계 관리를 담당하는 리프 에이전트다. 성격이 다른 세 유형의 이해관계자를 다룬다.

1. **협력기관** — 학교·복지관·문화재단·기업 등 도서관과 업무협약(MOU)을 맺거나 자원을 연계하는 기관
2. **지역구 의원** — 소속 지자체 시·군의회 의원 등 도서관 예산·정책에 영향을 미치는 대외 인사
3. **운영위원회** — 도서관 운영위원회 위원 및 정기 회의 운영

세 유형 모두 "관계를 꾸준히 관리해야 하지만 반복 업무가 많다"는 공통점이 있어 하나의 에이전트로 통합 설계한다.

### 1.2 배경

도서관은 예산 확보, 정책 지지, 프로그램 협력을 위해 다양한 외부 이해관계자와 지속적인 관계를 유지해야 한다. 그러나 이 관계 관리 업무는 성격상 흩어져 있다.

| 이해관계자 | 반복 업무 | 문제점 |
|-----------|---------|-------|
| 협력기관 | MOU 체결·갱신, 협력 내용 관리 | 협약 만료를 놓치거나 협력 이력이 개인 기억에 의존 |
| 지역구 의원 | 행사 초청, 자료 요구 대응, 정기 소식 안내 | 의원 대응 이력이 체계적으로 관리되지 않음 |
| 운영위원회 | 위원 명단 관리, 회의 안건·회의록 작성 | 회의마다 문서를 처음부터 작성, 위원 임기 관리 누락 우려 |

F-02는 이 세 이해관계자 그룹에 대한 최소한의 구조화된 관리(등록·이력·알림)와 반복 문서 작성(A-01 연계)을 자동화하여 이 번거로움을 줄인다.

### 1.3 다른 에이전트와의 구분

| 에이전트 | 관계 성격 | 비고 |
|---------|---------|------|
| **F-02 (이 문서)** | 포괄적 대외 관계 — MOU·의원·운영위 | 프로그램 운영이 아닌 관계 자체가 목적 |
| D-01 동아리 (outreach 유형) | 특정 기관에 독서동아리를 파견하는 프로그램 운영 | 관계가 아닌 프로그램 운영이 목적 |
| D-06 순회문고 | 도서 배치 대상 기관 관리 | 관계가 아닌 도서 배치 운영이 목적 |

동일 기관이 D-01·D-06과 F-02에 중복 등록될 수 있다 (예: 같은 유치원이 순회문고 배치 대상이면서 MOU 협약 기관일 수 있음). F-02는 기관명 기준으로 중복 여부를 확인하되, 각 에이전트의 DB는 목적이 다르므로 통합하지 않고 별도 유지한다.

### 1.4 범위

- **포함:** 협력기관 정보·MOU 이력 관리, MOU 만료 알림, 지역구 의원 명단 및 소통 이력 관리, 의원 대상 안내·초청 문서 지원(A-01 연계), 운영위원회 위원 관리, 회의 안건·회의록 초안 작성 지원(A-01 연계), 협력기관 프로그램 연계 요청의 도메인 에이전트 전달
- **제외:** MOU 실제 체결·날인 (사서·기관장 직접 처리), 의원 개별 민원 응대 실질 내용 판단 (사서 직접 처리), 운영위원회 심의·의결 (위원회 고유 권한), 순회문고·동아리 파견 등 실제 프로그램 운영 (D-01·D-06 담당)

## 4. 기능 요구사항

### FN-01 협력기관 정보 및 MOU 이력 관리

협력기관 정보를 `partner_institutions` 테이블에, MOU 이력을 `mou_records` 테이블에 등록·관리한다.

**`partner_institutions` 저장 항목:**

| 필드 | 설명 |
|------|------|
| `institution_id` | 자동 부여 ID |
| `name` | 기관명 |
| `type` | 기관 유형 (`학교`/`복지관`/`문화재단`/`기업`/`시민단체`/`기타`) |
| `contact_name`·`contact_phone`·`contact_email` | 담당자 정보 |
| `cooperation_area` | 협력 분야 (예: 도서 기증, 강사 파견, 시설 공유 등) |
| `status` | `active`/`inactive` |
| `memo` | 특이사항 |

**`mou_records` 저장 항목:**

| 필드 | 설명 |
|------|------|
| `mou_id` | 자동 부여 ID |
| `institution_id` | 연결 기관 ID |
| `signed_date` | 체결일 |
| `expiry_date` | 만료일 (갱신 주기 있는 경우) |
| `cooperation_content` | 협약 내용 요약 |
| `status` | `active`/`expired`/`renewing` |

**만료 임박 알림:** 만료 D-30 기준으로 사서에게 갱신 여부 확인을 요청한다 (Config로 조정 가능).

---

### FN-02 지역구 의원 명단 및 소통 이력 관리

지역구 의원 명단과 소통 이력을 `council_members`·`council_interactions` 테이블로 관리한다.

**`council_members` 저장 항목:** `member_id`, `name`, `affiliation`(소속 위원회 등), `contact`, `term_start`·`term_end`(임기), `memo`

**`council_interactions` 저장 항목:** `interaction_id`, `member_id`, `date`, `type`(`행사 초청`/`자료 요구 대응`/`정기 소식 안내`/`방문`/`기타`), `summary`, `follow_up_needed`(불리언)

**자료 요구 대응 지원:** 의원 또는 의회 사무국의 자료 요구가 있을 경우, 관련 도메인 에이전트(A-02·A-03·A-04 등)에서 필요한 통계·현황 자료를 취합하도록 사서에게 안내하고, 취합된 내용을 답변 문서 초안 형태로 정리한다.

> ⚠️ **Human-in-the-loop 필수:** 의원 대상 소통 문서는 반드시 사서·도서관장 검토 후 발송한다. 에이전트가 직접 발송하지 않으며, 응답 내용의 정치적·정책적 판단은 하지 않는다.

---

### FN-03 지역구 의원 대상 문서 지원 (A-01 호출)

행사 초청장, 정기 소식 안내문, 자료 요구 답변서 등 의원 대상 문서의 hwpx 초안을 A-01 공문서 에이전트를 호출하여 생성한다.

**A-01 호출 입력 구성:** 문서 유형(초청/안내/답변), 수신 의원명, 행사·안건 개요, 첨부 필요 자료 목록

**Human-in-the-loop 필수:** 초안 생성 후 사서·도서관장 검토·수정 후 발송한다.

---

### FN-04 운영위원회 위원 관리

운영위원회 위원 명단과 임기를 `committee_members` 테이블로 관리한다.

**저장 항목:** `member_id`, `name`, `role`(위원장/위원 등), `affiliation`, `term_start`·`term_end`, `contact`

**임기 만료 알림:** 임기 만료 D-30 기준으로 사서에게 위촉 갱신 또는 신규 위원 선임 필요 여부를 안내한다.

---

### FN-05 운영위원회 회의 지원 (A-01 호출)

회의 일정이 확정되면 안건자료 초안을, 회의 종료 후에는 회의록 초안을 A-01을 호출하여 생성한다.

**안건자료 구성:** 회의 차수, 일시·장소, 참석 위원, 안건 목록(제목·배경·상정 사유), 참고 자료

**회의록 구성:** 회의 차수, 일시·장소, 참석·불참 위원, 안건별 논의 내용 요약, 의결 사항, 차기 회의 일정(안)

**Human-in-the-loop 필수:** 안건자료·회의록 모두 사서가 실제 회의 내용을 확인·보완한 후 확정한다. 에이전트는 회의에 참석하지 않으므로 논의 내용은 사서가 입력한 요약을 기반으로 정리만 수행한다.

---

### FN-06 협력기관 프로그램 연계 요청 처리

협력기관이 도서관과의 프로그램 협력(강연, 전시, 공동 행사 등)을 제안하거나, 반대로 도서관이 협력기관에 프로그램 연계를 요청하는 경우를 처리한다.

**처리 흐름:**
1. 요청 내용(제안 기관, 프로그램 성격, 희망 시기, 필요 자원) 확인
2. 성격에 맞는 도메인 에이전트 안내 (예: 독서문화 행사 성격 → D-02 행사기획, 평생학습 강좌 성격 → E-01 강좌기획)
3. 사서 확인 후 해당 도메인 에이전트에 연계 정보 전달

**전달 형식 (예시, D-02 대상):**
```json
{
  "requester_agent": "F-02",
  "institution_name": "○○문화재단",
  "proposal_summary": "지역 작가 초청 강연 공동 개최 제안",
  "preferred_period": "2026-09",
  "required_resources": "강의실 1, 장비 지원 요청"
}
```

> ⚠️ 실제 프로그램 기획·운영 여부는 전달받은 도메인 에이전트와 사서가 결정한다. F-02는 정보 전달까지만 담당한다.

## 5. 데이터 흐름

```
[협력기관 관리]
사서 → F-02: 협력기관 정보 또는 MOU 체결 내용 입력
F-02: partner_institutions·mou_records 저장
F-02: 만료 D-30 도래 시 → 사서 알림

[지역구 의원 소통]
사서 → F-02: 소통 이력 또는 자료 요구 내용 입력
F-02: council_interactions 저장, 필요 시 관련 에이전트에 자료 취합 안내
F-02 → A-01: 문서 초안 생성 요청 (해당 시)
A-01 → F-02 → 사서: 초안 전달 → 검토·발송

[운영위원회 지원]
사서 → F-02: 회의 일정 확정 또는 회의 종료 후 요약 입력
F-02 → A-01: 안건자료 또는 회의록 hwpx 초안 생성 요청
A-01 → F-02 → 사서: 초안 전달 → 검토·확정
F-02: 위원 임기 만료 D-30 도래 시 → 사서 알림

[프로그램 연계 요청]
협력기관 또는 도서관 → F-02: 연계 제안·요청 내용 전달
F-02: 성격 판단 → 해당 도메인 에이전트 안내
사서 확인 후 → F-02: 해당 에이전트에 정보 전달

[월간·연간 통계 수집 시]
A-02 → F-02: 데이터 수집 요청
F-02 → A-02: 표준 실적 데이터 응답
```

| 안건자료·회의록 확정 | **필수** | 사서가 실제 내용 확인·보완 후 확정 |
| 프로그램 연계 요청 전달 | **필수** | 사서 확인 후 해당 에이전트에 전달 |
| A-02 데이터 수집 응답 | 불필요 | 요청 즉시 자동 응답 |

---

## 8. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| MOU 만료 알림 무응답 | 재알림 1회 후 `expired` 상태로 자동 전환, 사서에게 안내 |
| 협력기관 중복 등록 (D-01·D-06과 기관명 중복) | 중복 가능성 안내만 하고 별도 유지 (목적이 다른 DB이므로 병합하지 않음) |
| 의원 자료 요구 내용에 정책적 판단 필요 | 사실 관계·통계 정리까지만 지원, 정책적 답변 내용은 사서·도서관장이 직접 작성 |
| 운영위원회 회의 내용 미입력 | 안건자료만 생성, 회의록은 사서 요약 입력 후 생성 |
| 프로그램 연계 요청의 도메인 판단 모호 | 후보 도메인 에이전트 복수 제시 후 사서 확인 요청 |

## 9. 비기능 요구사항

- MOU·위원 임기 만료 알림 기준일(D-30)은 Config에서 조정 가능하다.
- 협력기관 유형·의원 소통 유형 등 분류값은 Config로 관리하며 기관별로 조정 가능하다.
- SQLite 데이터는 연도 단위로 보존하며 삭제하지 않는다.
- 에이전트 응답 언어: 한국어
