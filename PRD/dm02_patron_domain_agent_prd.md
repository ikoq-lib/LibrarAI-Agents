# PRD — DM-02 이용자 도메인 에이전트 (Patron Services Domain Agent)

**문서 버전:** 1.0
**작성일:** 2026-07-07
**소속 도메인:** D2 이용자 (총괄)
**에이전트 ID:** DM-02
**에이전트 유형:** 도메인 에이전트 (최상위 오케스트레이터와 D2 리프 에이전트 사이의 중간 관리 계층)
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3

---

> **표기 안내:** 이 문서의 `FN-01`, `FN-02`... 는 DM-02 내부 기능 번호다. `C-01`~`C-06`은 D2 이용자 도메인의 리프 에이전트를 가리키는 실제 참조다.

---

## 1. 개요

### 1.1 목적

DM-02 이용자 도메인 에이전트는 D2 이용자 도메인(C-01 FAQ, C-02 추천, C-03 프로그램안내, C-04 상호대차, C-05 외부도서서비스, C-06 만족도)을 총괄하는 중간 관리 계층이다. 최상위 오케스트레이터로부터 이용자 서비스 정책 지시를 받아 해당 리프에 분배하고, 각 리프의 월간 실적을 취합해 통합 결과보고서를 생성한 뒤 A-02의 표준 데이터 수집 요청에 응답한다.

### 1.2 리프-투-리프 직접 협업과의 관계 (중요)

**DM-02는 D2 리프 간 기존 직접 협업 호출에 개입하지 않는다.** C-01이 개인화 추천 질문을 C-02로 라우팅하는 것, C-03이 D-01·D-02·D-06·E-01·E-03을 실시간 조회하는 것, D-05·E-05(폐지 후 DM-03·DM-04)가 만족도 조사를 C-06에 요청하는 것은 지금처럼 리프끼리 직접 처리한다. DM-02는 ①최상위 정책 지시의 하향 분배와 ②정기 실적 취합·보고에만 관여한다.

### 1.3 범위

- **포함:** 최상위 지시 수신·분배(FN-01), 계획서 초안 생성·전달(FN-02, 월간/주간/특별 공통), C-01~C-06 월간 실적 데이터 수신·검증(FN-03), 관련 예산 집행 현황 조회(FN-04, 해당하는 경우), 월간 통합 결과보고서 hwpx 초안 생성(FN-05), A-02 표준 데이터 수집 응답(FN-06), 연간 누계 보고(FN-07)
- **제외:** 각 리프의 개별 운영 업무, 리프 간 직접 협업 호출의 중계(C-01↔C-02, C-03↔D/E 도메인 실시간 조회 등), 결과보고서 실제 제출·결재(사서 담당), 최고관리자에게 직접 확인·승인을 요청하는 것(단일 접점 원칙 위반 — 반드시 escalations로 chief-coordinator를 경유)

```
   [C-01 FAQ] [C-02 추천] [C-03 프로그램안내] [C-04 상호대차] [C-05 외부도서서비스] [C-06 만족도]

```

## 3. 기능 요구사항

### FN-01 최상위 지시 수신 및 분배

chief-coordinator로부터 이용자 서비스 정책 지시(예: "상호대차 연간 한도를 조정해라", "만족도 조사 문항을 개편해라")를 수신해 대상 리프(C-01~C-06 중 하나 이상)에 전달한다. 모호하면 확인 질문 후 배분하며, 결과를 상위에 보고한다.

---

### FN-02 계획서 초안 생성 및 최상위 전달 (월간/주간/특별 공통)

chief-coordinator의 월간·주간·특별 계획 조회 요청에 응답한다. **DM-02가 직접 새 계획을 만들어내는 것이 아니라, 각 리프가 이미 보유·확정한 계획을 취합해 도메인 수준 요약으로 편집한다.**

**요청 (chief-coordinator → DM-02):**
```json
{ "requester_agent": "chief-coordinator", "request_type": "plan_request", "scope": "monthly", "target_period": "2026-08" }
```
(`"scope": "weekly"`, `"target_period": "2026-W30"` 형식도 동일하게 처리 — D2는 주간 단위도 `unavailable`이 흔함)

**처리 절차:**
1. D2 이용자 도메인은 대부분 상시 운영(FAQ 응대, 추천, 상호대차 처리 등) 성격이라 "월간 계획"이 뚜렷한 경우가 드물다. 계획성 활동이 있는 리프(예: C-06의 신규 설문 문항 개편 예정, C-04/C-05의 정책 변경 예정)를 우선 확인한다.
2. 해당 리프에 보유 중인 계획 정보를 조회한다.
3. 리프 응답을 도메인 수준으로 편집·요약한다.

**응답 (DM-02 → chief-coordinator):**
```json
{
  "agent_id": "DM-02",
  "agent_name": "이용자 도메인 에이전트",
  "scope": "monthly",
  "period": "2026-08",
  "has_plan": false,
  "plan_summary": null,
  "source_leaf": [],
  "status": "unavailable"
}
```

**계획 없음이 정상 상태:** D2는 계획성 활동이 없는 달이 흔하므로 `"has_plan": false, "status": "unavailable"` 응답이 기본값에 가깝다 — 오류가 아니다.

**`escalations`(선택 필드):** 리프 단계 판단 필요 사안이 있으면 이 배열에 담아 올린다. DM-02는 사서/최고관리자에게 직접 확인을 요청하지 않는다 — `urgency: "normal"`은 다음 정기 계획서/보고서에, `urgency: "urgent"`는 chief-coordinator에 즉시 신호를 보낸다.

> DM-02는 이 계획 초안에 대해 hwpx 문서를 직접 생성하지 않는다 — chief-coordinator가 5개 도메인 응답을 통합 계획서 한 편으로 편집할 때 A-01을 호출한다.

---

### FN-03 D2 리프 에이전트 실적 데이터 수신 및 검증

매월 초 각 리프에 해당 월 실적 데이터를 요청한다.

**공통 요청 구조 (DM-02 → 각 리프):**
```json
{ "requester_agent": "DM-02", "request_type": "monthly_result", "target_period": "2026-06" }
```

**소스별 필수 응답 항목:**

| 소스 | 필수 항목 |
|------|---------|
| C-01 FAQ | 응답 건수, 미답변 질의 건수(신규 FAQ 후보) |
| C-02 추천 | 추천 요청 건수(개인화/비개인화), 대출 통계 최근 업로드일 |
| C-03 프로그램안내 | 조회 건수, 소스 미응답 발생 빈도 |
| C-04 상호대차 | 신청 처리 건수(inbound/outbound), 미수령·기한초과 건수 |
| C-05 외부도서서비스 | 서비스별(책나래·책바다·택배대출) 처리 건수 |
| C-06 만족도 | 상시 설문 응답 수, 평균 만족도 점수, 표본 부족 경고 건수 |

**검증 실패 시:** 누락·형식 오류 항목을 목록화해 해당 리프에 1회 재요청한다. 지속 미해소 시 사서에게 직접 묻지 않고 `escalations`(`urgency: "normal"`)로 표시해 chief-coordinator 응답에 포함한다.

---

### FN-04 관련 예산 집행 현황 조회 (A-03 호출, 해당 시)

D2 도메인은 직접적인 사업 예산이 크지 않으나(대부분 이용자 부담 또는 무료 서비스), 상호대차 관련 소모품비 등 해당 예산이 있으면 A-03에서 조회해 보고서에 반영한다. 해당 예산이 없으면 이 항목은 생략한다.

---

### FN-05 월간 통합 결과보고서 초안 생성 (A-01 호출)

FN-03·FN-04 데이터를 통합해 hwpx 초안을 생성한다.

**결과보고서 구성:** ①운영 개요 ②FAQ 응대 현황(표) ③추천 서비스 이용 현황(표) ④상호대차 처리 현황(표) ⑤외부도서서비스 처리 현황(표) ⑥만족도 조사 결과(표, 표본 부족 경고 포함) ⑦성과 및 개선사항(개조식, 예: 미답변 질의 급증 시 지식베이스 보강 제언)

> ⚠️ **Human-in-the-loop:** DM-02는 이 초안을 사서/최고관리자에게 직접 결재 요청하지 않는다 — chief-coordinator에게 전달하며, 최종 검토·확정은 chief-coordinator의 통합 보고서 채널을 통해서만 이루어진다.

---

### FN-06 A-02 표준 데이터 수집 응답

```json
{
  "agent_id": "DM-02",
  "agent_name": "이용자 도메인 에이전트",
  "period": "2026-06",
  "metrics": [
    { "metric_name": "FAQ 응대 건수", "value": 0, "unit": "건" },
    { "metric_name": "상호대차 처리 건수", "value": 0, "unit": "건" },
    { "metric_name": "외부도서서비스 처리 건수", "value": 0, "unit": "건" },
    { "metric_name": "평균 만족도", "value": 0.0, "unit": "점" }
  ],
  "status": "complete"
}
```

**중요 변경:** A-02는 이제 C-01~C-06에 개별적으로 요청하지 않고 DM-02 1곳에만 요청한다(`a02_top_level_relay_agent_prd.md` 갱신 반영).

---

### FN-07 연간 누계 보고 (연말 요청 시)

연간 12개월 실적을 취합해 연간 결과 요약(FAQ 응대·추천·상호대차·외부도서서비스 연간 누계, 연간 평균 만족도 추이, 차기 연도 이용자 서비스 개선 제언)을 생성한다.

## 4. Human-in-the-loop 정책

| 단계 | 인간 개입 여부 | 내용 |
|------|--------------|------|
| 상위 지시 분배(FN-01) | 불필요(모호할 때만 chief-coordinator에 확인 질문) | 자동 분배 |
| 계획서 취합·전달(FN-02, 월간/주간/특별) | 불필요 | 리프가 이미 확정한 계획을 편집만 함 |
| 리프 데이터 수신·검증(FN-03) | 불필요(DM-02는 인간에 직접 개입시키지 않음) | 자동 처리, 지속 실패 시 escalation으로 chief-coordinator에 전달 |
| 결과보고서 초안 생성(FN-05) | 불필요 | 자동 생성 후 chief-coordinator에게 전달 |
| 결과보고서 최종 검토·확정 | **필수 — chief-coordinator 경유로만** | chief-coordinator의 통합 보고서를 통해 최고관리자가 확인 |
| A-02 응답(FN-06) | 불필요 | 요청 즉시 자동 응답 |
| 연간 누계 보고(FN-07) | 불필요 | 자동 생성 또는 chief-coordinator 요청 즉시 응답 |
| escalations 발신 | 해당 없음(DM-02가 인간에게 직접 접촉하지 않음) | 판단 필요 사안은 escalations로 chief-coordinator에만 전달 |

## 7. 비기능 요구사항

- 월간 결과보고서는 익월 5영업일 이내 초안 생성을 목표로 한다.
- A-02 응답 데이터 형식은 A-02 PRD의 표준 응답 구조와 완전히 일치해야 한다.
- SQLite 데이터는 연도 단위로 보존하며 삭제하지 않는다.
- 응답 언어: 한국어
