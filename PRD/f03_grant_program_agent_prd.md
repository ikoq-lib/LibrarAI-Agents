# PRD — F-03 공모 에이전트 (Grant Program Agent)

**문서 버전:** 1.0
**작성일:** 2026-07-04
**소속 도메인:** D5 홍보협력
**에이전트 ID:** F-03
**에이전트 유형:** Leaf Agent
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3

---

## 1. 개요

### 1.1 목적

F-03 공모 에이전트는 도서관 예산 확충과 특색 프로그램 운영을 위한 외부 공모사업(지원사업) 정보를 수집·관리하고, 신청 준비를 지원하는 리프 에이전트다. 공모사업 정보는 두 가지 경로로 F-03에 유입된다.

1. **능동 탐색:** F-03이 웹 검색으로 지자체·교육청·문화체육관광부·도서관 관련 기관의 공모 공고를 상시 탐색
2. **접수 공문 등록:** 사서가 이미 공문으로 접수한 공모사업 안내를 F-03에 알려주면, 그 내용을 F-03이 구조화하여 등록·관리

두 경로로 모인 공모사업을 하나의 목록으로 통합 관리하며, 신청 요건 분석, 마감 일정 알림, 신청서 초안 작성 지원, 선정 결과 추적까지 전 과정을 지원한다.

### 1.2 배경

도서관에 필요한 외부 재원의 상당수는 사서가 직접 찾아야 하는 공모사업이지만, 실제로는 **상급기관(교육청 등)이 공문으로 직접 안내하는 공모사업도 매우 많다.** 이 두 유형은 성격이 다르다.

| 구분 | 특징 |
|------|------|
| 능동 탐색형 | 사서가 놓치기 쉬움 — 여러 기관 홈페이지·게시판을 일일이 확인해야 발견 가능 |
| 공문 접수형 | 이미 도서관에 전달되었으나, 접수 후 별도 시스템으로 관리되지 않아 검토·신청 여부 판단이 누락되거나 마감을 놓치는 경우 발생 |

기존 설계(F-01 SNS, F-04 소식지)는 도서관 실적을 대외에 알리는 홍보 기능 중심이었던 반면, F-03은 반대 방향 — **외부 재원·기회 정보를 도서관 내부로 끌어오는** 기능이다. 특히 공문 접수형 공모사업은 그동안 시스템적으로 누락되기 쉬웠던 지점이므로, F-03의 핵심 기능 중 하나로 설계한다.

### 1.3 범위

- **포함:** 외부 공모사업 웹 탐색, 사서가 접수한 공문 기반 공모사업 등록, 신청 요건 분석 및 적합도 판단 지원, 마감 일정 관리·알림, 신청서·사업계획서 초안 작성 지원 (A-01 연계), 선정 결과 기록 및 추적, 선정 시 A-03 예산 반영 안내
- **제외:** 신청서 실제 제출·발송 (사서 직접 처리), 공모 심사·평가 참여, 선정 후 사업비 집행·정산 관리 (A-03 담당), 협력기관과의 실무 협의 자체 (F-02 담당)

## 4. 기능 요구사항

> **표기 안내:** 아래 `FN-01`, `FN-02`... 는 이 문서 내부의 기능(Function) 번호이며, F-01·F-02·F-04 등 **에이전트 ID와는 무관**하다. F 도메인(홍보협력) 에이전트의 PRD는 에이전트 ID 접두어(F)와 기능 번호 접두어가 겹칠 수 있어, 혼동 방지를 위해 F-03부터 기능 번호를 `FN-`으로 표기한다.

### FN-01 외부 공모사업 능동 탐색

사서 요청 시 또는 월 1회 정기적으로, 웹 검색을 통해 신규 공모사업을 탐색한다.

**탐색 대상 채널 (예시, Config로 조정 가능):**
- 소속 교육청 공모사업 게시판
- 지자체(시·군·구) 문화체육관광 부서 공고
- 문화체육관광부·한국도서관협회·국립중앙도서관 등 상위기관 공고
- 지역 문화재단·평생교육진흥원 공고

**탐색 전략:**
1. "작은도서관 지원사업", "독서문화 프로그램 공모", "평생학습 지원사업" 등 도서관 업무와 연관된 키워드 조합 검색
2. 발견된 공고의 발신 기관, 신청 기한, 지원 내용, 지원 대상 요건 수집
3. 도서관 업무와 무관하거나 신청 자격에 명백히 맞지 않는 공고는 제외

**출력 형식 (발견된 공모사업 1건당):**
```
## [공모사업명] — 출처: 웹 검색 🔍
- 발신·주관 기관: [기관명]
- 신청 기한: [날짜]
- 지원 내용: [금액·물품·컨설팅 등]
- 신청 자격: [요건 요약]
- 출처 URL: [링크]
```

**Human-in-the-loop 필수:** 탐색 결과는 후보 목록으로만 제시하며, FN-02 등록 여부는 사서가 결정한다.

---

### FN-02 접수 공문 기반 공모사업 등록 (핵심 기능)

사서가 이미 공문으로 접수한 공모사업 안내를 F-03에 알려주면, 그 내용을 구조화하여 등록한다. **이 경로는 F-03이 스스로 발견한 것이 아니라 이미 도서관에 도달한 정보이므로, 탐색 없이 즉시 등록 및 신청 검토 단계로 진행한다.**

**사서 입력 예시:**
> "경남교육청에서 공문으로 '2026년 작은도서관 특화프로그램 지원사업' 안내가 왔어요. 신청기한 7월 20일까지, 지원금액 최대 500만원, 공문번호는 경남교육청-1234(2026.7.1.)입니다."

**등록 시 확인 항목:**

| 항목 | 필수 여부 | 설명 |
|------|---------|------|
| 공모사업명 | 필수 | |
| 발신 기관 | 필수 | |
| 관련 공문 번호·날짜 | 필수 | 원문 추적을 위한 근거 |
| 신청 기한 | 필수 | 마감 알림 기준일 |
| 지원 내용·금액 | 필수 | |
| 신청 자격·요건 | 선택 | 미입력 시 사서에게 확인 요청, 공란으로 두고 진행 가능 |
| 첨부(공고문 원본) 파일 경로 | 선택 | MCP Filesystem 경로로 연계, 스캔본·hwpx 등 |

**누락 항목 처리:** 필수 항목이 누락된 경우 해당 항목만 사서에게 질의한다. 임의로 추정하지 않는다.

**등록 완료 시:** 등록 직후 FN-03(신청 요건 분석) 단계로 자동 진행하여 신청 검토를 제안한다.

---

### FN-03 신청 요건 분석 및 적합도 판단 지원

등록된 공모사업(출처 무관)에 대해 도서관 현황(예산·인력·시설·기존 프로그램)과 대조하여 신청 적합도 판단 초안을 제공한다.

**판단 근거:**
- 신청 자격 요건 충족 여부 (기관 유형, 규모 등)
- 지원 내용과 도서관 현재 수요 부합도 (예: 시설 개선 사업 vs 현재 노후 시설 이슈 여부)
- 신청 준비 소요 기간 대비 마감까지 남은 기간의 현실성
- 유사 사업 과거 신청·선정 이력 (에이전트 메모리 참고)

**출력 형식:**
```
[공모사업 적합도 검토 — ○○○ 지원사업]
- 자격 요건: 충족 / 불충족 / 확인 필요
- 준비 기간: 마감까지 D-○○일, 신청서 작성 소요 예상 ○일
- 적합도 의견: [1~2문장 근거]
- 권고: 신청 추진 / 신중 검토 / 신청 보류
```

> 최종 신청 여부는 사서(및 예산·인력 소요가 큰 경우 도서관장)가 결정한다. 에이전트는 판단을 보조하는 초안만 제공한다.

---

### FN-04 마감 일정 관리 및 알림

등록된 전체 공모사업(웹 탐색·접수 공문 출처 통합)의 신청 기한을 기준으로 알림을 제공한다.

**알림 시점:** 마감 D-7, D-1 (Config로 조정 가능)

**알림 출력 예시:**
```
[F-03 공모사업 마감 알림 — 2026-07-13 기준]

D-7 임박
 · 2026년 작은도서관 특화프로그램 지원사업 (경남교육청) — 마감 7/20, 신청 여부 미결정

D-1 임박
 · 지역문화재단 독서문화 프로그램 공모 — 마감 7/14, 신청서 작성 중
```

신청 여부가 결정되지 않은 상태에서 마감이 임박한 경우, 사서에게 명시적으로 재확인을 요청한다.

---

### FN-05 신청서·사업계획서 초안 작성 지원 (A-01 호출)

사서가 신청을 결정하면 A-01 공문서 에이전트를 호출하여 신청서·사업계획서 hwpx 초안을 생성한다.

**A-01 호출 입력 구성 요소:**
- 공모사업명, 발신 기관, 관련 공문 번호
- 사업 개요, 운영 기간, 대상, 예산 계획 (기존 D-02/E-01 기획안 재활용 가능 시 연계)
- 기대 효과 (개조식)

**Human-in-the-loop 필수:** 초안 생성 후 사서 검토·수정 후 제출한다. 에이전트가 직접 제출하지 않는다.

---

### FN-06 선정 결과 기록 및 추적

사서가 결과(선정/미선정/미신청)를 입력하면 이를 기록하고 후속 조치를 안내한다.

| 결과 | 처리 |
|------|------|
| 선정 | 확보 재원 정보를 A-03 예산 에이전트에 전달하여 예산 반영 안내. 협력기관 연계 필요 시 F-02에 정보 공유 |
| 미선정 | 사유(선택) 기록, 재공모 여부·차기 연도 재도전 후보로 등록 |
| 미신청 | 미신청 사유 기록 (준비 기간 부족, 자격 미충족 등) |

**A-03 전달 형식 (선정 시):**
```json
{
  "requester_agent": "F-03",
  "grant_name": "2026년 작은도서관 특화프로그램 지원사업",
  "issuing_org": "경상남도교육청",
  "amount": 5000000,
  "purpose": "특화프로그램 운영비",
  "confirmed_date": "2026-08-05"
}
```

---

### FN-07 연간 공모 이력 관리 및 재도전 후보 안내

사서 요청 시 또는 연말, 연간 신청·선정 이력을 요약하여 제공한다.

**요약 포함 항목:**
- 연간 신청 건수, 선정 건수, 선정률, 확보 재원 총액
- 미선정 사업 중 재공모 예정 사업 (재도전 후보)
- 신청하지 않고 마감된 사업 (누락 방지 참고용)

## 5. 데이터 흐름

```
[상시]
F-03: 월 1회 또는 요청 시 웹 검색 → 공모사업 후보 발견 → 사서 확인 후 등록

[공문 접수 시]
사서 → F-03: 접수 공문 내용 전달
F-03: 필수 항목 확인 → 누락 시 질의 → grant_opportunities 등록
F-03: 신청 요건 분석 → 사서에게 적합도 의견 제시

[마감 관리]
F-03: 매일 등록 목록 점검 → D-7·D-1 대상 사서 알림

[신청 결정 시]
사서 → F-03: 신청 추진 확정
F-03 → A-01: 신청서·사업계획서 hwpx 초안 생성 요청
A-01 → F-03 → 사서: 초안 전달
사서: 검토·수정 → 직접 제출

[결과 확정 시]
사서 → F-03: 선정/미선정/미신청 결과 입력
F-03: 이력 기록
  선정 시 → A-03: 확보 재원 반영 안내
  협력기관 연계 필요 시 → F-02: 정보 공유

[연말 또는 요청 시]
F-03 → 사서: 연간 공모 이력 요약 제공
```

## 7. Human-in-the-loop 정책

| 단계 | 사서 개입 여부 | 내용 |
|------|--------------|------|
| 웹 탐색 결과 등록 여부 | **필수** | 사서 확인 후 등록 |
| 접수 공문 등록 | **필수** | 사서가 내용 전달, 누락 항목 확인 |
| 신청 적합도 판단 | 불필요 (초안 제공) | 최종 신청 여부는 사서(또는 도서관장) 결정 |
| 마감 알림 | 불필요 | 자동 발송 |
| 신청서 초안 생성 | 불필요 | 자동 생성 후 사서 전달 |
| 신청서 검토·제출 | **필수** | 사서 직접 처리 |
| 선정 결과 입력 | **필수** | 사서 직접 입력 |
| A-03·F-02 전달 | 불필요 | 결과 확정 후 자동 전달 |

## 8. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 접수 공문 필수 항목 누락 | 누락 항목만 사서에게 질의, 임의 추정 금지 |
| 웹 탐색 결과와 접수 공문이 동일 사업 중복 | 공모사업명·발신 기관 기준 중복 탐지 후 병합 확인 요청 |
| 신청 자격 요건 불명확 | "확인 필요"로 표시, 사서에게 발신 기관 문의 권고 |
| 마감 임박(D-1) + 신청 여부 미결정 | 강조 알림 + 즉시 사서 확인 요청 |
| 선정 후 A-03 반영 실패 | 사서에게 수동 반영 요청, 이력에는 선정 상태 유지 |

## 9. 비기능 요구사항

- 접수 공문 등록은 사서 입력 즉시 반영되어야 한다 (탐색 대기 없음).
- 마감 알림 기준일(D-7, D-1)은 Config에서 조정 가능하다.
- 웹 탐색 대상 채널 목록은 Config로 관리하며 기관별로 추가·수정 가능하다.
- SQLite 데이터는 연도 단위로 보존하며 삭제하지 않는다.
- 에이전트 응답 언어: 한국어

## 11. 향후 확장 고려사항

- 선정 성과를 A-04 성과관리 에이전트의 지표로 연계 검토 (예: "외부 재원 확보액" 성과지표)
- 접수 공문 원본을 OCR·문서 파싱으로 자동 구조화하여 등록 항목 자동 채움 기능 검토 (현재는 사서가 핵심 항목을 직접 전달하는 방식)
- 유사 도서관의 공모 선정 사례 벤치마킹 기능 추가 검토
- 재공모 주기가 있는 사업(매년 반복)의 다음 공모 시점 자동 예측 알림 검토
