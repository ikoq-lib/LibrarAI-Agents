**문서 버전:** 1.0  
**작성일:** 2026-05-11  
**소속 도메인:** D2 이용자  
**에이전트 ID:** C-05  
**에이전트 유형:** Leaf Agent  
**참조 아키텍처:** 창녕도서관 사서 AI 에이전트 시스템 v3

## 1. 개요

### 1.1 목적

C-05 상호대차 에이전트는 경상남도교육청 소속 도서관 간 상호대차 업무를 지원하는 리프 에이전트다. 신청 접수 확인, 처리 현황 추적, 미수령 알림, 타관 반납 택배 회수 관리 등 매일 발생하는 고빈도 상호대차 업무 흐름을 자동화하여 사서의 반복 처리 부담을 줄인다.

### 1.2 서비스 개요 (창녕도서관 기준)

창녕도서관 FAQ 및 이용안내(v1.6) 기반 확정 스펙:

| 항목 | 내용 |
|------|------|
| 이용 대상 | 경상남도교육청 소속 도서관(공공도서관·지혜의바다·지혜의방) 통합회원 |
| 신청 방법 | 도서관 홈페이지 자료검색 → 상호대차 메뉴 |
| 비용 | 무료 (연간 20책 한도) |
| 대출 기간 | 대출일 제외 14일 |
| 수령 기한 | 도착 통보 후 3일 이내 직접 신청 도서관에서 수령 |
| 1회 대출 책 수 | 최대 3책 |
| 통합 대출 한도 | 1인 통합회원 총 20책에 포함 |
| 수령 도서관 | 이용자가 직접 지정 |
| 반납 가능 | 경상남도교육청 소속 도서관 어디에서나 가능 |
| 반납 불가 | 경상남도교육청 북카페 「지혜의방」 |
| 미수령 불이익 | 수령 기한 초과 시 향후 도서 대출에 불이익 발생 |

### 1.3 배경

상호대차는 창녕도서관에서 거의 매일 발생하는 고빈도 업무다. 주요 처리 흐름은 크게 세 가지로, ①타 도서관이 신청한 도서를 우리 도서관에서 발송하는 흐름, ②우리 이용자가 신청한 도서를 타 도서관에서 수령하는 흐름, ③이용자가 타 도서관 책을 우리 도서관에 반납하면 원 도서관으로 택배 회수하는 흐름이다. 현재는 사서가 시스템 로그를 직접 확인하고 엑셀로 현황을 관리하나, 누락이나 기한 초과가 발생하기 쉽다.

### 1.4 범위

- **포함:** 신청 현황 조회·정리, 수령 기한 임박 알림, 미수령 이용자 안내문 초안, 타관 반납 택배 회수 관리대장 작성, 처리 현황 일일 요약 보고
- **제외:** 도서관 시스템(LMS) 직접 연동, 이용자 대출 이력 조회, 과태료·불이익 처분 직접 실행, 책바다·택배대출 처리 (→ C06 외부도서서비스)

| 구분 | 역할 |
|------|------|

## 3. 기능 요구사항

### F-01 신청 현황 조회 및 정리

사서가 엑셀 또는 텍스트 형태로 당일 신청 현황 데이터를 붙여넣으면, 에이전트가 이를 파싱하여 아래 항목으로 구조화하고 SQLite `ill_requests` 테이블에 저장한다.

**저장 항목:**

| 필드 | 설명 | 예시 |
|------|------|------|
| `request_id` | 신청 번호 | `ILL-2026-0511-001` |
| `direction` | 방향 | `outbound` (우리→타관) / `inbound` (타관→우리) |
| `requester_name` | 신청 이용자명 (inbound) | |
| `requester_contact` | 연락처 (inbound) | |
| `book_title` | 도서명 | |
| `book_isbn` | ISBN | |
| `origin_library` | 원 소장 도서관 | |
| `destination_library` | 수령 도서관 | |
| `request_date` | 신청일 | `2026-05-11` |
| `arrival_date` | 도착 확인일 (inbound) | |
| `deadline_date` | 수령 기한 (도착일 + 3일) | |
| `loan_due_date` | 반납 기한 (대출일 + 14일) | |
| `status` | 처리 상태 | `requested` / `arrived` / `collected` / `returned` / `expired` |

---

### F-02 수령 기한 임박 알림

매일 사서가 업무 시작 시 또는 요청 시, 수령 기한이 당일 또는 익일인 `inbound` 건을 조회하여 목록을 출력한다.

**출력 형식 예시:**
```
[상호대차 수령 기한 알림 — 2026-05-11]

⚠️ 오늘 마감 (3일 초과 위험)
 · 홍길동 님 — 『채식주의자』 (경남도서관 발송) → 오늘(5/11)까지

📋 내일 마감
 · 김영희 님 — 『82년생 김지영』 (통영도서관 발송) → 내일(5/12)까지

총 미수령 건수: 5건 / 이번 주 마감: 8건
```

---

### F-03 미수령 이용자 안내문 초안 생성

수령 기한을 초과한 이용자 또는 기한 임박 이용자에게 발송할 안내 문자·이메일 초안을 생성한다. 발송은 사서가 직접 수행하며, 에이전트는 초안만 제공한다.

**Human-in-the-loop 필수:** 안내문 초안 생성 후 사서 확인·수정·승인 이후에만 사용 가능하다. 에이전트가 직접 발송하지 않는다.

**안내문 초안 예시 (기한 임박):**
```
[창녕도서관 상호대차 수령 안내]
안녕하세요, 홍길동 님.
신청하신 도서 『채식주의자』가 도착하였습니다.
수령 기한은 2026년 5월 11일(월)까지입니다.
기한 내 미수령 시 향후 대출 서비스 이용에 불이익이 발생할 수 있습니다.
창녕도서관 ☎ 055-532-9501
```

### F-04 타관 반납 택배 회수 관리

이용자가 타 도서관 상호대차 도서를 창녕도서관에 반납하면, 원 도서관으로 택배 회수를 처리해야 한다. 단, 「지혜의방」은 반납 불가이므로 해당 안내도 포함한다.

**처리 흐름:**

1. 사서가 반납 도서 정보 입력 (도서명, 원 도서관, 반납 이용자)
2. 에이전트가 `return_shipments` 테이블에 기록
3. 원 도서관 주소 조회 (SQLite `library_registry` 테이블 기반)
4. 택배 송장 기재용 발송 정보 초안 출력
5. 사서 확인 후 실제 발송

**`return_shipments` 저장 항목:**

| 필드 | 설명 |
|------|------|
| `shipment_id` | 자동 부여 ID |
| `book_title` | 도서명 |
| `book_isbn` | ISBN |
| `origin_library` | 원 소장 도서관 |
| `origin_address` | 원 도서관 주소 |
| `returned_by` | 반납 이용자명 |
| `return_date` | 창녕도서관 반납일 |
| `shipped_date` | 택배 발송일 |
| `tracking_number` | 운송장 번호 (사서 입력) |
| `status` | `pending` / `shipped` / `confirmed` |

**지혜의방 반납 시도 안내:**
지혜의방에서 반납을 시도할 경우(사서가 해당 상황을 입력 시), 에이전트는 자동으로 "상호대차 도서는 지혜의방 반납 불가 — 경남교육청 소속 일반 도서관으로 반납 안내 필요"라는 메시지를 출력한다.

### F-05 일일 처리 현황 요약 보고

사서 요청 시 또는 하루 업무 마감 시점에 당일 상호대차 처리 현황을 요약하여 출력한다.

**보고 형식 예시:**
```
[상호대차 일일 현황 — 2026-05-11]

신규 신청
 · inbound (우리 이용자 신청): 3건
 · outbound (타관 신청, 우리 발송): 2건

처리 현황
 · 도착 완료: 4건
 · 수령 완료: 3건
 · 반납 완료: 2건
 · 택배 회수 발송: 1건

기한 초과 (미수령)
 · 1건 — 홍길동 님 『채식주의자』(5/9 만료)

누적 연간 현황 (2026년 기준)
 · 총 처리 건수: 127건
 · 연간 무료 한도 소진율: 평균 4.1책/인
```

## 4. 데이터 흐름

```
[매일]
사서 → C-05: 당일 신청 현황 데이터 입력
C-05: 파싱 → SQLite 저장
C-05 → 사서: 수령 기한 임박 알림 출력

[수시]
사서 → C-05: 반납 도서 정보 입력
C-05: 회수 발송 정보 초안 출력 → 사서 확인 → 발송

사서 → C-05: 미수령 안내문 요청
C-05: 초안 생성 → 사서 확인·수정 → 직접 발송

[업무 마감]
사서 → C-05: 일일 현황 요약 요청
C-05 → 사서: 처리 현황 요약 출력
```

## 5. MCP 도구 연동

| 도구 | 용도 |
|------|------|
| MCP SQLite | 신청 현황·회수 발송 이력·도서관 주소록 저장 및 조회 |
| MCP Filesystem | 일일 현황 보고서 텍스트 파일 출력 (필요 시) |

외부 API 연동 없음. 도서관 LMS 직접 연동 없음 (연구용 더미 데이터 기반 운영).

## 6. Human-in-the-loop 정책

| 단계 | 사서 개입 여부 | 내용 |
|------|--------------|------|
| 신청 현황 파싱·저장 | 불필요 | 자동 처리 후 결과만 확인 |
| 수령 기한 알림 출력 | 불필요 | 자동 생성, 사서 열람용 |
| 미수령 안내문 초안 | **필수** | 사서 확인·수정 후 직접 발송 |
| 택배 회수 발송 정보 | **필수** | 사서 확인 후 직접 발송 처리 |
| 운송장 번호 등록 | **필수** | 사서가 직접 입력 |
| 일일 현황 보고 | 불필요 | 사서 요청 즉시 응답 |

## 7. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 지혜의방 반납 시도 | "반납 불가" 안내 메시지 자동 출력 |
| 연간 20책 한도 초과 신청 | 해당 이용자 한도 초과 여부 안내 (조회 기반) |
| 수령 기한 3일 초과 | `status`를 `expired`로 자동 변경, 사서 알림 |
| 도서관 주소록 미등록 기관 | 주소 조회 불가 안내 후 사서에게 수동 입력 요청 |
| 데이터 입력 형식 불일치 | 파싱 실패 항목 목록화 후 사서에게 재입력 요청 |

## 8. 비기능 요구사항

- 당일 신청 건은 입력 후 즉시 처리되어야 한다.
- 수령 기한 알림은 업무 시작 시(오전 9시 기준) 자동 출력을 목표로 한다.
- SQLite 데이터는 연도 단위로 보존하며 삭제하지 않는다.
- 에이전트 응답 언어: 한국어
