**문서 버전:** 1.0
**작성일:** 2026-07-06
**소속 도메인:** D1 장서
**에이전트 ID:** B-04-H

## 1. 개요

### 1.1 목적

B-04-H 자료조직 하네스 에이전트는 입고 확정된 도서를 **일괄(배치) 단위로 자료조직 워커(B-04-W)에 전달·수집·검증하는 오케스트레이션 전담 에이전트**다. B-04-W(현재 `b-04-w-cataloging-worker.md` 스펙으로 구현된 KDC 분류·KORMARC 기술 워커)는 도서 1건 단위로 정확한 분류·기술을 수행하는 데 특화되어 있으나, 실제 입고는 여러 권이 한 번에 발생한다. B-04-H는 이 배치 처리·품질 검증·출력 파일 생성·처리 현황 보고를 전담하여 B-04-W가 순수 분류·기술 로직에만 집중할 수 있도록 한다.

### 1.2 배경

기존 B-04-W(자료조직 워커)는 도서 1권씩 입력받아 KDC 분류와 KORMARC 레코드를 생성하는 방식으로 설계·구현되어 있다. 그러나 실제 업무에서는 B-01 수서 에이전트를 통해 선정된 도서가 한 번에 수십 권 단위로 입고되며, 사서가 매 권마다 개별적으로 워커를 호출하는 것은 비효율적이다. B-04-H는 입고 배치를 받아 각 도서를 B-04-W에 순차 전달하고, 결과를 취합·검증하여 배치 단위 출력물(KORMARC 파일, 처리 현황 보고)을 생성한다.

### 1.3 범위

- **포함:** 입고 도서 배치 접수 및 작업 목록 구성, B-04-W 순차 호출 및 결과 수집, QA 체크리스트 기반 결과 검증 및 재작업 요청, 배치 단위 KORMARC 출력 파일 생성, 처리 현황 보고(사서 및 A-02 연계), 실패 건 재시도 및 예외 처리
- **제외:** KDC 분류 판단 자체 및 KORMARC 필드 기술 자체 (B-04-W 담당), 도서 선정·구입 결정 (B-01 담당), 복본 판정 (B-03 담당), 실제 서가 배치·라벨 부착 (사서 담당), 국립중앙도서관 등 외부 서지 DB로의 레코드 업로드(해당 기능 필요 시 별도 검토)

## 4. 기능 요구사항

### FN-01 입고 도서 배치 접수 및 작업 목록 구성

사서가 입고 확정된 도서 목록(엑셀 또는 직접 입력)을 전달하면 배치 작업을 초기화한다.

**필수 입력 항목(도서당):** 제목, 저자, 출판사, 출판연도, ISBN(있는 경우), 판사항·총서사항(있는 경우)

**처리:**
1. 목록을 `catalog_batch` 테이블에 배치 단위로 저장 (`batch_id` 자동 부여)
2. 각 도서를 `catalog_jobs` 테이블에 개별 작업 항목으로 등록 (`status: pending`)
3. 필수 항목(제목·저자) 누락 도서는 등록하지 않고 목록화하여 사서에게 보완 요청

---

### FN-02 B-04-W 워커 순차 호출 및 결과 수집

`pending` 상태 작업을 하나씩 B-04-W에 전달하여 분류·기술 결과를 수집한다.

**호출 방식:** 배치 내 도서를 순차 처리한다(동시 병렬 호출 없음 — KDC 분류 판단 품질을 위해 한 번에 한 건씩 완결 처리).

**전달 항목:** 제목, 저자, 출판사, 출판연도, ISBN, 판사항, 총서사항, 목차/요약(있는 경우)

**수신 항목:** KDC 분류번호 및 분류 근거, 청구기호(KDC+Cutter), KORMARC 레코드(필드별), 메모/특이사항

**개별 작업 실패(워커가 분류 불확실·정보 부족으로 완료하지 못한 경우):** 해당 작업을 `needs_info`로 표시하고 배치 처리를 중단하지 않은 채 다음 작업으로 진행한다.

---

### FN-03 결과 품질 검증 (QA 체크리스트 기반)

B-04-W가 반환한 각 레코드를 B-04-W 자체 QA 체크리스트 기준으로 재검증한다.

**검증 항목 (b-04-w-cataloging-worker.md의 Quality Assurance Checklist 그대로 적용):**
- KDC 분류번호가 세목(3자리) 이상 수준으로 구체적인가
- 245, 100, 020, 008, 090 등 필수 필드가 모두 존재하는가
- 090 청구기호가 부여된 KDC 분류번호와 일치하는가
- 최소 1개 이상의 650/653 주제명표목이 존재하는가

**검증 실패 시:** 해당 작업을 B-04-W에 재작업 요청(최대 1회)한다. 재작업 후에도 실패하면 `qa_failed`로 표시하고 사서 확인 대상으로 분류한다.

---

### FN-04 배치 KORMARC 출력 파일 생성

QA를 통과한 작업을 모아 배치 단위 KORMARC 출력 파일을 생성한다.

**출력 형식:** MARC XML 또는 ISO 2709 중 확정 필요 (10. TBD 항목 참조). 확정 전까지는 사람이 읽을 수 있는 텍스트 포맷(현행 b-04-w-cataloging-worker.md 출력 형식과 동일한 tag-order 텍스트)으로 생성하고, 형식 확정 시 자동 변환 기능을 추가한다.

**파일명 규칙:** `[배치일자]_자료조직_[배치ID].txt` (형식 확정 후 확장자 조정)

---

### FN-05 처리 현황 보고

배치 처리 완료 시 사서에게 현황을 보고한다.

**보고 형식:**
```
[자료조직 처리 현황 — 배치 2026-07-06-001]

접수: 32건
완료: 28건
재작업 후 통과: 3건
QA 실패(사서 확인 필요): 1건
정보 부족(사서 보완 필요): 0건

QA 실패 목록:
 · 『○○○』 — 090 청구기호 KDC 분류번호 불일치

출력 파일: 20260706_자료조직_batch001.txt
```

**A-02 표준 데이터 수집 응답 (매월 초):**
```json
{
  "agent_id": "B-04-H",
  "agent_name": "자료조직 하네스",
  "period": "2026-06",
  "metrics": [
    { "metric_name": "자료조직 완료 건수", "value": 118, "unit": "건" },
    { "metric_name": "QA 재작업 건수", "value": 9, "unit": "건" },
    { "metric_name": "QA 실패(사서 확인) 건수", "value": 2, "unit": "건" }
  ],
  "notes": "6월 자료조직 정상 처리",
  "status": "complete"
}
```

### FN-06 예외 처리 및 재시도

| 상황 | 처리 |
|------|------|
| B-04-W 응답 없음/오류 | 1회 재시도 후 지속 실패 시 `error`로 표시, 배치 내 나머지 작업은 계속 진행 |
| 정보 부족(목차·주제 불명확) | `needs_info`로 표시, 사서에게 보완 정보 요청 목록 제공 |
| QA 검증 실패 | 1회 재작업 요청 → 재실패 시 `qa_failed`, 사서 최종 확인 |
| 배치 내 ISBN 중복(동일 도서 복수 입력) | 최초 1건만 처리, 중복 입력임을 사서에게 안내 |

## 5. 데이터 흐름

```
[입고 배치 발생 시]
사서 → B-04-H: 입고 도서 목록 전달 (FN-01)
B-04-H: 작업 목록 구성 → catalog_jobs 등록

B-04-H → B-04-W: 도서 1건 전달 (순차, FN-02)
B-04-W → B-04-H: KDC 분류 + KORMARC 레코드 반환
B-04-H: QA 검증 (FN-03) → 실패 시 재작업 요청

전체 작업 완료 후:
B-04-H: 배치 출력 파일 생성 (FN-04)
B-04-H → 사서: 처리 현황 보고 + 출력 파일 (FN-05)

[매월 초]
A-02 요청 → B-04-H: 전월 자료조직 처리 통계 전달
```

## 7. Human-in-the-loop 정책

| 단계 | 사서 개입 여부 | 내용 |
|------|--------------|------|
| 입고 배치 접수 | **필수** | 사서가 입고 목록 전달 |

| 월간 통계 보고 | 불필요 | A-02 요청 시 자동 응답 |

## 8. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 배치 내 필수 항목(제목·저자) 누락 도서 | 등록 제외, 사서에게 보완 요청 목록 제공 |
| B-04-W 응답 실패 | 1회 재시도 후 `error` 표시, 나머지 작업 계속 진행 |
| QA 검증 실패 | 1회 재작업 요청 후 재실패 시 사서 확인 대상 |
| 배치 내 도서 중복 입력 | 최초 1건만 처리, 사서에게 중복 안내 |
| KORMARC 출력 형식 미확정 상태 | 텍스트 포맷으로 잠정 출력, 형식 확정 시 일괄 변환 |
