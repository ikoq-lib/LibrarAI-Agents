# PRD — D-03 강사섭외 에이전트 (Instructor Sourcing Agent)

**문서 버전:** 1.0  
**작성일:** 2026-06-30  
**소속 도메인:** D3 독서문화  
**에이전트 ID:** D-03  
**에이전트 유형:** Leaf Agent  

---

## 1. 개요

### 1.1 목적

D-03 강사섭외 에이전트는 독서진흥행사에 필요한 강사를 탐색하고 섭외 초안을 생성하는 에이전트다. D-02 행사기획 에이전트로부터 행사 정보를 인계받아 강사 DB 탐색 → 웹 검색 → 후보 목록 제시 → 섭외 문자 초안 생성 → 섭외 결과 기록의 전 과정을 지원한다. 최종 강사 선택과 실제 연락은 담당 사서가 직접 수행한다.

### 1.2 배경

독서진흥행사(북토크, 저자 강연, 독서 워크숍 등)는 행사 주제와 성격에 맞는 특정 인물을 직접 섭외하는 방식이 일반적이다. 공개 공모보다 담당 사서가 적합한 강사를 찾아 개별 컨택하는 경우가 많으며, 강사 탐색에 상당한 시간이 소요된다. D-03은 이 탐색 과정을 자동화하여 사서의 부담을 줄인다.

> **D02 행사기획 vs D03 강사섭외 역할 구분**  
> D-02는 행사 기획안(주제·일정·내용)을 생성하고, D-03은 그 행사에 맞는 강사를 찾아 섭외 초안을 제공한다. D-02가 강사 필요 여부를 판단하면 D-03을 호출한다.

> **D03 강사섭외 vs E02 강사공모 차이**  
> D-03은 독서문화 행사의 **개별 섭외** 방식이고, E-02는 평생학습 강좌의 **공개 공모** 방식이다. 단발성 이벤트에는 D-03, 정기 강좌에는 E-02를 사용한다.

## 2. 업무 범위 (Scope)

### 포함 (In Scope)
- 행사 주제·요건 기반 강사 DB 탐색 및 매칭
- DB 내 적합 후보 없을 경우 웹 검색을 통한 대안 탐색
- 강사 후보 목록 점수화 및 추천 보고
- 사서 선택 후 섭외 문자·이메일 초안 생성
- 섭외 결과(수락·거절·미응답) 기록 및 강사 DB 업데이트

### 제외 (Out of Scope)
- 강사 최종 선택 (사서 고유 권한)
- 실제 연락 발송 (사서가 직접 수행)
- 강사 계약서 작성 (별도 행정 처리)
- 강사비 지급 처리 (A-03 예산 에이전트 담당)
- 평생학습 강좌 강사 채용 (E-02 강사공모 에이전트 담당)

## 3. 업무 흐름 (Workflow)

```
[트리거]
D-02 행사기획 에이전트 인계 또는 사서 직접 요청

STEP 1 — 행사 요건 확인 (FN-01)
  → 행사명, 주제 키워드, 날짜, 대상, 강사비 예산, 필요 전문분야 확인
  → 누락 항목은 사서에게 질의

STEP 2 — 강사 DB 탐색 (FN-02)
  → MCP SQLite로 강사 DB 검색
  → 전문분야·주제 키워드 매칭, 과거 실적·평점·강사비 범위 필터
  → 후보 점수화 및 정렬
  → 후보 3명 이상 확보 시 → STEP 4로
  → 후보 부족(3명 미만) 시 → STEP 3으로

STEP 3 — 웹 검색 탐색 (FN-03)  [DB 결과 부족 시]
  → 행사 주제 키워드로 웹 검색
  → 관련 작가·전문가·강연자 정보 수집
  → 연락처·SNS·소속기관 정보 취합
  → DB 출처와 웹 검색 출처 구분하여 목록 합산

STEP 4 — 후보 목록 보고 (FN-04)
  → 강사 후보 3~5명 추천 목록 제시
  → 사서가 후보 선택 [Human-in-the-loop]

STEP 5 — 섭외 문자·이메일 초안 생성 (FN-05)
  → 선택된 강사에 맞춘 섭외 문자 초안 생성
  → 사서 검토 및 직접 발송 [Human-in-the-loop]

STEP 6 — 섭외 결과 기록 (FN-06)
  → 사서가 결과(수락·거절·미응답) 입력
  → 강사 DB 업데이트
  → 수락 시 F-01 홍보물 에이전트에 강사 정보 전달 가능
```

## 4. 기능 요구사항

### FN-01 행사 요건 확인

D-02 인계 정보 또는 사서 직접 입력을 통해 섭외 요건을 정의한다.

**필수 확인 항목:**
- 행사명 및 주제 키워드 (예: "그림책 작가 북토크", "환경 인문학 강연")
- 행사 일시 및 소요 시간
- 대상 (어린이·청소년·성인·전체)
- 강사비 예산 범위 (예: ~100,000원, ~200,000원)
- 필요 전문분야 또는 강사 유형 (예: 아동문학 작가, 환경 운동가, 그림책 작가)
- 선호 조건 (예: 지역 내 강사 우선, 여성 강사 선호 등) — 선택사항

정보 부족 시 필요 항목만 명시하여 사서에게 질의한다. 임의 가정 금지.

---

### FN-02 강사 DB 탐색

강사 DB(MCP SQLite)에서 요건에 맞는 강사를 탐색하고 점수화한다.

**강사 DB 스키마 (instructor_pool 테이블):**

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | |
| name | TEXT | 강사명 |
| type | TEXT | 'reading_culture' / 'lifelong_learning' / 'both' |
| specializations | TEXT | 전문분야 태그 (쉼표 구분) |
| contact_email | TEXT | |
| contact_phone | TEXT | |
| affiliation | TEXT | 소속 기관·직함 |
| fee_range_min | INTEGER | 강사비 하한 (원) |
| fee_range_max | INTEGER | 강사비 상한 (원) |
| past_events | TEXT | 과거 행사 이력 (JSON) |
| rating | REAL | 사서 평점 (1.0~5.0) |
| last_contacted | DATE | 최근 섭외 일자 |
| notes | TEXT | 특이사항 |

**매칭 기준 (점수화):**

| 항목 | 가중치 | 측정 방법 |
|------|--------|---------|
| 주제 키워드 일치도 | 50% | specializations 및 past_events 텍스트 매칭 점수 |
| 강사비 예산 적합도 | 20% | fee_range가 예산 내에 있으면 100pt, 초과 시 0pt |
| 사서 평점 | 20% | rating 정규화 (5.0 = 100pt) |
| 최근 활동 여부 | 10% | last_contacted 기준 1년 이내 = 100pt, 이후 선형 감소 |

후보 3명 이상 확보 시 STEP 4로 진행. 미달 시 웹 검색(FN-03) 병행.

---

### FN-03 웹 검색 탐색

강사 DB 결과가 부족할 때 웹 검색으로 대안 강사를 탐색한다.

**검색 전략:**
1. 행사 주제 키워드 + "강연" / "작가" / "강사" 조합으로 검색
2. 관련 도서 저자 정보 탐색 (알라딘 등)
3. 지역 문화재단·도서관 협회 강사풀 페이지 참고
4. 해당 분야 전문가 개인 웹사이트·SNS에서 연락처 수집

**수집 항목:** 이름, 소속·직함, 전문분야, 연락처(이메일·SNS·소속기관 대표번호), 관련 도서·활동 이력

**출처 명시 원칙:** DB 출처 강사와 웹 검색 출처 강사를 명확히 구분하여 표시. 연락처 신뢰도(공식 채널 여부)도 표시.

---

### FN-04 후보 목록 보고

사서에게 강사 후보 목록을 제시하고 선택을 요청한다.

**출력 형식 (후보 1명당):**
```
## [순위]. [강사명] — [출처: DB / 웹검색]
- 소속·직함: [내용]
- 전문분야: [태그]
- 강사비: [범위 또는 "협의 필요"]
- 연락처: [이메일 / 전화 / SNS]
- 추천 이유: [주제 키워드 매칭 근거, 1~2문장]
- 과거 실적: [있을 경우]
- 특이사항: [있을 경우]
```

목록 제시 후: "위 후보 중 섭외할 강사를 선택해주시면 섭외 문자 초안을 작성하겠습니다." 안내.

⚠️ 후보 선택은 사서가 결정한다. 에이전트가 임의로 강사를 확정하지 않는다.

---

### FN-05 섭외 문자·이메일 초안 생성

사서가 후보를 선택하면 해당 강사에게 보낼 섭외 문자(또는 이메일) 초안을 생성한다.

**초안에 포함할 내용:**
- 인사말 및 에이전트(도서관) 소개
- 행사명, 일시, 장소, 대상
- 강사 역할 및 소요 시간
- 강사비 제안 (또는 협의 의향)
- 회신 요청 및 문의처

**형식 선택:** 사서 요청에 따라 문자(짧게 3~5줄) 또는 이메일(공식 서식) 중 선택.

⚠️ 초안 생성 후 반드시 사서 검토·수정을 안내한다. 에이전트가 직접 발송하지 않는다.

---

### FN-06 섭외 결과 기록

섭외 결과를 사서로부터 입력받아 강사 DB에 기록한다.

**결과 유형:**
- **수락**: 강사 확정. DB의 past_events 업데이트, 확정 사실 F-01 전달 가능
- **거절**: 거절 이유(선택) 기록. 차순위 후보 섭외 진행 여부 사서에게 확인
- **미응답**: 재연락 일정 안내. 지정 기간 후 차순위 검토 권고

신규 강사(DB에 없던 경우) 수락 시 → 강사 DB에 신규 등록 여부 사서에게 확인 후 등록.

## 5. 비기능 요구사항

| 항목 | 기준 |
|------|------|
| Human-in-the-loop | 후보 선택·섭외 문자 발송 모두 사서 승인 필수 |
| 범용 설계 | 기관명·연락처·예산 기준은 Config로 주입. PRD 본문 하드코딩 금지 |
| 웹 검색 투명성 | 검색 출처 URL 명시. 연락처 신뢰도(공식/비공식) 표시 |
| DB 없는 환경 | 강사 DB 미구축 시 웹 검색만으로 동작 가능 (DB는 선택 요소) |
| 미응답 처리 | 에이전트가 자동 재연락하지 않음. 사서에게 안내만 제공 |

## 6. 도구 및 MCP 연동

| 도구 / MCP | 사용 시점 |
|-----------|---------|
| MCP SQLite | 강사 DB 탐색·업데이트 (instructor_pool 테이블) |
| MCP Fetch / 웹 검색 | FN-03 웹 검색 탐색 |
| MCP Filesystem | 섭외 문자 초안 파일 저장 (선택) |

## 7. 수용 기준 (Acceptance Criteria)

- **AC1**: 강사 DB에 주제 매칭 후보가 있을 경우 점수 기준 상위 3명 이상을 30초 이내 제시한다.
- **AC2**: DB 후보 3명 미만 시 자동으로 웹 검색을 수행하고 결과를 DB 후보와 구분하여 제시한다.
- **AC3**: 사서가 후보를 선택하면 행사 정보를 반영한 섭외 문자 초안을 즉시 생성한다.
- **AC4**: 에이전트가 사서 승인 없이 강사에게 직접 연락하지 않는다.
- **AC5**: 섭외 결과(수락·거절·미응답)를 입력받으면 강사 DB를 갱신한다.

## 8. 강사 DB 더미 데이터 계획

초기 구축 시 아래 유형의 더미 데이터 10~20건을 SQLite에 삽입하여 탐색 기능을 검증한다.

| 강사 유형 예시 | specializations 태그 |
|-------------|---------------------|
| 아동문학 작가 | 그림책, 동화, 어린이, 북토크 |
| 환경 활동가 | 환경, 기후, 생태, 지속가능성 |
| 지역사 연구자 | 지역역사, 문화유산, 향토 |
| 독서치료사 | 독서치료, 심리, 성인, 시니어 |
| 인문학 강연자 | 철학, 인문학, 성인, 인생 |

## 9. 미결 사항 (Open Questions)

1. **강사 DB 공유 여부**: D-03(독서문화)과 E-02(평생학습) 강사 DB를 통합(type 컬럼 분기) 운영할지, 별도 테이블로 분리할지 결정 필요
2. **웹 검색 도구 확정**: MCP Fetch 직접 호출 vs. 별도 검색 MCP 서버 사용 여부
3. **연락처 수집 기준**: 웹에서 수집한 개인 연락처의 개인정보 처리 방침 확인 필요
