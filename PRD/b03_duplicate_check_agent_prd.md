# PRD — B-03 복본 에이전트 (Duplicate Copy Check Agent)

**문서 버전:** 1.0
**작성일:** 2026-07-06
**소속 도메인:** D1 장서
**에이전트 ID:** B-03
**에이전트 유형:** Leaf Agent (공통 도구 에이전트, D1 장서 도메인 내)
**참조 아키텍처:** 창녕도서관 사서 AI 에이전트 시스템 v3

---

## 1. 개요

### 1.1 목적

B-03 복본 에이전트는 **도서 구입 후보가 발생할 때마다 기존 장서와의 중복(복본) 여부를 판정**하는 공통 도구 에이전트다. B-01 수서 에이전트의 신간 후보 목록, B-02 희망도서 에이전트의 신청 도서 목록이 구입 확정되기 전 반드시 B-03을 거쳐 복본 여부를 확인받으며, 이미 소장 중인 도서에 대해서는 추가 구입(복본 확보) 필요성까지 함께 분석하여 의견을 제시한다.

### 1.2 배경

CLAUDE.md와 기존 문서에 명시된 복본조사 기준(ISBN 동일 = 복본, 제목+저자 80% 이상 유사 = 상세조사 필요)은 지금까지 B-01 수서 에이전트 내부에 ISBN 대조 수준으로만 단순하게 구현되어 있었고, 제목·저자 유사도 기반의 "상세조사 필요" 판정은 별도로 전담하는 에이전트가 없었다. B-03은 이 기준을 단일 에이전트로 일원화하여, B-01·B-02가 각자 중복 판정 로직을 중복 구현하지 않고 B-03을 호출하도록 한다.

> **B-01과의 관계:** B-01 PRD의 FN-02(중복 및 장서 균형 확인)에 포함된 "ISBN 대조를 통한 중복 자동 제외" 기능은 B-03 도입 이후 B-03 호출로 대체된다. B-01은 KDC 균형 분석·희망도서 교차 확인 등 복본 판정 이외의 기능만 유지한다. (B-01 PRD는 B-03 완성 후 별도로 갱신 필요 — 10.2 참조)

### 1.3 범위

- **포함:** ISBN 완전일치 복본 판정, 제목+저자 유사도 기반 상세조사 필요 판정, 기존 소장 부수·대출 실적 조회를 통한 추가 구입(복본) 필요성 분석 및 의견 제시, B-01·B-02 호출 인터페이스, 사서 단건 조회 대응, 상세조사 건 사서 확인 절차, 월간 복본조사 현황 보고
- **제외:** 최종 구입 결정 (B-01·사서 고유 권한), KDC 분야별 장서 균형 분석 (B-05 담당), 폐기·재배치 처분 판단, KORMARC 레코드 조회·생성 (B-04-W 담당), 장서 DB 자체의 구축·정비

```

[B-01 수서 에이전트]

[B-02 희망도서 에이전트]
    ↓ 신청 도서 (ISBN·제목·저자)

[사서]
    ↔ 단건 복본 조회 요청·응답 (직접 호출)
```

## 4. 기능 요구사항

### FN-01 복본 판정 (ISBN 완전일치)

후보 도서의 ISBN을 장서 DB와 대조한다.

**처리 흐름:**
```
1. 후보 ISBN → 장서 DB 조회
2. 완전일치 존재 → "복본" 확정, 기존 소장 서지정보(청구기호·소장부수) 반환
3. 완전일치 없음 → FN-02로 진행
```

**판정 결과:** `duplicate` (복본 확정) — 사서 확인 없이 자동 확정하되, 구입 후보에서 자동 제외할지 FN-03 추가구입 분석 결과와 함께 최종 판단은 호출 에이전트·사서에게 넘긴다.

---

### FN-02 상세조사 필요 판정 (제목+저자 유사도)

ISBN이 없거나 완전일치하지 않는 경우, 제목+저자 유사도를 계산한다.

**판정 기준:**

| 유사도 | 판정 결과 | 처리 |
|--------|----------|------|
| 제목+저자 종합 유사도 ≥ 80% | `needs_review` (상세조사 필요) | 사서 확인 요청 (FN-04) |
| 제목+저자 종합 유사도 < 80% | `new` (신규) | 구입 후보 유지, 추가 조치 없음 |

**유사도 계산 방식 (기본안, 10.1 TBD 참조):**
- 제목: 공백·특수문자 정규화 후 문자열 유사도(예: Jaccard 또는 Levenshtein 기반 비율) 산출
- 저자: 저자명 정규화(공백 제거, "지음/옮김" 등 역할 표기 제거) 후 일치 여부 확인
- 종합 유사도 = 제목 유사도 × 0.7 + 저자 일치 여부 × 0.3 (가중치는 TBD, 사서 협의 후 조정 가능)

**상세조사 필요로 분류되는 대표 사례:** 개정판·증보판(제목 유사, ISBN 상이), 저자명 표기 차이(예: "김영하" vs "김 영하"), 출판사 재출간본, 오탈자로 인한 서지 불일치

---

### FN-03 추가 구입(복본) 필요성 분석

FN-01에서 "복본"으로 확정된 도서에 대해, 이미 소장 중이더라도 추가 구입이 필요한지 여부를 분석하여 의견을 제시한다.

**분석 근거:**

| 지표 | 조회 방법 | 판단 기준 |
|------|----------|----------|
| 기존 소장 부수 | 장서 DB 소장 레코드 수 | 부수 자체 확인 |
| 최근 대출 실적 | 장서 DB 대출 이력 (최근 3개월) | 대출 빈도 대비 소장 부수 비교 |
| 예약(대출 대기) 건수 | 장서 DB 예약 큐 | 대기자 다수 시 추가구입 근거 |

**의견 출력 예시:**
```
[복본 판정 결과]
도서: 『아몬드』 손원평 저 (ISBN: 97891...)
판정: 복본 (기존 소장 2부)
최근 3개월 대출: 18회 / 현재 예약 대기: 5명
→ 의견: 수요 대비 소장 부수 부족 — 추가 구입(복본) 검토 권고
```

**Human-in-the-loop:** 추가 구입 여부의 최종 결정은 항상 호출 에이전트(B-01)와 사서에게 있다. B-03은 의견만 제시하며 구입 여부를 확정하지 않는다.

**대출·예약 데이터 미확보 시:** 지표 조회 없이 "복본 확정, 추가구입 필요성은 데이터 부족으로 판단 보류"로 응답한다.

---

### FN-04 상세조사 필요 건 사서 확인

FN-02에서 `needs_review`로 분류된 건은 사서 확인 절차를 거친다.

**처리 흐름:**
1. 유사 후보(기존 소장 서지정보)와 신규 후보를 나란히 제시
2. 유사도 산출 근거(제목·저자 비교 결과) 함께 표시
3. 사서 판단 결과를 `duplicate_checks` 테이블에 반영 (`confirmed_duplicate` / `confirmed_new`)

**Human-in-the-loop 필수:** 상세조사 필요 건은 사서 확인 전까지 구입 후보에서 자동 제외하거나 자동 확정하지 않는다.

---

### FN-05 B-01·B-02 호출 인터페이스

**요청 구조 (B-01/B-02 → B-03):**
```json
{
  "requester_agent": "B-01",
  "candidates": [
    { "candidate_id": "c-001", "isbn": "9791165219876", "title": "아몬드", "author": "손원평" }
  ]
}
```

**응답 구조 (B-03 → 호출 에이전트):**
```json
{
  "results": [
    {
      "candidate_id": "c-001",
      "match_type": "duplicate",
      "matched_isbn": "9791165219876",
      "similarity_score": 1.0,
      "existing_copies": 2,
      "recent_loan_count_3m": 18,
      "reservation_count": 5,
      "additional_purchase_opinion": "수요 대비 소장 부수 부족 — 추가 구입 검토 권고",
      "status": "confirmed"
    },
    {
      "candidate_id": "c-002",
      "match_type": "needs_review",
      "matched_isbn": null,
      "similarity_score": 0.83,
      "existing_copies": null,
      "additional_purchase_opinion": null,
      "status": "pending_librarian_review"
    }
  ]
}
```

`status` 값: `confirmed`(자동 확정) / `pending_librarian_review`(FN-04 대상)

## 7. Human-in-the-loop 정책

| 단계 | 사서 개입 여부 | 내용 |
|------|--------------|------|

| 단건 조회 응답 | 불필요 | 즉시 응답 |
| 월간 현황 보고 | 불필요 | A-02 요청 시 자동 응답 |

## 8. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 장서 DB 미연동·미확정 | 전체 건 `needs_review`로 분류, 사서에게 수동 확인 요청 |
| 대출·예약 이력 데이터 없음 | 복본 확정은 유지하되 추가구입 의견은 "데이터 부족으로 판단 보류" |
| 저자명 표기 불일치로 유사도 오판 우려 | 유사도 80% 근접 구간(75~85%)은 항상 `needs_review`로 안전하게 분류 |
| 동명이인 저자·동명 도서 | 유사도 계산만으로 자동 확정하지 않고 사서 확인 요청 |
| 후보 데이터에 ISBN·제목 모두 누락 | 판정 불가, 호출 에이전트에 데이터 보완 요청 반환 |
