## 1. 개요

### 1.1 목적

E-02 강사공모 에이전트는 E-01 강좌기획 에이전트가 확정한 프로그램 정보를 인계받아, 강사가 최종 확정되기까지의 전 과정 — 공모 공고, 모집 결과 보고, 선정위원회 개최, 선정 결과 보고, 범죄경력조회 안내, 강사 위촉 — 을 공식 공모 절차 기반으로 담당하는 리프 에이전트다.

강사 확정 완료 후 E-03 수강생 모집 에이전트에 인계한다.

### 1.2 배경

도서관 평생학습 강사 채용은 공공기관 운영 특성상 공개 공모를 원칙으로 한다. 비공식 개별 섭외 방식은 절차적 투명성을 확보하기 어렵고 타 기관에 범용 적용하기 적합하지 않다. E-02는 공모 공고 → 접수 → 결과 보고 → 선정위원회 개최 → 선정 → 범죄경력조회 → 위촉의 단일 공모 트랙만 지원하며, 각 단계에서 필요한 공문 초안을 자동 생성한다.

공모 미달 시에는 재공모 또는 공모 방식 조정을 사서가 판단하며, 에이전트는 미달 결과 보고 공문 초안과 선택지를 제시한다.

### 1.3 D-03 강사공모 에이전트와의 역할 경계

| 구분 | D-03 강사공모 (독서문화) | E-02 강사공모 (평생학습) |
|------|------------------------|------------------------|
| 소속 도메인 | D3 독서문화 | D4 평생학습 |
| 강사 성격 | 북토크·작가·독서지도사 등 | 공예·요리·어학·체육 등 실용 강좌 강사 |
| 강사 DB | 독서 분야 특화 | 생활 실용 분야 특화 |
| 선행 에이전트 | D-02 행사기획 | E-01 강좌기획 |
| 후행 에이전트 | DM-03 (독서문화 도메인, 구 D-05 결과보고) | E-03 수강생 모집 |

### 1.4 범위

- **포함:** 공모 공고문 초안 생성, 모집 결과 보고 공문 초안, **강사 선정위원회 개최 공문 초안(신규)**, 강사 선정 결과 보고 공문 초안, 범죄경력조회 안내 및 공문 초안, **강사 위촉 공문(겸 위촉장) 초안(신규)**, 강사 DB 조회·등록, E-03 인계
- **제외:** 비공식 개별 섭외 (v2.0부터 제거), 강사비 지급 (E-04 담당), 범죄경력조회 직접 실행 (외부 경찰청 시스템), 수강생 모집 (E-03 담당), 선정위원회 위원 임명 자체(인사 발령)

## 4. 강사 DB (instructor_db)

### 4.1 현황 및 구축 계획

강사 DB는 현재 미구축 상태이며, 더미 데이터로 초기 구축 후 실운영 데이터로 교체한다. 공모를 통해 선정된 강사 이력이 누적되어 다음 시즌 공모 참고 자료로 활용된다. DB 유무와 관계없이 공모 절차는 정상 진행되며, DB가 비어 있을 경우 이력 조회 기능만 제한된다.

### 4.2 instructor_db 테이블 구조

| 필드 | 설명 | 예시 |
|------|------|------|
| `instructor_id` | 자동 부여 ID | `INST-001` |
| `name` | 강사명 | |
| `contact` | 연락처 | |
| `email` | 이메일 | |
| `subject_tags` | 강의 분야 태그 (복수) | `["캘리그라피", "서예"]` |
| `fee_per_session` | 회당 강사비 | `100000` |
| `career_summary` | 주요 경력 요약 | |
| `past_programs` | 도서관 강의 이력 (JSON) | |
| `crime_check_date` | 최근 범죄경력조회 완료일 | `2025-12-01` |
| `crime_check_valid` | 조회 유효 여부 (1년 기준) | `true` / `false` |
| `availability_note` | 특이사항 (선호 요일 등) | |
| `status` | `active` / `inactive` | |

### 4.3 더미 데이터 투입 기준

초기 더미 데이터는 아래 조건을 충족하도록 구성한다.

- 분야 태그: 공예, 요리, 어학, 체육, IT·디지털, 독서·글쓰기, 미술, 음악 각 2~3명
- 강사비: Config 기본값 기준으로 통일 (예외 강사는 `fee_per_session`에 별도 기재)
- 범죄경력조회: 절반은 `crime_check_valid: true`, 나머지는 `false`로 설정하여 재조회 필요 케이스 포함
- 강의 이력: 프로그램명·시즌·출석률 요약 포함

## 5. 공모 업무 흐름

E-02는 단일 공모 트랙만 지원한다.

```
E-01 인계 수신
  ↓
FN-01 공모 공고문 생성 → 사서 게시
  ↓
공모 마감
  ↓
FN-02 모집 결과 보고 공문 생성
  ├─ 지원자 있음 → FN-03 선정위원회 개최(신규) → FN-04 선정 결과 보고
       → FN-05 범죄경력조회 → FN-06 강사 위촉(신규) → FN-07 E-03 인계
  └─ 미달(지원자 없음) → 미달 보고 공문 생성 → 사서 판단
       ├─ 재공모: FN-01로 돌아가 공모 공고 재생성
       └─ 공모 방식 조정: 사서가 별도 처리 (에이전트 범위 외)
```

## 6. 기능 요구사항

### FN-01 강사 공모 공고문 초안 생성 (A-01 호출)

E-01 인계 수신 후 프로그램별 강사 공모 공고문 hwpx 초안을 생성한다. 프로그램이 여러 개인 경우 각각 개별 생성한다.

**공고문 포함 항목:**

| 항목 | 내용 |
|------|------|
| 프로그램명 | E-01 인계 데이터 |
| 강의 일정 | 운영 기간·요일·시간·회차 |
| 강사비 | 회당 금액 (Config 기본값 또는 프로그램별 별도 금액) |
| 지원 자격 | 해당 분야 강의 경력 (기관 Config 설정값) |
| 제출 서류 | 이력서, 강의계획서 등 (기관 Config 설정값) |
| 접수 기간 | 사서 입력 |
| 접수 방법 | 이메일 또는 방문 접수 (기관 Config 설정값) |
| 문의처 | 기관 Config 설정값 |

**instructor_db 이력 참고:**
DB에 동일 분야 강의 이력이 있는 경우, 지원 자격 기준 설정 시 참고 정보로 제공한다. 단, 특정 강사를 직접 추천하거나 우대하는 방식은 지원하지 않는다. 공모의 공정성 유지를 위해 지원자 정보는 공고 단계에서 노출하지 않는다.

**Human-in-the-loop 필수:** 사서 검토 후 직접 게시.

### FN-02 강사 모집 결과 보고 공문 초안 (A-01 호출)

공모 마감 후 사서가 지원 현황을 입력하면 모집 결과 보고 공문 초안을 생성한다.

**공문 포함 항목:**
- 공모 기간, 모집 정원, 지원 인원, 지원자 명단, 특이사항, 향후 계획

**지원자 있음 시:**
- 향후 계획: "심사를 통해 강사를 선정할 예정임"
- FN-03 선정위원회 개최 단계로 진행

**미달(지원자 없음) 시:**
- 향후 계획: "공모 미달에 따라 재공모를 실시하거나 공모 방식을 조정할 예정임"
- 사서에게 다음 두 가지 선택지 제시:
  1. 재공모: 공모 기간·조건을 수정하여 FN-01 재실행
  2. 공모 방식 조정: 에이전트 범위 외, 사서가 기관 방침에 따라 별도 처리

**Human-in-the-loop 필수:** 미달 시 사서가 선택지 중 하나를 선택 후 진행.

### FN-03 강사 선정위원회 개최 공문 초안 (A-01 호출, 2026-07-09 신규)

모집 결과 보고 후, 지원자 서류 심사를 위한 선정위원회 개최 공문 초안을 생성한다. 실물 문서 학습 결과 확인된 신규 단계로, 기존 PRD에는 없었다.

**공문 포함 항목:**
- 일시, 장소, 참석자(위원 — 문헌정보담당·학교도서관담당 등 소수 위원, 기관 Config로 조정), 심의안건("○○ 프로그램 강사 모집에 따른 서류 심사")
- 붙임: 강사 선정 심사 기준표(A-01 `ATT-002`), 강사선정 심사기준표 취합자료

**심사 기준:** `ATT-002` 서식(100점 만점: 강의경력30·강사자격20·강의계획서30·수상경력10·활동능력10)을 기본값으로 사용하며, 기관이 조정 가능하다.

**Human-in-the-loop 필수:** 사서가 위원회 일시·장소·참석자를 확정 후 공문 생성. 심사 자체(점수 부여)는 위원회가 수행하며 에이전트는 관여하지 않는다.

### FN-04 강사 선정 결과 보고 공문 초안 (A-01 호출)

선정위원회 심사 결과를 바탕으로 사서가 지원자 중 최종 선정 강사를 확정하면 선정 결과 보고 공문 초안을 생성한다.

**공문 포함 항목:**
- 프로그램명, 선정 강사명, 선정 사유, 강사비, 향후 일정

**선정 강사 instructor_db 등록:**
신규 강사(DB 미등록)가 선정된 경우, 기본 정보를 `instructor_db`에 신규 등록한다.

**게시용 공고문 병행 생성 (2026-07-09 신규):** 내부결재용 선정 결과 보고(본 문서)와 별개로, 일반 이용자 대상 게시용 공고문이 필요한 경우 A-01 `TPL-012`(결재선 있는 게시 승인용 기안문) + `ATT-012`(게시문 본체, 결재선 없음)를 함께 요청한다. TPL-012는 "결재 상신"이 아니라 "게시 승인"만 필요함을 사서에게 안내한다.

**Human-in-the-loop 필수:** 사서가 최종 선정 강사를 확정 후 공문 생성.

---

### FN-05 범죄경력조회 안내 및 공문 초안 (A-01 호출)

선정 강사의 범죄경력조회가 필요한 경우(신규 강사 또는 `crime_check_valid: false`) 조회 신청 공문 초안을 생성하고 절차를 안내한다.

**자동 판단:**

| 조건 | 처리 |
|------|------|
| `crime_check_valid: true` (1년 이내 완료) | "재조회 불필요" 안내, 이 단계 생략 후 FN-05 진행 |
| `crime_check_valid: false` 또는 신규 강사 | 조회 신청 공문 초안 생성 |

**에이전트 처리 범위:**
범죄경력조회는 경찰청 외부 시스템에서 처리되므로 에이전트는 신청 공문 초안 생성과 절차 안내에 한정한다. 조회 결과 수신·처리는 사서가 직접 수행하며, 완료 후 사서가 에이전트에 완료 입력한다.

**조회 완료 처리:**
사서가 조회 완료를 입력하면 `instructor_db`의 `crime_check_date`와 `crime_check_valid`를 업데이트한다.

---

### FN-06 강사 위촉 (기안문 겸 위촉장) 공문 초안 (A-01 호출, 2026-07-09 신규)

범죄경력조회 완료(또는 재조회 불필요 확인) 후, E-03 인계 이전에 시즌 전체 강사를 일괄 위촉하는 공문을 생성한다. 실물 문서에서는 이 문서 자체가 "위촉장을 대신"하는 형태로 확인되었다 — 별도 위촉장을 만들지 않는다.

**공문 포함 항목 (표 형식):**
- 구분, 강사명, 프로그램명, 위촉기간, 운영횟수 — 해당 시즌에 확정된 강사 전원을 한 표에 일괄 기재
- 본문에 "위촉장은 본 공문으로 대신합니다" 문구 고정 포함
- 붙임: 강사 준수사항 1부 (A-01 `ATT-002`와는 별개의 서식)

**시점 판단:** 해당 시즌의 모든 프로그램에 대해 FN-05(범죄경력조회)가 완료된 시점에 일괄 생성한다. 프로그램별로 개별 생성하지 않음 — 시즌 단위로 1회 생성이 실물 패턴이다.

**Human-in-the-loop 필수:** 사서가 강사 목록·위촉기간을 확정 후 공문 생성.

## 7. 데이터 흐름

```
[E-01 인계 수신]
E-01 → E-02: 확정 프로그램 정보 수신

[공모 공고]
E-02 → A-01: 공모 공고문 hwpx 초안 생성
사서: 검토·게시
사서: 공모 기간 운영

[공모 마감 후]
사서 → E-02: 지원 현황 입력 (지원자 명단·인원)
E-02 → A-01: 모집 결과 보고 공문 초안 생성

  → 지원자 있음:
    사서 → E-02: 선정위원회 일시·장소·참석자 확정
    E-02 → A-01: 선정위원회 개최 공문 초안 생성 (FN-03, 신규)
    사서: 위원회 심사 후 강사 선정 확정
    E-02 → A-01: 선정 결과 보고 공문 초안 생성 (FN-04)
    E-02: crime_check_valid 확인 (FN-05)
      → 재조회 불필요: 강사 위촉 단계로 진행
      → 조회 필요: 공문 초안 생성 → 사서 제출
        사서 → E-02: 조회 완료 입력
        E-02: instructor_db 업데이트 → 강사 위촉 단계로 진행
    사서: 시즌 전체 강사 확정 후
    E-02 → A-01: 강사 위촉(기안문 겸 위촉장) 공문 초안 생성 (FN-06, 신규)
    E-02: FN-07 E-03 인계

  → 미달(지원자 없음):
    E-02: 미달 보고 공문 초안 생성 + 선택지 제시
    사서: 재공모 또는 공모 방식 조정 선택
      → 재공모: FN-01 재실행
      → 공모 방식 조정: 에이전트 범위 외
```

## 10. 제약 및 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 공모 미달(지원자 없음) | 미달 보고 공문 초안 생성 + 재공모/방식 조정 선택지 제시. 에이전트가 임의로 처리하지 않음 |
| 동일 강사 복수 프로그램 선정 | 일정 충돌 여부 확인 후 사서에게 안내 |
| 범죄경력조회 유효 기간 만료 임박 (30일 이내) | 선정 결과 보고 공문 생성 시 "조회 만료 임박" 경고 표시 |
| 신규 강사 선정 시 DB 미등록 | 선정 결과 보고 공문 생성 후 instructor_db 자동 등록 |
| instructor_db 미구축 | 이력 조회 기능 제한 안내. 공모 절차 자체는 정상 진행 |
| 재공모 선택 시 | 공고 기간·조건 수정 여부 사서 확인 후 FN-01 재실행 |

## 11. 비기능 요구사항

- 공모 절차만 지원하며 비공식 개별 섭외 방식은 지원하지 않는다.
- 범죄경력조회 유효 기간은 조회 완료일로부터 1년으로 설정하며 Config에서 조정 가능하다.
- instructor_db는 연도를 초월하여 누적 보존한다.
- 기관별 고유 정보(강사비 기준·지원 자격·접수 방법 등)는 Config로 주입한다.
- 에이전트 응답 언어: 한국어
