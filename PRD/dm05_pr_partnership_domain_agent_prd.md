**문서 버전:** 1.0
**작성일:** 2026-07-07
**소속 도메인:** D5 홍보협력 (총괄)
**에이전트 ID:** DM-05
**에이전트 유형:** 도메인 에이전트 (최상위 오케스트레이터와 D5 리프 에이전트 사이의 중간 관리 계층)
**참조 아키텍처:** 도서관 사서 AI 에이전트 시스템 v3

> **표기 안내:** 이 문서의 `FN-01`, `FN-02`... 는 DM-05 내부 기능 번호다. `F-01`~`F-04`는 D5 홍보협력 도메인의 리프 에이전트를 가리키는 실제 참조다.

## 1. 개요

### 1.1 목적

DM-05 홍보협력 도메인 에이전트는 D5 홍보협력 도메인(F-01 홍보물, F-02 협력기관, F-03 공모사업, F-04 소식지)을 총괄하는 중간 관리 계층이다. 최상위 오케스트레이터로부터 대외협력·홍보 정책 지시를 받아 해당 리프에 분배하고, 각 리프의 월간 실적을 취합해 통합 결과보고서를 생성한 뒤 A-02의 표준 데이터 수집 요청에 응답한다.

### 1.2 리프-투-리프 직접 협업과의 관계 (중요)

**DM-05는 D5 리프 간, 그리고 다른 도메인과의 기존 직접 협업 호출에 개입하지 않는다.** D-02·D-03·E-01이 F-01에 홍보물을 요청하는 것, F-04가 DM-03·DM-04(구 D-05/E-05)·D-01·D-02·E-01로부터 소식지 콘텐츠를 취합하는 것은 지금처럼 직접 처리한다. DM-05는 ①최상위 정책 지시의 하향 분배와 ②정기 실적 취합·보고에만 관여한다.

### 1.3 범위

- **포함:** 최상위 지시 수신·분배(FN-01), 계획서 초안 생성·전달(FN-02, 월간/주간/특별 공통), F-01~F-04 월간 실적 데이터 수신·검증(FN-03), A-02 표준 데이터 수집 응답(FN-04), 연간 누계 보고(FN-05)
- **제외:** 각 리프의 개별 운영 업무, 리프 간·타 도메인과의 직접 협업 호출 중계, F-03 공모사업의 선정 결과에 따른 예산 반영 결정(A-03·F-03 담당), 최고관리자에게 직접 확인·승인을 요청하는 것(단일 접점 원칙 위반 — 반드시 escalations로 chief-coordinator를 경유)


## 3. 기능 요구사항

### FN-01 최상위 지시 수신 및 분배

chief-coordinator로부터 대외협력·홍보 정책 지시(예: "이번 분기 공모사업을 적극적으로 발굴해라", "소식지 발행 주기를 조정해라")를 수신해 대상 리프(F-01~F-04 중 하나 이상)에 전달한다. 모호하면 확인 질문 후 배분하며, 결과를 상위에 보고한다.

---

### FN-02 계획서 초안 생성 및 최상위 전달 (월간/주간/특별 공통)

chief-coordinator의 월간·주간·특별 계획 조회 요청에 응답한다. **DM-05가 직접 새 계획을 만들어내는 것이 아니라, 각 리프가 이미 보유·확정한 계획을 취합해 도메인 수준 요약으로 편집한다.**

**요청 (chief-coordinator → DM-05):**
```json
{ "requester_agent": "chief-coordinator", "request_type": "plan_request", "scope": "monthly", "target_period": "2026-08" }
```
(`"scope": "weekly"`, `"target_period": "2026-W30"` 형식도 동일하게 처리)

**처리 절차:**
1. F-03에 발굴·접수 진행 중인 공모사업과 마감 예정 일정을, F-04에 다음 호 발행 예정 여부를, F-02에 예정된 MOU 갱신·운영위원회 일정을 조회한다(각 리프 보유 정보 그대로, 새로 계획을 세우도록 지시하지 않음).
2. 리프 응답을 도메인 수준으로 편집·요약한다. 여러 리프의 계획이 상충하거나 중복되면 원본 그대로 병기하고 임의로 조정하지 않는다.

**응답 (DM-05 → chief-coordinator):**
```json
{
  "agent_id": "DM-05",
  "agent_name": "홍보협력 도메인 에이전트",
  "scope": "monthly",
  "period": "2026-08",
  "has_plan": true,
  "plan_summary": "8월 공모사업 2건 접수 진행 중(F-03), 소식지 8월호 발행 예정(F-04). MOU·운영위 일정 없음.",
  "source_leaf": ["F-03", "F-04"],
  "status": "complete",
  "escalations": [
    { "item": "F-03 공모사업 A 신청 자격 애매 — 신청 여부 판단 필요", "urgency": "normal", "source_leaf": "F-03" }
  ]
}
```

계획성 활동이 없는 달은 `"has_plan": false, "status": "unavailable"`로 응답한다 — 오류가 아니다.

**`escalations`(선택 필드):** 리프 단계 판단 필요 사안이 있으면 이 배열에 담아 올린다. DM-05는 사서/최고관리자에게 직접 확인을 요청하지 않는다 — `urgency: "normal"`은 다음 정기 계획서/보고서에, `urgency: "urgent"`(예: 공모 마감 임박)는 chief-coordinator에 즉시 신호를 보낸다.

> DM-05는 이 계획 초안에 대해 hwpx 문서를 직접 생성하지 않는다 — chief-coordinator가 5개 도메인 응답을 통합 계획서 한 편으로 편집할 때 A-01을 호출한다.

---

### FN-03 D5 리프 에이전트 실적 데이터 수신 및 검증

매월 초 각 리프에 해당 월 실적 데이터를 요청한다.

**공통 요청 구조 (DM-05 → 각 리프):**
```json
{ "requester_agent": "DM-05", "request_type": "monthly_result", "target_period": "2026-06" }
```

**소스별 필수 응답 항목:**

| 소스 | 필수 항목 |
|------|---------|
| F-01 홍보물 | 매체별(보도자료/인쇄물/SNS) 생성 건수, 대상 행사 수 |
| F-02 협력기관 | 신규 MOU 체결 건수, 만료 임박 건수, 의원·운영위 소통 이력 건수 |
| F-03 공모사업 | 신규 발굴·접수 건수, 신청 건수, 선정 건수·금액 |
| F-04 소식지 | 발행 호수, 발행 여부(지연 시 사유) |

**검증 실패 시:** 누락·형식 오류 항목을 목록화해 해당 리프에 1회 재요청한다. 지속 미해소 시 사서에게 직접 묻지 않고 `escalations`(`urgency: "normal"`)로 표시해 chief-coordinator 응답에 포함한다.

### FN-04 A-02 표준 데이터 수집 응답

```json
{
  "agent_id": "DM-05",
  "agent_name": "홍보협력 도메인 에이전트",
  "period": "2026-06",
  "metrics": [
    { "metric_name": "홍보물 생성 건수", "value": 0, "unit": "건" },
    { "metric_name": "신규 MOU 체결 건수", "value": 0, "unit": "건" },
    { "metric_name": "공모사업 선정 건수", "value": 0, "unit": "건" },
    { "metric_name": "소식지 발행 여부", "value": 1, "unit": "회" }
  ],
  "status": "complete"
}
```

**중요 변경:** A-02는 이제 F-01~F-04에 개별적으로 요청하지 않고 DM-05 1곳에만 요청한다(`a02_top_level_relay_agent_prd.md` 갱신 반영).

필요 시 최고관리자 요청에 따라 월간 통합 결과보고서 hwpx 초안을 A-01 호출로 생성할 수 있다(다른 도메인과 달리 매월 정례 보고서가 필수는 아니며, 요청 시에만 생성). 이 요청은 chief-coordinator를 통해서만 전달된다 — DM-05는 이 초안을 사서/최고관리자에게 직접 결재 요청하지 않으며, chief-coordinator에게 전달해 통합 보고서 채널을 통해서만 검토·확정이 이루어진다.

---

### FN-05 연간 누계 보고 (연말 요청 시)

연간 12개월 실적을 취합해 연간 결과 요약(홍보물 생성 누계, MOU·협력기관 현황, 공모사업 신청·선정 이력, 소식지 발행 이력, 차기 연도 대외협력 방향 제언)을 생성한다.

## 4. Human-in-the-loop 정책

| 단계 | 인간 개입 여부 | 내용 |
|------|--------------|------|
| 상위 지시 분배(FN-01) | 불필요(모호할 때만 chief-coordinator에 확인 질문) | 자동 분배 |
| 계획서 취합·전달(FN-02, 월간/주간/특별) | 불필요 | 리프가 이미 확정한 계획을 편집만 함 |
| 리프 데이터 수신·검증(FN-03) | 불필요(DM-05는 인간에 직접 개입시키지 않음) | 자동 처리, 지속 실패 시 escalation으로 chief-coordinator에 전달 |
| A-02 응답(FN-04) | 불필요 | 요청 즉시 자동 응답 |
| 통합 결과보고서 생성(요청 시) | **필수 — chief-coordinator 경유로만** | chief-coordinator의 통합 보고서를 통해 최고관리자가 확인 |
| 연간 누계 보고(FN-05) | 불필요 | 자동 생성 또는 chief-coordinator 요청 즉시 응답 |
| escalations 발신 | 해당 없음(DM-05가 인간에게 직접 접촉하지 않음) | 판단 필요 사안은 escalations로 chief-coordinator에만 전달 |

## 6. 예외 처리

| 상황 | 처리 방식 |
|------|----------|
| 일부 리프 데이터 필수 항목 누락 | 누락 항목 목록화 후 해당 리프 1회 재확인 요청, 지속 미해소 시 escalation으로 chief-coordinator에 전달 |

| 상위 지시 대상 리프 불명확 | 임의 배분하지 않고 chief-coordinator에 명확화 질문 |

## 9. 미결 사항 (Open Questions)

1. **에이전트 스펙 신규 작성**: D5에는 흡수할 기존 도메인급 에이전트가 없어 `.claude/agents/`에 완전히 새로 작성해야 한다.
2. **월간 정례 보고서 필요성**: 다른 도메인과 달리 D5는 매월 정례 hwpx 보고서가 꼭 필요한지(F-04 소식지와 내용이 겹칠 수 있음), 사서 요청 시에만 생성하는 현재 설계가 적절한지 운영 후 재검토.
