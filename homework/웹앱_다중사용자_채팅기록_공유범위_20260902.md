# Vercel 웹앱 다중 사용자 — 채팅 기록·데이터 공유 범위 조사

조사일: 2026-09-02 / 대상: `LibrarAI.html` + `api/*` (커밋 `974d0ec` 기준)
질문: "A가 접속해서 채팅한 내용을 B가 볼 수 있나? A의 채팅이 B에게 영향을 주나?"

## 결론 요약

| 항목 | 공유 여부 | 비고 |
|---|---|---|
| 채팅 기록 | **공유 안 됨** | 브라우저 `localStorage`에만 저장, 서버 저장 없음 |
| 장서 DB·수서 후보 조회 | 공유(읽기 전용) | 서로 영향 없음 |
| **예산 집행 원장** | **공유(쓰기)** | **A의 집행이 B의 잔액을 바꿈** |
| 사용자 식별 | **없음** | 로그인·인증 코드 0건 |

---

## 1. 채팅 기록은 PC(브라우저)별로만 남는다

대화는 전부 브라우저 `localStorage`에 저장된다. 서버(Supabase)에는 대화가 저장되지 않는다.

| 키 | 내용 | 저장 위치(`LibrarAI.html`) |
|---|---|---|
| `librarai_tab_state` | B-01~F-04 리프/도메인 탭 대화 전체 | `setItem` ~5084행 |
| `librarai_chief_state` | 총괄(chief) 채팅·실행 기록 | ~5094행 |
| `librarai_plans` | 총괄 지시 계획·단계별 결과 | ~5078행 |
| `librarai_b01_batches` | B-01 배치 메모리 | ~4316행 |
| `librarai_chat_model` | 선택한 응답 모델 | ~4036행 |

`localStorage` 는 **오리진(도메인) + 브라우저 프로필** 단위 저장소다.

- A의 PC와 B의 PC는 저장소가 완전히 별개 → **B는 A의 대화를 볼 수 없다**
- 같은 PC라도 브라우저가 다르거나(크롬/엣지), 크롬 프로필이 다르거나, 시크릿 창이면 서로 안 보인다
- **같은 PC·같은 브라우저 프로필을 두 사람이 함께 쓰면 그때는 보인다** — 계정 개념이 없어서 구분 수단이 아예 없다
- 브라우저 데이터(사이트 데이터) 삭제 시 대화도 함께 사라진다. 백업 경로 없음

`api/chat.js` 는 `req.body` 를 OpenRouter 로 그대로 넘기는 순수 프록시라 서버에 대화가 남지 않는다.
다만 요청 자체는 OpenRouter 를 경유하므로 "외부 전송이 전혀 없다"는 뜻은 아니다.

## 2. 공유되는 것 — 읽기 전용 데이터

서로 영향 없음. 조회만 한다.

- `api/books.js` — `public.books` **select 전용** (복본 판정)
- `api/acquisition-candidates.js` — GET 전용(POST는 405). `book_catalog` / `v_candidate_scores` / `acquisition_shortlist_kdc()` 조회
- `api/seoji.js`, `api/naver-shopping.js`, `api/gemini.js` — 외부 API 프록시

## 3. 유일하게 서로 영향을 주는 것 — 예산 집행

`api/budget.js` 의 `action: "execute"` 만 DB에 쓴다.

```sql
insert into public.budget_resolutions (unique_key, resolved_date, resolved_month, description, amount, source) ...
update public.budget_lines set executed_amount = executed_amount + $1, updated_at = now() where unique_key = $2
```

- **A가 A-03에서 집행(결의)을 기록하면 B가 보는 예산 잔액이 즉시 줄어든다.** 의도된 공유 원장이긴 하다
- 그런데 누가 넣었는지 구분할 수단이 `source` 텍스트 필드뿐이다
- 링크를 아는 사람은 누구나 호출할 수 있다(인증 없음, `Access-Control-Allow-Origin: *`)
- 되돌리기(취소·정정) 경로가 API에 없다 — 잘못 넣으면 DB를 직접 고쳐야 한다

## 4. 인증이 없다

`LibrarAI.html` 에 login/signin/password/인증 관련 코드가 **0건**. URL을 아는 사람은 누구나
모든 에이전트를 쓰고, 예산 원장에 쓸 수 있다. API 키는 서버 환경변수에만 있어 노출되진 않지만,
**호출 자체는 누구나 할 수 있어 OpenRouter 크레딧도 외부인이 소모시킬 수 있다.**

## 고민해볼 지점 (미결)

1. **대화 보존을 어디까지 원하는가**
   - 지금(로컬 전용): 사서가 PC를 바꾸거나 캐시를 지우면 진행 중인 업무 맥락이 사라진다
   - 서버 저장으로 가려면 사용자 구분이 필요하고 → 로그인이 필요하다
   - 중간안: 대화 내보내기/불러오기(JSON 파일) 버튼만 붙여 백업만 가능하게

2. **예산 집행에 사람 식별·승인이 필요한가**
   - 최소안: 집행 시 담당자명 입력을 필수로 받아 `source` 에 기록 (코드 변경 작음)
   - 제대로: 로그인 + 집행 취소(역분개) API + 감사 로그

3. **접근 통제를 어떻게 할 것인가**
   - 최소안: Vercel Password Protection(배포 단위 공용 비밀번호) — 로그인 코드 없이 외부 차단만
   - 제대로: 사서 계정 기반 인증 (Supabase Auth 등)

4. **다중 사서 동시 사용 시나리오가 실제로 있는가**
   - 현 구조는 "1인 사서 데스크" 전제다. 팀 단위로 쓸 계획이면 1~3이 전부 필요해진다
   - 데모/연구 단계까지만이면 지금 구조로도 충분하다
