# B-04-W 자료조직 워커 테스트 — 2026-09-01~02

B-04-W(자료조직 워커)가 실제로 쓸 만한지 확인하려고 돌린 테스트의 산출물이다.
후보는 Supabase `book_catalog`(SEOJI 신간 수집분 11,762건)에서 KDC 분야·대상독자·자료유형이
겹치지 않게 10권을 골랐고, 이후 회귀 검증으로 2권을 더 돌렸다.

## 파일

| 파일 | 내용 |

| `records_normalized.txt` | 표기 고정값을 적용한 **11건**. 오분류본을 빼고 수정본만 실었다 |

`records_normalized.txt`도 **사서 검토 전 초안**이다. `needs_info` 주석이 붙은 건은 실물 확인이 남아 있다.

## 결과 요약

**10권 중 8권 정확, 1권 판정 보류, 1권 오분류.**

- **저자기호 10/10 정확.** 리재철 제5표를 예외까지 맞혔다 — `장295칼`·`셸298프`(ㄹ 3자리),
  `김92수`(ㅎ9+ㅏ2), `구58동`, `시35사`. 자관 기존 소장과 독립적으로 일치한 게 6건.
- **할루시네이션 0건.** 워커들이 인용한 장서 DB 레코드를 전수 대조했으나 지어낸 것이 없었다.
  `843 셸298프`(휴머니스트, 2022), `833.6 시35너`, `813.7 정55옆`, `420 김92수 1~9`,
  조지 오웰 `843 오66동`(민음사)/`843 오67동`(문학동네) 이판 병존 선례까지 전부 실재.
- **LDR 24자리·008 40자리 전 레코드 정확.** `008/18`(삽화)·`22`(대상독자)·`33`(문학형식) 자리
  배치까지 맞고, `008/22=b ↔ 049 $f=J`, `a ↔ 유` 정합도 지켰다. 기본표목 미사용·`052` 미생성·
  `245 $d/$e` 등 자관 3대 정책 위반 0건.
- **함정 2개 통과.** [9]는 부가기호가 590인데 실제로는 요리사 산문집이라 814.7로 넘겼고,
  [7]은 기획자 김상욱이 아니라 실제 집필자 김하연에게 `$4aut`를 줬다.

### 발견한 문제 3가지

**① [8] 유아 그림책 오분류 (813.7 → 813.8)**
국중 레코드 표본 4건을 근거로 813.7을 배정했는데, 자관 장서와 KDC6 원문 양쪽에 어긋났다.

```
813 계열 × 별치기호 (public.books)
  유(유아)   813.8 = 3,092건   813.7 =    8건
  J(어린이)  813.8 = 4,291건   813.7 =   80건
  성인       813.7 = 2,696건   813.8 =   52건
```
KDC6 본표(p.226)는 `813 .8 동화(우화를 포함한다)` — 시대구분과 나란한 **형식 구분**이다.
워커는 이 판단을 에이전트 메모리에 영구 저장까지 했다. 삭제하고 실측 근거로 재작성했다.
→ 커밋 `974d0ec`, 재실행에서 813.8로 수정 확인.

**② KDC6 분류표를 읽을 수 없었음**
에이전트 정의가 1차 근거로 지정한 `References/KDC6_for_learning.pdf`는 폰트에 ToUnicode
매핑이 없어 `pdftotext`로 한글이 한 글자도 안 나온다 — **에러 없이 조용히 실패**한다.
`pdf-parse`로 추출해 `References/KDC6_for_learning.txt`(247쪽)를 만들고, 정의를
"이 파일이 유일한 분류표 경로"로 고쳤다. 아울러 KDC6가 제공하는 별법 중 자관이 어느 것을
채택했는지는 표로 알 수 없으므로, `public.books` 세목 분포 교차검증을 필수 단계(Step 2-1)로
추가했다. → 커밋 `974d0ec`, `e04bbfd`

**③ 워커 간 표기 불일치**
같은 책을 세 번 목록하면 세 번 다 다른 조합이 나왔다. 분류 판단은 안정적인데
정의가 값을 못박지 않은 자리에서 워커마다 다른 관행을 택했다.

| 필드 | 원본 [8] | 원본 [11] (같은 책 재실행) |
|---|---|---|
| `LDR` | `00000nam a2200000 c 4500` | `-----nam a22----- c 4500` |
| `001` | `1509008` | `000001509008` |
| `008/29-31` | `000` | (공백) |
| `020 1_` | `...617 (세트)` | `...617(세트)` |
| `300` | `$a[32] p.` | `$a32 p.` |
| `650 _8` | `$a창작 동화[創作童話] $0KSH…` | `$a창작동화` |

근본 원인은 정의의 LDR 예시가 **"24자리"라고 써놓고 실제로는 25자**였던 것 —
워커들이 제각각 쓴 게 아니라 깨진 예시를 각자 고쳐 쓴 결과였다.
자관 실물 5건 + 국중 47건 실측으로 고정값을 확정했다. → 커밋 `e04bbfd`

## 정규화 규칙 (원본 → 정규화본)

`records_normalized.txt`에 적용한 변환은 아래 7가지뿐이고, 서지 내용(분류·저자기호·표제·
책임표시·주기)은 워커 산출물 그대로 두었다.

| 항목 | 확정값 | 실측 근거 |
|---|---|---|
| LDR | `00000nam a2200000 c 4500` | 00-04·12-16은 적재 시스템이 계산하는 숫자 필드 → `0` 채움 |
| 001 | `ctrl_no` 0채움 12자리 | 자관 실물 `000005293128`, `books.ctrl_no` 전부 7자리 |
| 049 `$c` | 복본수가 아니라 **복본기호**. 1부면 생략, 2부째 `$c2` | 실물 52건에 `$c1` **0건** |
| 008/29-31 | `000` (색인 있으면 `001`) | 49건 `000` / 3건 `001`, 공백 0건 |
| 종지부 | 필드 끝 마침표 **미사용** | 국중 47건 전부 미사용 |
| 020 세트 | `$a<ISBN> (세트)` 괄호 앞 공백 1칸 | 18/18건 일치 |
| 300 면수 | 쪽번호 미인쇄 그림책은 `[32] p.` | 실물 19건이 이 형식 |

종지부는 자관 5건이 마침표를 쓰고 국중 47건이 안 쓴다. 자관 5건이 전부 『루팡의 딸』
한 총서의 납품 데이터라 관행 표본으로 보기 어려워 국중 다수를 따랐다. 사서가 반대로
정하려면 에이전트 정의의 ISBD 절 한 줄만 고치면 된다.

## 알아둘 점

- 이 테스트는 **B-04-H 하네스를 거치지 않고** B-04-W를 직접 호출했다. 그래서 배치 KORMARC
  출력 파일 생성(FN-04)과 장서 DB 반영(FN-03.5)은 수행되지 않았고, 이 폴더의 파일은
  사후에 대화 기록에서 정리한 것이다. 실제 운영에서는 B-04-H가 출력 파일을 만든다.
- 등록번호 `EM100001~EM100011`과 제어번호 `1509001~1509011`은 **테스트용 가상값**이다.
  실제 장서 DB에 없는 번호이므로 그대로 적재하면 안 된다.
- 작업 중 네이버 책 검색 API 종료(`404 SE05`)를 발견했다. 워커들은 지시 없이 WebSearch로
  우회했다. 별건으로 프로젝트 전반에서 해당 경로를 제거했다(커밋 `974d0ec`).
