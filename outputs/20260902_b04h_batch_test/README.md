직전 테스트에서 확인했으므로, 이번 배치는 **하네스의 책임 영역**(예외 분기·QA·채번·배치 일관성)을
찌르도록 짰다.

| # | 도서 | 노린 것 |

| 1 | 공생의 언어 / 롭 던 ; 송근아 옮김 | 기본 케이스, 번역서. 자관에 동일 저자 소장(`511.186 던295딜`) → 저자기호 재사용 판단 |

| 3 | 옹고집전 / 박철 글 ; 조혜란 그림 | **자관에 같은 책 2004년판 소장**(`813.508 우239창 8`). 총서 저자기호·권차 계승 판단 |

장서 DB는 운영 테이블(73,390행)이므로 **INSERT를 실행하지 않았다.** 채번·조회(SELECT)까지만 수행하고
INSERT 문은 기록만 남겼다. 배치 전후로 `count(*)`·`max(reg_no)`·`max(ctrl_no)`가 모두 그대로임을 확인했다.

## 1차 결과 (정의 수정 전)

6행 → 저자 누락 1건 제외, 중복 1건 제외, **4건 목록 완료**.

### 잘 된 것

- **예외 3종이 전부 정의대로 분기됐다.** 저자 누락(등록 제외), ISBN 중복(1건만 처리),
  대상 자료실 미기재(카탈로깅은 진행 + DB 반영만 보류 — 정의에 없는 판단인데 합리적으로 갈랐다)
- **직접 분류하지 않고 실제로 B-04-W에 위임했다.** 역할 경계는 지켜졌다
- **할루시네이션 0건.** 하네스가 인용한 근거를 전수 재조회했으나 전부 실재했다 —
  `511.186 던295딜`(롭 던 기존 소장), `EM52629 옹고집전 / 박철 글 ; 조혜란 그림 / 창작과비평사 2004 /
  813.508 우239창 8`, 주제명 `KSH2002004891`
- **직전 테스트의 오분류가 회귀하지 않았다.** 놀이터를 `813.8`로 분류했다(813.7 아님)
- 하네스가 정의에 없는 검증을 스스로 추가했다 — 워커가 인용한 소장 선례를 Supabase로 재조회,
  KSH 번호를 국중 파싱 파일에서 grep 대조, 자관 `room` 값 2단계 구조 실측 확인

### QA가 통과시킨 결함 3가지

**① `008`이 4건 전부 38자인데 "실측 40자 통과"로 인증됐다**

```
파일 실물: 260902s2026    ulk           000   kor      → 38자
QA 기록:  "260902s2026    ulk           000   kor  "  → 40자로 실측·통과
```

위치 배치(15-17, 22, 29-31, 33, 35-37)는 전부 맞고, 빠진 것은 **말미 공백 2칸**(38 수정레코드,
39 목록전거)이다. QA는 하네스가 손으로 옮긴 문자열을 쟀고, 파일에 쓴 문자열에서는 그 공백이 사라졌다.

원인은 두 겹이었다.
- **B-04-W의 008 표에 `38-39` 항목이 아예 없었다.** 표가 `35-37 언어`에서 끝나 워커에게 마지막
  두 자리를 채울 근거가 없었다 — 하네스만의 문제가 아니었다
- 텍스트 포맷에서 말미 공백은 보이지 않고 편집기·포매터·git이 소리 없이 지운다 (구조적 취약점)

**② `056 $2` 표기가 배치 안에서 갈렸는데 못 잡았다**

```
056 __ $a472     $26     ← 공생의 언어
056 __ $a813.8   $26     ← 놀이터
056 __ $a813.508 $2 6    ← 옹고집전 (혼자 다름)
056 __ $a370.18  $26     ← 애착장애
```

FN-03이 "한 배치 안에서 이 값들이 레코드마다 다르면 QA 실패로 처리한다"고 명시한 바로 그 상황인데
통과했다. 고정값 목록(LDR·001·008·049 `$c`·세트 ISBN·마침표)에 **`056`이 없었기** 때문이다 —
열거된 항목만 검사하는 체크리스트의 한계.

**③ 옹고집전 청구기호에서 총서 권차가 빠졌다**

자관 「재미있다 우리 고전」 18건이 **전부** `813.508 우239창 N` 형식이고, 같은 책 2004년판(EM52629)은
`call_no='813.508 우239창 8'`·`vol='8'`이다. 새 레코드는 `813.508 우239창`으로 권차가 없다.
총서 저자기호는 계승했는데 권차는 놓쳤고, QA 체크리스트에 총서 권차 항목이 없었다.

**부수 문제 — 보류 건이 등록번호를 소비했다.** 놀이터에 `EM0197352`를 배정하고 DB 반영은 보류해서,
실제 적재하면 351·353·354만 들어가고 352가 빈 번호로 남는다. 정의에 보류 건 번호 처리 규정이 없었다.

## 회귀 결과 (정의 수정 후)

같은 입고 목록 6행을 고친 정의로 재처리했다(`v2/`). **①②③ 전부 해소됐다.**

| 결함 | 1차 | 회귀 | 확인 방법 |
|---|---|---|---|
| ① `008` 자릿수 | 4건 전부 **38자** | **4건 전부 40자**, `38-39`=`##` | 배치 출력 파일을 스크립트로 실측 |
| ② `056 $2` 표기 | `$26` 3건 / `$2 6` 1건 | **4건 전부 `$26`** | 배치 출력 파일 grep |
| ③ 총서 권차 | 누락 | `call_no='813.508 우239창 8'`·`vol='8'`·`049 $v8`·`490/830 $v8` | 자관 소장 18건과 대조 |

부수 개선도 있었다.

- **`049 $v` 총서 권차가 놀이터에도 붙었다** (`$v118`) — 1차에는 없었다
- **놀이터 발행지가 `[발행지불명]` → `서울`로 확정됐다** — 워커가 확인 절차를 밟았다
- **옹고집전에 `490/830 $a재미있다! 우리 고전 ; $v8`이 생성됐다** — 1차에는 총서 필드 자체가 없었다
- LDR·008이 `#` 표기로 나가 자릿수가 눈으로 검증 가능해졌고, 워커 응답 원문을 `job1~5_raw.txt`로
  따로 저장해 **파일 대 파일로 대조**했다 (1차의 "손으로 옮긴 문자열을 잼" 문제 차단)
- 보류 건(`#2`)의 번호를 **회수 대신 예약 유지**로 처리하고 그 사실을 보고에 명시했다

### 회귀에서 새로 드러난 것

**하네스의 사전 지시가 틀렸고, 워커가 근거를 들어 거슬렀다.** 하네스는 입고 목록의 총서란이 "-"인 것만
보고 "EM52629는 무관한 별개 총서이니 계승하지 말라"고 워커에게 지시했다. 워커는 이를 따르지 않고
Supabase를 직접 조회해 저자·삽화가·발행처가 일치함을 확인하고 권차를 계승했다. 하네스가 재검증한 결과
워커가 옳았다.

결과적으로 ③이 고쳐진 것은 맞지만, **고친 QA 규칙이 아니라 워커의 불복종이 결과를 구했다.** 정의에
남은 공백 둘:

- 하네스가 위임 시 전달하는 총서·선례 판단은 **확정 지시가 아니라 가설**이라는 점, 그리고
  워커가 근거를 들어 이의를 제기할 수 있다는 점이 FN-02에 없다
- **입고 목록의 총서란 공란은 "총서 없음"을 보장하지 않는다.** 총서 여부의 최종 판단 기준은
  텍스트 필드가 아니라 저자·삽화가·제목 일치 여부의 DB 조회다

**남은 사소한 것:** Job2 레코드만 지시기호 뒤 공백이 한 칸 더 많다(`049 0_  $l` vs `049 0_ $l`).
서브필드 구분과는 무관한 표기 스타일 차이지만, 배치 일관성 검사가 이 자리는 보지 않는다.

**분류 변동:** 공생의 언어가 1차 `472` → 회귀 `472.5`로 바뀌었다. 둘 다 QA를 통과하는 값이고
회귀 쪽이 더 구체적이다. 워커의 분류 판단이 실행마다 흔들릴 수 있다는 뜻이며, 하네스 결함은 아니다.
