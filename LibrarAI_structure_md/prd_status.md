### A01 공문서
- hwpx-autofill-conversion 스킬 기반 (Filesystem MCP로 템플릿 로드 → `section0.xml` `<hp:t>` 치환 → rezip)
- 공통 도구 에이전트: 전 도메인 에이전트가 hwpx 초안 필요 시 A01 호출
- 결과물 USB로 업무 PC 이전 후 한글 프로그램에서 검토·결재
- 템플릿 11종 관리 (TPL-001~TPL-011)
- 강사 섭외 문자·범죄경력조회 등 기안문 불필요 유형은 별도 처리

### A02 최상위이관
- 최상위 오케스트레이터로 통계보고서 기능 이관 후, 데이터 수집 브로커 역할로 재정의
- 32개 리프 에이전트 실적 데이터를 표준 JSON으로 수집·변환·전달
- 수집 실패 에이전트 탐지 후 사서에게 알림, 수동 보완 입력 지원

### A03 예산
- 공통 도구 에이전트: 도메인 에이전트가 잔액 조회·집행 기록 시 호출
- K-EduFine 동일 구조 Excel 파일 기반 운영 (실제 편성액은 Config로 주입)
- 도메인간 예산 유용: 최고관리자 승인 필수, 사서 미승인 시 기록 불가
- 이상 집행 탐지 기준: 잔액 <10%, 6월 말 이전 집행률 >70%, 10월 기준 잔액 추정 >15%

### A04 성과관리
- 연간 성과 목표 1~2개 등록, 산식 저장 (단일 지표 또는 가중치 복합 지표)
- 최상위 오케스트레이터에서 월간 지표값 수신 → 자동 계산 → SQLite 저장
- 복합 지표 가중치 합 반드시 1.0, 불일치 시 등록 거부
- 연환산 추정치 표시 시 "추정값" 명시 필수

### F02 협력기관
- 성격이 다른 세 이해관계자(협력기관 MOU, 지역구 의원, 운영위원회)를 하나의 에이전트로 통합하되 DB는 목적별로 분리(`partner_institutions`/`mou_records`, `council_members`/`council_interactions`, `committee_members`)
- D-01(outreach 파견)·D-06(순회문고)의 "기관"과 목적이 다름을 명시 — 프로그램 운영이 아닌 관계 관리 자체가 목적. 동일 기관 중복 등록 가능하나 DB 병합은 하지 않음

- 의원 대상 소통·운영위 확정 단계는 HITL 필수 — 정치적·정책적 판단은 하지 않고 사실관계 정리까지만 지원

### F03 공모사업
- 공모사업 유입 경로를 웹 탐색(FN-01)과 접수 공문 등록(FN-02) 두 갈래로 분리 — 접수 공문형은 이미 도서관에 도달한 정보이므로 탐색 없이 즉시 등록·검토 단계로 진행
- 신청 요건 적합도 판단(FN-03) → 마감 D-7·D-1 알림(FN-04) → A-01 호출 신청서 초안(FN-05) → 결과 추적(FN-06, 선정 시 A-03 예산 반영) → 연간 이력·재도전 후보 안내(FN-07)
- **표기 규칙**: 에이전트 ID(F-01~F-04)와 내부 기능 번호 접두어가 겹치는 D5 도메인 특성상, F03부터 내부 기능 번호를 `F-01…` 대신 `FN-01…`로 표기하여 구분 (다른 도메인 PRD는 기존 `F-01…` 표기 유지). F02도 동일 규칙 적용
- 선정 성과의 A-04 성과지표 연계, 접수 공문 OCR 자동 구조화는 향후 확장 검토 항목

### F04 소식지
- F01 SNS(개별 행사 즉시 홍보)와 목적·주기·산출물 형태로 구분 — F04는 월간/계간 정기 발행물, 여러 섹션(하이라이트+예고+공지) 구성
- 지난 활동 하이라이트는 D-05·E-05(이미 취합된 결과보고 데이터)에서, 예정 프로그램 안내는 D-01·D-02·E-01(기획/운영 단계)에서 취합 — D-01은 기존 `F-08` 소식 제공 인터페이스 재사용
- 소스 미응답 시 "다음 호 안내 예정" 처리, 하이라이트 수치는 임의 수정 금지(원본 데이터 그대로 반영)
- F02·F03과 동일하게 `FN-` 접두어 규칙 적용
